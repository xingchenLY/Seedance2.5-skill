# 剧梦 Dreama CLI 资产执行流程

仅 `asset_workflow=jumeng` 且用户选择 `jumeng_operation_mode=cli` 时使用。网页入口及未覆盖步骤见 [剧梦流程](jumeng-workflow.md)。CLI 是操作通道，不改变资产范围、定妆照／三视图规格、项目与剧集命名、分镜粒度、审核、最多 5 次返修或本地存储。本文基于实际核对的 Dreama 1.0.5 命令；运行时以安装版本帮助为准，不锁定版本、不猜参数或未公开接口。

## 1. 安装、登录与环境

1. 用系统命令定位 `Dreama`／`Dreama.exe`，Windows 可用 `Get-Command Dreama.exe`；未找到时检查当前用户标准安装目录 `%LOCALAPPDATA%/Programs/Dreama/Dreama.exe` 或用户提供路径，不整盘扫描。记录实际路径，其他设备不硬编码本机用户名。
2. 实际运行 `version`、`--help`，核对可运行、环境、服务地址及所需子命令。检查 `auth status`；按当前帮助用 `auth whoami` 核验远程账户。登录缺失或过期由用户通过 CLI 支持的登录入口完成，不索取聊天中的 token，不复制浏览器凭据。
3. 用 `capability list --kind image` 等授权的只读业务查询核验服务与权限。`ping` 仅辅助诊断：已观察到 1.0.5 的生产 ping 返回 404 而模型查询成功，不能因该 404 单独判断离线；本地 loggedIn 也不能代替远程可用性。网络受限、认证错误、权限不足分别处理。
4. 缺 CLI、无法运行或首次登录未完成时报告具体缺项，按已有授权处理；不把它们自动当作 token 过期。运行中已确认 token 过期按下方自动降级规则处理。仅某个命令缺能力，按第 6 节网页补齐后返回 CLI。
5. 首次读取所用命令的 `--help`，记录版本绑定的能力；同环境同版本复用，不每张图重读帮助。CLI 与网页补齐须同账号、环境及项目；不得猜 `--server` 或传不支持的 `--env`。

## CLI token 过期后的自动网页降级

本规则是用户预先授权的恢复方式，仅用于已选择 CLI 的资产任务运行中确认 token 过期；用户本次明确“只用 CLI／不切网页／等待我登录”或要求停止时优先。首次操作模式仍由用户选择，不因本规则改为默认网页。

1. 依据 CLI 实际认证错误确认 token 过期；模糊 401 可用当前帮助支持的只读身份查询核对一次，不能把 403、网络超时、ping 404、余额不足或模型故障当过期。暂停新的 CLI 平台写入，已提交任务继续保留在途状态，不标作生成失败、不消耗返修次数。
2. 提示用户：“CLI 登录已过期，请重新登录；约 60 秒内未回复，将按已授权规则尝试切换网页继续。”记录提示时间；可用异步询问收取用户选择。期间继续本地审核、归档等不依赖失效登录的工作，不反复发送登录提示。约 60 秒无回复即可开始网页恢复，不无限等待；这是执行本规则的预先授权，不将沉默当作新的授权。用户回复正在登录、继续等或不切换，则遵从；续跑依据已记录时间，不重新计时拖延。
3. 先尝试本地 Chrome，不能调用或实际打不开才用内置浏览器。检查网页登录态、账号／环境及同一项目的真实标识，不能只凭同名项目继续。网页已登录且目标可确认时，无需再次询问切换许可。网页也需登录、验证码或账号不一致且无法确认时，说明具体阻塞、保留断点并等待用户；不能复制 CLI token 到浏览器或绕过认证。
4. 用网页历史核对原项目、剧集、分镜及所有已知任务。CLI 过期前提交结果不明的操作先对账，不重新点击生成／创建／保存；暂时无法确定的任务保留占位及句柄，仅阻塞对应项。当前分镜满额仍等其空位，不借切换转其它分镜补交。旧结果按真实任务对应继续下载、审核及保存。
5. 网页目标及恢复条件确认后，把 request 的 jumeng_operation_mode 改为 web，再按原流程 init；保留原设计、图片、表格、尝试的 CLI 来源、任务句柄、失败预算和当前等待分镜。工作区映射记录切换原因、时间、未明操作及网页定位证据，不向 state 添加新字段。通知“已切换网页继续”，从断点执行原网页流程，不重做已完成步骤。
6. 后续沿用网页，不每个资产重新试 CLI 或反复切换。用户明确要求恢复 CLI 时，核验其登录和能力、对账在途后再切。切换失败只作一次针对性恢复，不在两种通道间无限重试；继续可执行的本地工作并说明待用户处理项。

自动切换由执行技能的协调者完成，CLI／保存脚本本身不自带此降级服务；只有实际完成网页验证与状态切换才能宣称已恢复。

## 2. 项目、资产剧集与分镜

| 操作 | 命令与执行要求 |
| --- | --- |
| 查找用户指定项目 | `project list/get`；分页完整检查目标，真实 ID 唯一定位，不创建项目、不取同名首项 |
| 查询资产剧集 | `series list/get`；按启用类别准确匹配人物资产、场景资产、道具资产 |
| 缺失时新增并命名 | `series create --project-id <ID> --name <类别资产> --yes`；先确认不存在，创建后读回 ID 与名称；不重复创建。当前无剧集改名命令，既有剧集命名修复由网页补齐 |
| 分镜复用／新建／改名 | `storyboard list/create/update`；同名优先，再用真实空白无历史／无在途分镜，否则新增。CLI 无法证明历史为空时网页补查，空队列不证明无历史 |
| 写图片提示词 | `storyboard update --series-id <ID> --id <分镜ID> --image-prompt <完整稿> --produce-type 3 --yes`；读回核对全文与真实引用，不改视频提示词等无关字段 |

仍是每人物一个分镜共用定妆照、三视图及所选状态；每主场景一个分镜共用房间及昼夜；每道具一个分镜共用状态。写入前核对项目／剧集／分镜映射，提交结果不明先查询而不是换网页再创建。`storyboard create --prompt` 是视频提示词参数，不用于保存图片稿。

## 3. 素材引用与模型

- 用 `library list --project-id <ID> --type <1/2/3>` 查询项目全部素材，处理分页；默认不加单集过滤。核对真实 assetId、imageId、具体形象版本和图片，名称不当 ID，空记录不当已有图片。
- `prompt assemble --project-id <ID> --kind image --prompt <文本> --ref <已核实形象>` 获取真实图片引用。按当前帮助可用 `assetId:imageId:名称` 消除同名歧义。保留完整原始标签，不手写节点、不把名字当引用。组装可能替换名称，须将真实节点放到共用规则指定的原人物／原场景／原道具名称之后，保留必要原名称、完整提示词和规格；不在目标变体名后误引、不只在末尾追加。实际读回核对身份、位置和节点。
- 三视图与换装引用本次已合格基准照；相关场景／昼夜及道具变体按真实依赖等待审核通过、归档和可用引用，不用未经审核的候选解锁。参考图仅在本地且没有平台上传命令时，网页上传再由 CLI 查询确认其 ID。
- `capability list --kind image` 获取真实 EID、比例及分辨率枚举，默认 2K、各类画幅沿用原规则。仍按九极 2.5S → 九极 2.5F → 九极 2.0、成功率严格大于 90% 及原网页候选顺序选型。1.0.5 的裁剪模型响应未提供成功率与网页排序证据，这部分首次由网页核对后映射 CLI EID；不拿 tokens、imageMax 或列表顺序代替成功率／并发槽位。已有选择未失效不反复开网页，生成失败按原规则复核。

## 4. 提交与持续调度

常用提交链：查询定位 → 写图片提示词 → 读回 → 核价 → 保存提交意图 → `image produce` → 记录真实任务 ID。

```text
Dreama point calc --kind image --project-id <项目ID> --llm <实际EID> --image-resolution 2K --number 1
Dreama image produce --project-id <项目ID> --series-id <剧集ID> --storyboard-id <分镜ID> --llm <实际EID> --image-resolution 2K --proportion <实际比例> --yes
```

- 参数中的 ID、枚举、比例必须来自本次核验，不直接运行占位示例。`--yes` 只是执行标志，当前资产生图授权已明确时不逐次询问；先核对所选资产、真实引用、提示词、模型、费用、用户预算（若有）、在途去重和返修预算。不以预估／dry-run 当真正已提交，不为验证接入额外付费生图。
- 首选带 `--storyboard-id` 的 `image produce` 保持原分镜归属。1.0.5 的 `image generate` 虽支持 `--prompt` 与 `--image <URL>`，但没有 `--storyboard-id`，不能当成固定分镜的等价重生成命令；未证明准确归属前不用它替代。返修同样更新对应分镜图片稿、核对后提交 produce。
- 每分镜最多 5 个在途、当前分镜满额等其空位，不转其它分镜补交；其它已有请求继续。按项目／剧集／分镜记录全部实际句柄，结合 `task status/get/queue` 回查，平台更低限制优先，未知任务保留占位。逐个发起生成命令、收到接受结果即继续，不等待图片生成完成。共享分镜的提示词写入、读回和提交由前台串行完成，避免 A 请求误用 B 的提示词。
- 前台 CLI 提交与 [后台审核双队列](result-recovery.md) 同时推进，不因待审或待平台保存数量停发。后台只看真实本地图并提交结果，前台统一 state 写入、归档及平台变更。CLI 不自带视觉审核或后台审查服务，必须实际启动可用工作者；环境不支持时按双队列的如实降级规则执行。
- 每次提交记录唯一 asset_id、attempt_id、操作模式、真实任务 ID、项目／剧集／分镜 ID、模型、比例、分辨率、完整实际提示词和引用版本。CLI `task_id` 保存为工具句柄，按现有 generating 事件记账，不伪造 source_path；额外平台映射放独立工作区文件。已知任务绑定到原通道，即使之后换模式也不重新生成。
- 按双队列的最多 2 次新提交或 15–30 秒先到者回查；`task status` 支持多个 `--task-id`，按 ID 对应结果、不靠返回顺序。只查已知与到期任务；完整响应留本地、对话输出变化和队列计数。首次失败加最多 5 次返修，第 6 次同阶段连续失败暂停该项，和网页共用计数。

## 5. 下载、实际审核与本地存储

1. 成功任务通过 `task status` 获取真实图片资源地址，核对对应 ID、资源类型和版本。`task get` 用于结果／错误信息，不用猜 URL。CLI 暂无独立下载命令；用可用下载工具将该授权任务结果保存到本次工作区确定路径，记录来源、大小及哈希，勿输出带签名地址或凭据。
2. 下载前查询该 attempt 的已有文件／在途下载；支持自定目标时优先按 [下载直接进入待审](runtime.md#剧梦下载直接进入待审) 使用 receive_asset.py 的 --prepare-download，将真实结果直接落到待审目标，完成传输后接收，省去额外复制。几何解码由 checked 完成，下载阶段不重复执行同样的 image_check。超时先核对部分文件与已有结果，不重新生图。若 CLI 不能提供可下载资源地址，仅该项通过网页第 9 节下载，不能两条通道重复下载。
3. 交给后台工作者实际打开审核。前台核验审核结果对应当前尝试、设计、引用与文件哈希，再调用 `finish_asset.py` 统一几何检查、审核记录与正式归档。不把文件可解码当视觉合格，不跳过三视图面部打码、人体比例、角色与空间一致性检查。
4. 保持原目录、名称、版本保护、Excel 原路径覆盖及清理规则。CLI 下载原件、待审文件也按网页第 9 节在确认副本／正式成品完整后精确清理；未完成或不合格尝试先保留，不能通配清空。下载、归档与平台保存失败只重试对应步骤一次，不占生成／质量返修预算，不因保存失败重新生图。

## 6. 项目资产保存与网页补齐

已支持且属于本次授权的操作均走 CLI，不能因旧规则写了点击而重复网页操作。以下缺口基于 1.0.5；后续版本只有帮助与实际返回能证明满足要求才改用新增命令。

| 事项 | 执行方式 |
| --- | --- |
| 上传本地基准照／参考图 | 网页原流程上传；`library add-image` 只有形象记录参数，没有文件／URL 参数，不能当作上传 |
| 将某张合格分镜成图存到指定资产组 | 网页第 10 节选择准确结果并保存；`library create/add-image` 不等于关联该成图，不能用空记录冒充完成 |
| 保存后形象改名、描述清理 | 用 `library list` 确认真实 ID 后 `library update --project-id <ID> --id <资产ID> --image-id <形象ID> --field name --value <本地实际文件主名> --yes`；描述按原规则定向修改，不能误清提示词。回读核对。身份不明不修改首个同名项 |
| 历史完整性、现有剧集改名、成功率／候选顺序或其它缺失证据 | 只补对应网页步骤，记录证据和实际缺口；补齐后回 CLI |

网页补齐仍先本地 Chrome，不能调用或打开再用内置浏览器。前台唯一操作者负责 CLI 与网页平台变更，不让后台审图工作者争抢页面。保存保持人物组最多 10 张、群像新建组、场景道具按原组规则；不能为减少网页工作改成先入库未审图。

同轮最多 2 张的平台保存复用一次必要的 library 列表定位；优先沿用本任务已核验的项目／组／形象 ID，编辑后合并一次回读核对这两项（当前 CLI 支持的参数为准）。已有名称正确不调用 update。新建、删除、外部变更、ID 失效或结果不明才定向刷新，不逐图全库重查。定妆照本地上传已完成第 7 节核验时直接复用为平台保存结果，沿用“人物中文名-定妆照”特例，不再按通用本地主名改名或重复保存。缓存放工作区映射，记录本地哈希、attempt、真实资产／形象 ID 及核验时间；只凭同名或旧列表不能确认当前图已入库。

`library generate/batch` 是另一条资产库直接生图路线，不自动启用：本技能保留“原分镜生图→审核→指定结果存库”的流程。不能用该命令绕过分镜规则、审核门槛、所选范围或已存在图片的版本保护。

## 7. 错误、恢复与命令安全

- 同时核对退出码、JSON ok/action 和任务／资源 ID；超时或解析失败不当成功。生成、创建、编辑状态不明先对账，不立即重发、不换网页再次执行。失败不能因换通道清零计数；只读查询可作有界恢复重试，重复故障报告具体阻塞。
- 用户改通道时保存断点，对账在途和未明操作，更新 `jumeng_operation_mode` 后 init；保留每次尝试的原模式、句柄、设计及失败预算。已有结果可以继续接收和审核，不要求重新生图或重做表格。
- 完整提示词可能含引号、换行、反引号或 `$()`；优先用参数数组／可靠进程 API 传参（例如 Python `subprocess.run([...], shell=False)`），不要把提示词拼成可执行 shell 文本，不假定有 `--prompt-file`。Token 由 CLI 自己管理，日志不输出凭据；不请求无必要的 `--raw`。
- `ready_for_jumeng_setup`／`ready_for_generation` 仅代表请求字段就绪，不证明安装、登录、模型、引用、预算及保存都已核实。执行日志记录 CLI 路径／版本、环境、能力、必要网页例外、真实任务与下载版本；完成必须同时满足本地合格归档和平台保存核对，不把 CLI 退出成功当整体交付。
