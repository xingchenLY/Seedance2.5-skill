# 总资产表交付

先完成国内／海外模式选择。国内行使用完整国内提示词，必要中文字句逐字写在原提示词列；海外行沿用原模板，不新增模式列或工作表。仅当 input_check.py 返回 `generate_workbook=true` 时执行，默认规则统一见 [请求字段](request-options.md)。资产表整理并核对完成后立即保存本地：有主路径就保存到主路径根目录；没有主路径时，保存到本次本地工作区并提供实际文件链接，不创建图片分类归档目录。不等图片、三视图全部完成或整轮收尾，不再询问是否保存。关闭表格时跳过模板读取、导出与渲染，保留内部计划及既有文件。`generate_images=false` 时完成表格本地保存、检查和交付后结束，不启动出图。

## 固定成果

交付一个 Excel 文件，仅包含本次所选类别对应的工作表；点名模式按指定名称筛选条目，类别由点名项推导，未点名资产不加行。非点名模式下，资产类型未填或选择全部时包含“人物资产”“场景资产”“道具资产”三张工作表，单选时仅一张，多选时按人物、场景、道具顺序保留所选表。使用同目录 assets 中对应模板复现表头、列序、字体、颜色与行分组；模板示例不是本次资产，必须清除，不覆盖原模板。

| 工作表 | 模板 | 五列（顺序固定） |
| --- | --- | --- |
| 人物资产 | assets/characters.xlsx | 角色名、服装、场次、场景、人物文生图提示词 |
| 场景资产 | assets/scenes.xlsx | 场景、场景房间、时间、涉及场次、文生图提示词参考 |
| 道具资产 | assets/props.xlsx | 序号、道具名称、首次出现、后续出现、文生图提示词 |

有主路径时在根目录保存“剧名-本次范围-总资产表.xlsx”；点名无主路径但明确要表格时使用相同命名保存到本次本地工作区，说明“已保存到本地工作区”，不冒称保存到了未指定的资产主目录。点名模式的“本次范围”注明所选资产，避免标成全剧完整资产表；全剧范围可写“全剧”。只选部分类别时在“总资产表”前加入类别，例如“剧名-全剧-场景-总资产表.xlsx”或“剧名-全剧-人物及道具-总资产表.xlsx”。剧名和范围来自本次输入及正文，不使用历史项目名。首次保存记录实际交付路径；后续修改同一资产表时，始终覆盖该原文件，保持目录和文件名不变，不追加 -v2/-v3、日期或“修改版”等后缀，不另问是否覆盖。跨轮继续修改也沿用已确认的原表路径；本规则仅授权覆盖本次待修改的资产表，不覆盖模板或无关同名文件。首次新建遇到无关同名文件时仍另选不冲突路径，后续固定使用首次实际保存路径。

**表内不贴图，不嵌入缩略图，也不包含文件路径、图片链接、超链接或文件位置备注。** 不把路径藏在隐藏工作表、批注、公式或隐藏列里。来源只用剧名、集数和场次等内容定位，不写源文件地址。

## 行与提示词

- 已启用 [拟人动物都市题材](animal-city.md) 时，动物居民仍进入“人物资产”，其场景和道具进入原有对应表；保留原五列、排序合并和三视图排除规则。物种、毛色、尺度、动画材质及光影均写入该行完整提示词，不另建题材表或加入真人摄影冲突措辞。

- 表格范围与图片选择分开：关闭某类图片不删除该类表格行，未启用图片不进入 unresolved_images。表格只采用 resolved_assets 精确范围中的可入表资产，排除人物三视图任务；人物按角色、服装和必要状态归一，同资产跨场次复用，场次去重并按原文排序。同版本 count 多张但提示词相同时可合并一行，候选提示词有实际差异时分别成行；图片张数按计划统计，不用表格行数替代。
- 人物资产表只收录单人原照及所选群像的资产和对应完整提示词。无论是否启用或已生成三视图，都不加入三视图行、提示词或占位内容，也不另建三视图工作表。三视图的生成、交付及进度记录仍按本次图片请求处理，表格排除不代表取消图片任务。
- 人物资产表按“角色 → 服装 → 必要状态”归组排序：角色按本次正文首次出现顺序排列，同一角色的全部行连续；角色内部的服装按首次出现顺序排列，同套服装的各状态集中排列，状态顺序也按首次出现。同一服装与状态下保留原照候选顺序；不按姓名字母或拼音重排，不因跨场次或换装把同一角色拆散。
- 排序后，A 列“角色名”中相同且连续的角色名纵向合并；B 列“服装”仅在同一个角色分组内，将相同且连续的完整服装标签纵向合并。完整标签包括必要状态，状态不同仍分别保留，不能因同套衣服就抹去区分。不同角色即使同服装也不能跨组合并；空白标签、仅一行的分组不合并，不横向合并 A、B 两列。C、D、E 列的场次、场景及完整提示词逐行保留。
- 场景按地点、空间和确有差异的时间建行；时间可来自原文明示或合理的剧情推断，不重复堆叠地点名，不为同一时段重复建行，也不凭空补室内或昼夜版本。
- 每条场景提示词按 [场景影视光影](scene-lighting.md) 写入本场确定的光源、方向、光质、明暗冷暖及适用效果，直接保留在原有“文生图提示词参考”列；不另加光影列、术语词典、来源链接或检查说明。沿用 state 中对应版本的完整提示词，不在导出时拼接另一套光影；纯表格模式同样完成具体设计。
- 同地点不同实际空间各保留独立资产行及明确的房间标签；“主卧／客卧”等不同房间不能统一成“卧室”后合并。每行完整提示词包含该空间的可见区分点；基于关联图片延伸时，同时具体描述应继承的建筑细节与连接关系，按 [空间区分与防重复](visual-specs.md#空间区分与防重复) 检查，不能复制提示词只改房间名，也不能仅写“参考上一张图”。合并地点标签不表示共用同一张场景图；完整设计写入现有提示词列，参考 ID／路径与检查日志留在内部计划，不新增表列。生图依赖顺序不改变资产表按正文首次出现归组排序的规则。
- 场景资产表按“场景 → 场景房间 → 版本”归组排序：场景按本次正文首次出现的顺序排列，同一场景的全部行连续；场景内部的房间按首次出现顺序排列，同一房间的时间或必要状态版本连续，并保留其首次出现顺序。不按名称字母或拼音重排，不让跨集再次出现的同一地点散落到其他场景之间。
- 排序后，A 列“场景”中相同且连续的场景名纵向合并；B 列“场景房间”仅在同一个场景分组内，将相同且连续的房间名纵向合并。不同场景中同名的房间不能跨组合并；空白房间、仅一行的分组不合并，不横向合并 A、B 两列。只合并重复标签，C、D、E 列的时间、涉及场次和完整提示词仍逐行保留，空白时间保持真正空单元格。
- 场景“时间”列填写索引 `variant.time` 中原文明示或按 [剧情逻辑推断](visual-specs.md#场景时间推断) 确定的时段，与提示词照明和文件名保持一致。推断依据写在内部分析及已有 preflight 中，不新增列，也不把推断说明塞进时间值。只有无法合理确定时才保持真正的空单元格（不写“时间未明”“未知”“—”或空格），对应提示词省略时间。
- 场景的必要装饰道具和生活陈设写入该场景行的完整提示词，保留已确定的样式和摆放位置；不因它们属于小道具就从场景提示词删除，也不默认逐件新增道具表条目。只有本次明确要求单独制作或按剧情筛选为独立道具的物件才另行建项，仍遵守所选类别和范围；固定五列及场景／房间排序合并规则不变。
- 道具按正文首次出现顺序排列。同一资产别称合并，无后续出现写“—”；纯台词提及或回述须明确注明。
- 手机及其配套壳体按同一手机资产入道具表，完整提示词写明 [正背面双视图和角色适配手机壳](visual-specs.md#手机道具正背面与手机壳)，不因两个视图拆成两行，不另建手机壳行；有明确独立壳体资产请求时按该请求处理。手机双视图不属于被排除的人物三视图，保留在道具表原有五列内，已知所属人物可体现在具体道具名称中，归属不明时不臆填。
- 每行都是资产内容和确定的中文提示词。不放生成规则、分析过程、执行日志、备选项、未填变量或不必要的说明。
- 所选类别确无资产时保留表头，不编造占位资产；未选类别不建立工作表或占位行。
- 首次图片生成前先整理、检查并保存所选资产表，之后才选择出图流程；纯图片请求沿用用户明确的输出限制。首次导出条件是本次全部可入表条目的完整提示词已写入 state，分类、排序和合并范围可核对；满足后立即取数、导出、检查并保存，不要求图片生成、视觉验收或三视图任务全部完成。尚未通过图片验收的条目采用 state 中当前完整提示词；已通过图片读取其 accepted_attempt_id 对应的完整最终提示词，发现版本不一致则修正记录后再导出。禁止读取首批 plan、单独的最终提示词补丁或在表格代码里替换句子。纯表格模式同样先把完整计划 init 到 state。可入表资产中的待生成、失败／跳过项仍保留完整提示词；缺少可入表条目或提示词时继续补齐，不能用空行占位冒充已整理完成。三视图不参与表格行数及提示词完整性检查，`unresolved_images` 仅用于说明图片进度，不作为禁止保存表格的条件；表格已保存不代表图片已完成。

## 工具与验证

固定取数和导出命令如下，使用当前环境的 Python、Node 与 node_modules 绝对路径；不要每次编写专用表格脚本：

~~~text
python scripts/workbook_data.py state.json --output 工作区/workbook-data.json
node scripts/build_workbook.mjs 工作区/workbook-data.json 工作区/剧名-范围-总资产表.xlsx 当前node_modules目录
~~~

后续修改已保存表格时，使用原 Excel 的实际路径并启用覆盖；若先在工作区导出，检查通过后也须覆盖原交付路径，不能把工作区另存路径作为新的交付文件：

~~~text
node scripts/build_workbook.mjs 工作区/workbook-data.json 原资产表实际路径.xlsx 当前node_modules目录 --overwrite
~~~

workbook_data.py 校验精确范围与完整提示词，读取模板样式，写五列内容、每表内容哈希及未完成项。正文 scenes 的 label/location 用作场次名和地点；缺失时保留 scene ID，不另造显示名称。旧记录缺少尝试日志时返回 legacy_prompt_verification_required，必须对照原工具记录与成片，用 verify_legacy_prompt 事件核对后再导出，不补造历史计时。

build_workbook.mjs 使用 spreadsheets 的 Artifact Tool。它只读取五列内容，不将内部 ID、路径、日志写入 Excel；未变工作簿复用，变更时只更新受影响工作表并渲染其表头与最长提示词。人物表、场景表另渲染前四列的分组预览，分别检查角色与服装、场景与房间的纵向合并边界。内容／样式／导出器变化通过哈希判断；导出缓存、检查与预览留在工作区，不交付内部文件。后续更新原表使用 `--overwrite`，即使导出缓存缺失或旧哈希不再匹配，也按指定的原路径覆盖，不自动另存版本；若原表有本次修改需保留的用户改动，先核对并同步到权威 state，再导出，不能用陈旧计划抹掉这些改动。脚本先完成同目录临时文件，再替换原文件，不先删除原表；导出期间目标又被修改则停止本次替换，重读核对后仍覆盖原路径。先在本地工作区检查的流程，检查通过后立即覆盖原交付文件；无主路径的点名任务以工作区原 Excel 作为本地交付文件。记录实际目标路径与保存后哈希，不能只保留内存表格、workbook-data.json 或渲染图就称为已保存。

模板列宽不足时导出器扩宽并按文字调整行高，超过 Excel 行高容量会报错而非静默裁切。自动导出与几何排版估算不能代替实际查看预览。第一次每表均查看，后续只看发生变化的视图；纯提示词模式不运行以上命令。

使用当前适用的 spreadsheets 技能和其支持的表格库，运行时解析依赖路径，不写死一台机器的运行时。读取模板的实际表头、样式、列宽、行高、合并区后建立副本。长提示词自动换行，按内容调整列宽和行高，避免文字裁切；合并角色分组不能丢数据。

首次保存前抽看每张工作表的渲染图，重点检查最长提示词；这些排版预览仅用于内部检查，不嵌入 Excel。核对工作表与所选类别一致、条目数量、场次、人物表仅含原照／群像且没有三视图行或提示词、明确或推断时间与索引及提示词一致、仍无法确定的时间确实留空、提示词完整性，以及不存在图片对象、路径或超链接。检查完成后立即保存到上述本地目标，再核对实际文件非空、可重新读取；有主路径时不能只验证工作区副本。保存成功即简短告知实际绝对路径并提供 Excel 链接；默认表格任务到此结束，只有明确启用图片时才继续其未完成项；最终回复仍保留最新文件链接及图片进度说明。

模板样式和依赖只读取、定位一次，在首次出图前的共用建表阶段使用，不要求先有图片。先完成表格整理、检查及保存，再按需分流出图；文件非空、可读性、类别、完整条目和各表最长提示词的排版都须在交付前检查。没有图片任务时连续完成建表、预览、本地保存和交付。缺失资产、提示词内容错误先修正；纯行高、列宽、裁切问题只修表格，不重生图片，已进入出图阶段后也不阻塞其它已就绪图片。目标保存失败时保留原表和已核验的工作区文件，修复文件占用、权限或路径后只补原路径覆盖与目标核验，不为绕过失败另存新版本，不重新出图，也不把待保存说成已成功。

首次表格保存后，返修导致完整提示词、资产范围或表格内容变化时，从更新后的 state 及时覆盖已保存的原 Excel，保持原路径和文件名；可合并同一轮已知变更，但不统一拖到全部图片完成。仅图片完成状态变化、表格内容未变时不重建。更新只重新渲染受影响工作表的相关区域与最长提示词；样式、列宽、行高或合并规则全局改变时重新检查所有受影响工作表。覆盖后重新读取原路径，核对修改内容、条目数量、排序和合并结果，并继续提供同一个文件链接。收尾只补尚未同步的变更，完全未变的表格不重复导出或渲染。
