# 资产返修方式

人物定妆照、群像、三视图、场景和道具共用，适用于国内／海外及 Codex、剧梦网页、Dreama CLI。实际看图后先判断缺陷严重程度，再选择返修方式；本页优先于其它页面笼统的“优先引用问题图”表述。

## 严重问题：改提示词后重新生成

主体身份或关键结构错误、明显撞脸／角色串脸、三视图主要姿态或人物比例错误、空间布局／透视大范围错误、场景整体地域或题材风格错误、道具主体造型或正背面结构错误，以及整图模糊、渲染大面积损坏等，均应重生成。关键身份或结构错误即使面积小也不是局部小问题；不只按错误码或受影响面积判断。无法确认原图基础正确时选择重生成。

1. 根据实际失败原因修改**完整提示词**，明确正确主体、结构、构图、区分点和容易重复出现的错误；删除相互冲突或造成缺陷的指令，不仅追加“修好／高清／不要出错”。保留剧情事实、已确定的设计目标、符合 [场景绑定条件](visual-specs.md#场景与道具绑定) 的必要物件及地域文字规则；误画入的未绑定道具应从新设计中排除，不以“保留原有物件”继续固化。
2. **不以当前或历史未通过的问题图为底图或参考图，不对它执行局部重绘、蒙版编辑、图生图、扩图或增强修复。** 从新请求中移除问题图的路径、URL、@ 引用、图片标签及平台参考绑定，同时清除“保留这张问题图，只修改……”一类编辑指令。不能只改文字却让平台继续自动引用上一张失败结果，也不能换名、裁切或锐化后再把问题图传回。
3. 原来独立且已通过审核的本人基准照、关联空间或道具基准仍可用于必要连续性；这是依据合格基准重新生成，不是修改失败图。只保留本项需要且仍适用的引用。若问题来自基准本身，先按授权范围修正基准、重新审核，再处理依赖它的派生；不拿失败基准继续锁定身份或布局，也不为重生擅自扩大资产范围。
4. 更新 plan/state 的完整提示词与有效引用，按既有 init 和 preflight 流程核对受影响约束；不能修改仍在途尝试的设计。需要表格时按更新后的完整稿覆盖原 Excel。提交一条新尝试，保留同一 asset_id、使用新的 attempt_id，并记录实际工具提示词、引用版本和真实句柄；不能重发旧输入冒充已调整重生。

移除引用只影响新提交，不意味着删除源文件、平台历史或审核记录；待审清理和正式成品版本保护仍按原存储流程。

## 局部小问题：允许局部返修

只有身份、主体结构、布局和整体风格均正确，且缺陷孤立、不会牵动这些基础时，才允许引用原图作局部修改，例如一处小标识、孤立文字错误或小块材质瑕疵。明确修改位置及应保留内容，同时更新完整最终提示词。多个缺陷表明整体基础不可靠，或局部修复后暴露严重问题时，改走上面的重新生成，不连续在问题图上打补丁。

### 场景小物件调整

场景主体结构、布局、透视和整体风格正确时，小物件的增删、替换、数量、颜色、材质或位置调整，**可以引用已经生成的这张场景图进行局部修改**，不必从零重生成整间房。适用于审核中发现的小问题，也适用于用户对已合格场景提出的局部设计调整。

- 例如按单人床一个／双人床两个的要求调整枕头，移除桌后多余的并排椅子，调整花瓶或桌面摆件。判断依据是修改是否只影响局部；小物件若牵涉大范围布局、主体结构或透视重建，就不按本例放行。
- **参考版本选择：** 先实际查看正确场景的候选版本，优先选最接近目标且主体稳定的合格图；没有合适合格图时，才选基础已核实正确、仅局部待修的版本。本轮记录固定底图的 attempt、路径／平台图片 ID 和哈希，不默认引用“最新失败图”。只有整图对照证明新版本更接近目标、未引入主体漂移，才更换底图；重选时完整提示词仍保留已确认的全部修改目标，不能丢掉上一轮已完成的要求。已合格图可以直接作为修改参考；仅有局部问题、其余基础已核实正确的待审图也可用于**本资产这次修正**，但不作为已批准项目资产或解锁其它依赖。严重失败图仍按上节排除。
- 实际传入源图路径或平台可验证的图片引用，不能只在提示词写“参考原图”。写明“哪个位置、哪个物件、改成什么、最终数量／摆放”，除本次明确点名的调整对象及必要的接触阴影／反射外，保留原机位、画幅、建筑结构、门窗入口、主要家具布局、整体光影及其它陈设；例如移除多余椅子时，“保留家具”不包括该椅子。只调整与该物件有关的合理接触阴影和反射，不能通过裁切／遮挡藏起多余物件。
- 增删仍遵守 [场景与道具绑定](visual-specs.md#场景与道具绑定)：允许绑定的必要物件才可补入，应排除的临时物件可以局部移除，不能因支持局部修改又把它们固定回背景。仅调整场景时间继续按 [时间复用规则](visual-specs.md#同场景时间复用) 使用原图，不借小物件调整发起换光或昼夜版本。
- 更新完整最终提示词及实际工具编辑指令，记录源图版本／路径／哈希和新 attempt；本资产旧图不能以自己的 asset ID 加入 `reference_ids`，避免自引用依赖，按现有真实图片路径或平台图片引用方式记录。实际本地编辑底图须记录在 `reference_paths`，平台图片 ID 同步记录在工作区引用映射，不能只写在备注中。被选作编辑参考的文件由 [待审清理保护](runtime.md#待审清理与编辑参考保护) 统一检查；仍在使用时保留，不以完成归档为由删除。新图返回后先待审，再核对修改区域及整图，确认布局、入口、透视、画质和其它绑定物件未漂移；通过后按原版本保护归档并覆盖原表提示词。

引用成功只证明选中了图片，不证明工具能锁定修改区域；先核对当前工具是否支持带图编辑／局部编辑及可用控制。支持蒙版等局部控制时按实际能力使用，不虚构参数。能力不足按原已授权通道的补齐规则处理，不做额外收费试图验证，不把整图漂移结果当作局部修改通过。返修复审须与选定底图对照未调整区域；若出现新增漂移，拒绝该结果并回到最佳稳定底图，严重基础问题按上节重新生成。

局部编辑指令示例（填入实际源图与具体要求，完整场景规格仍保存在最终提示词中）：

> 引用已生成的[场景名及具体图片版本]，仅将[画面位置的物件]调整为[数量、外观或摆放要求]。除本次明确调整的物件及其必要接触阴影、反射外，保持原机位、画幅、门窗入口、建筑透视、主要家具、整体光影和其它陈设不变。不新增未指定物件。

用户提出局部设计调整本身不记原图质量失败；新结果实际不合格才按原规则计失败。实际返修仍与其它返修方式共用最多 5 次的预算，不因改用引用编辑而清零。

## 审核、次数与恢复

- 审核者在已有反馈及 `checked.note` 中写明实际缺陷、严重／局部判断依据，以及“调整提示词重新生成／局部返修”的处理方向；仍沿用对应类别的错误码，不新增 state 字段。后台只审核并反馈，前台按原分工更新提示词、引用和提交。
- 新结果先落盘待审，再完整复审当前资产：人物仍查身份和撞脸，群像逐人检查，三视图核对全部视图，场景查结构画质及关联道具，道具查结构、状态和必要文字。旧图的通过项不能直接当新图已审核。
- 两种返修共用**首次生成加最多 5 次返修**；本轮 generation 与 quality 合并累计第 6 次失败暂停该资产。生成成功但审核未通过不算本轮成功；换失败阶段、返修方式、提示词、错误码或通道均不清零；一次尝试多种缺陷只记一次。只有实际视觉审核通过才结束本轮。累计耗尽后不自动 retry，用户明确授权新一轮时，记录授权与修正依据再恢复，历史尝试不删除。其它独立生成按原队列继续，当前分镜槽位、真实依赖及用户预算限制保持。
- 下载、保存、归档或平台入库失败只恢复对应操作，不因这些操作失败重生成。授权资料待核等非图像缺陷继续走原阻塞规则，不误记质量失败。
