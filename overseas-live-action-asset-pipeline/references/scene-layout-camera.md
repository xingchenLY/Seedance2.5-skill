# 场景布局、入口机位与无畸变检查

场景设计、提示词和成图审核共用。海外地域风格约束仅作用于海外模式；室内机位、按用途选择入口展示和无畸变要求适用于国内／海外、真人／拟人动物场景。网页、Dreama CLI 和 Codex 使用同一完整提示词和验收标准。已有场景关联、必要装饰、时段、光影与空场景规则继续执行。

## 海外布局与家具不能中式化

- 明确本场故事国家／地区、时代、建筑用途和装修方向；地区沿用项目实际设定，不能因为聊天或提示词是中文就采用国内样板间。不能把所有海外地区一律画成欧式宫廷，也不只写“海外装修”。
- 从平面组织到细部统一：入口与走廊的连接、房间功能分区、会客／用餐／起居布局、门套窗型、墙地面、家具廓形、面料与装饰都符合已确定地区和时代。沿用正文所需动作与连通关系，将中式化的布置转换为相同功能的当地设计。
- 不用中式堂屋／祠堂式陈设、供桌与太师椅组合、仿古红木家具套组、圈椅、雕龙雕凤床柜、中式屏风、博古架、月洞门或中式花格等替代海外住宅／办公室的设计；原有红灯笼、春联、书法、中式茶具等排除项继续生效。对称布局、木材、茶杯或普通陶瓷本身不等于中式，不能机械全部排除。
- 每张明确核心家具的实际廓形、材质和位置，例如当代北美客厅可用软包沙发、低矮茶几、边几与落地灯组织会客区，门洞与走廊形成可用通路；这是示例，不强制所有国家、年代和房间使用同套家具。旧式、乡村、医院等按当地具体用途重新设计。
- 首图和关联空间都检查布局与家具，不以“没有中文”“只有沙发”判定海外合格。新房间继承合格基准的地区风格，不复制其整套布局，也不把错误中式化细节继续传给下一空间。

## 室内先定布局，入口按用途展示

**优先级：真实建筑结构与可信比例 → 本图必要的功能区及剧情空间关系 → 非必要入口和额外覆盖范围。** 门存在于房间布局中，不等于每张资产图都必须看见门。此规则替代旧的“室内入口一律完整入画”。

1. **先布局，后机位。** 从正文和适用的合格关联图固定房间形状、门窗所在墙面与连接、主要家具及通路，再选择摄影机实际可站立的内部位置和朝向。未明确部分可合理补充设计；不能先指定门在画面右后方，再搬门、折墙或改变关联结构迁就构图。摄影机仍避开主入口、门槛、门洞及外侧走廊，不从门口向室内深处拍，也不穿墙取景。
2. **按本张用途选择入口要求。** 在已有 `preflight.framing` 写明“必须展示／自然可见／允许画外”之一及依据，不新增字段。用户明确要门入画，或本张确需展示堵门、门口对峙、逃生路线、门与家具等空间关系时，列为必须展示；画面仍保持无人，不生成这些动作中的人物。只有“人物走进房间”的正文描述，不自动要求基础资产图拍到门。其它场景以主要功能区为中心，自然能看到门就保留，构图不适合时允许位于画外。
3. **展示程度服从用途。** 必须展示时，让所需入口及门前通行关系足够可辨；按具体用途呈现必要门扇、门框、门锁或开口，不一律要求完整门框，用户明确完整展示时则落实。自然可见的入口可以侧向、局部入画或有合理遮挡，不凭少了整扇门判失败；露出的部分仍须几何可信，不能把窗户、镜面反射或装饰拱形当真实入口。门扇开闭依剧情，不为露门强行打开。
4. **画外入口仍保持真实连接。** 位置与连接记录在 `preflight.continuity`，没有依据时标为美术设计。允许画外不是封死入口、删除门或新增门的理由；关联房间及之后明确选定的视角继续服从该布局。实际提示词重点描述本图可见内容，画外入口只在约束连续性需要时简洁说明，不反复描写它的颜色、尺寸和门框细节诱导其入画。没有展示的区域记为本图未验证，不声称已看见；缺少画外连接的图像证据本身不阻止本图按其可见目标通过。
5. **全景不等于整个房间全部装入。** 保持 16:9、正常观察距离和自然透视，清楚交代主要功能、必要家具与空间关系即可；不要求同时看见所有墙面、所有门窗、全部地面和天花板。非关键前景允许自然出画或局部遮挡，但不能裁掉本图必需的家具、绑定物件、指定数量或规定的空间区分点，也不能用裁切掩盖错误。画外陈设在布局中保留，不当成已删除。
6. **小空间先取舍内容。** 先让非必要入口或非关键区域离开画面，再调整内部站位与朝向；按空间选择合理视野，不能靠固定焦段、极端超广角或强拉伸硬塞全部内容，不移动既定门窗和家具来假装换机位。必须展示入口但仍无法兼顾必要主体时，记录冲突、暂缓该项并报告具体限制，继续独立资产；不擅自将必须展示降级为画外，不编造结构，不自动生成门口／反打／多视角资产，不在同一矛盾方案下反复付费重试。
7. **开放式与室外。** 开放式空间保留真实连通开口、边界和地面关系，不凭空造门；是否入画同样按本图用途选择。多个入口只展示本图必要或自然可见的部分。室外不强加房间入口。换机位依据真实几何转换画面左右，不镜像房间或把换角度冒充新空间；同空间仅时间变化继续复用原图。

例如狭长卧室以床和床侧通路为主体，入口位于机位后方且本图不承担门口关系时，可保持入口在画外；若用户明确要求门与床的位置关系，则先减少非关键前景并寻找合理内部机位，不能为了拍到门压缩床或扭曲墙面。

## 无畸变的成像与结构

- 使用正常观察距离和自然透视的建筑／室内摄影；根据真实站位和必要画面内容选择合理视野，不固定使用某个焦段。确有需要才补充镜头感描述，焦段文字不能证明生成图的真实参数；不能靠极端超广角挤入整间房。机身保持水平、垂直线自然端正，不用鱼眼、球面全景、桶形／枕形畸变、边缘拉伸或不合理仰俯视。
- 墙角、门框、窗框、地板接缝、家具边缘保持原本应有的直线；圆弧家具和曲面建筑保持设计曲率，不拉直本来弯曲的物件。透视线具有一致、合理的消失方向，允许正常近大远小和水平线汇聚；不能要求所有不同朝向的线都互相平行。
- 房间尺度、门窗高宽、家具相对尺寸可信，床桌沙发不被横向拉长或压扁；相同地砖／柜门不能忽大忽小、无故融化分叉。家具落地接触合理，不悬浮、不穿墙、不互相熔接；门窗不能落在互相矛盾的墙面，镜面反射须符合空间关系。
- 三维动画允许既定物种尺度和美术概括，但不是随机几何畸变的理由。保持同一物种使用设施的比例及结构连接，不能用“动画夸张”放行弯墙、错位门洞或拉伸家具。

## 写入和验收

### 场景成图质量验收

场景除了布局、重复校验，还必须通过本节质量检查。适用于国内／海外、真人／拟人动物及全部生成通道；在同次后台审图中完成，质量不合格必须返修重生成，不能仅记备注后当成品保存。

对应卧室、会议室及书房还按 [卧室与桌椅数量](visual-specs.md#卧室与桌椅数量) 检查枕头和指定桌后位置的椅子，核对实际数量及必要例外依据，合并到本次内容与连续性审核。

实际打开完整原始输出，先看整体，再看墙地交界、可见门窗、主要家具、关联道具及反光区域等必要局部；入口按本项已确定的展示要求检查，不为审核画外区域追加取景。缩略图、像素尺寸或提示词中的“高清／2K／8K”都不能证明画质合格；已选分辨率和实际尺寸也须核对，不能只满足脚本最低尺寸就宣称达到所选规格。

| 检查内容 | 不通过的具体表现 |
| --- | --- |
| 清晰度与细节 | 主体布局和必要道具失焦、整图糊化、明显像素块／压缩破坏、重影、过度锐化边缘，或放大仅有涂抹而无可用细节 |
| 材质与渲染 | 木石布金属无法区分、非设计需要的塑料感、纹理拉丝或错误拼接、家具／物件熔接、重复生成的零件、破碎边缘与明显渲染残块 |
| 光影与曝光 | 无来源光束、投影／反射矛盾、关键结构和关联道具严重过曝或死黑不可辨，或新图实际昼夜、冷暖与本次提交的基准设计明显不符；后续剧情时间变更本身不判失败 |
| 透视与结构 | 门窗、墙地、家具尺度或消失关系错误，弯曲拉伸、悬浮穿模、结构断裂；按本页原几何规则检查 |
| 构图与内容 | 本图明确必须展示的入口、功能区、家具或允许绑定的道具漏画、错误裁切／遮挡、位置和状态不符；允许画外的入口不因不可见判失败；按 [绑定条件](visual-specs.md#场景与道具绑定) 应排除的临时道具或后续复用冲突物件却被画入；无依据地新增人物、肢体、品牌、水印、乱码或其它不应出现的内容 |
| 风格与连续性 | 与当前真人／动画题材、地域时代、已批准关联场景或本空间固定设计明显冲突；不能用错误风格掩盖低质量 |

按本场实际设计判断：夜景、低调照明、合理体积光、克制胶片颗粒、非关键远处的自然柔化和动画美术概括本身不算缺陷；但不得遮蔽本图必须看清的结构与道具。不为统一“亮、锐、干净”破坏既定氛围，不用虚构的自动质量分数替代实际查看。

### 时间与光影专项校验

每张新生成或实际修改后的场景图，都要在同次视觉审核中检查时间与光影，不能只看是否清晰或空间结构正确。按下列步骤实际看图：

1. **明确验收依据。** 以该次实际提交的完整提示词、基准图时段及已确定的光源方案为准，区分原文明示与剧情推断；记录预期时段、关键光源和需要保留的氛围。不能用后续修改的剧情时间倒改该图当时的出图目标。
2. **检查时段表现。** 对照可见天空、窗外环境、日光强弱与方向、室内外亮度关系及必要的人工照明。夜景出现无依据的白昼天空／直射日光、白天出现与设计冲突的夜空、窗内外或镜面反射呈现互相矛盾的时段，均不通过。清晨、黄昏按已确定的天色与光质检查，不凭一张图虚报精确钟点或太阳方位。
3. **检查光源与光影因果。** 主要来光应与门窗、灯具或已说明的画外光源相容；投影方向、软硬过渡、反射、高光和接触阴影要能由相应光源解释。允许多光源，不强求所有阴影同一方向；不接受无依据光束、灯具状态与照明矛盾、悬浮物件无接触阴影等明显错误。昼夜不机械对应“所有灯全关／全开”。

   海外真人另按 [灯具开关状态](scene-lighting.md#海外真人的灯具开关状态) 对照本次确定的开／关及必要开启依据：日间默认关闭的灯具若实际自发光、灯罩被内部光源照亮或产生对应光池，不因“白天也能开灯”而放行；指定必须开启的功能灯也不能误关。结合发光部件、灯罩明暗、受光面及投影判断，日光反射、外部透光或单一亮点不直接证明灯已开启；看不清的状态如实注明未验证，不强行扩大取景。不能为了通过检查删除原有灯具。灯具状态错误仍用 `scene_lighting_mismatch`，写清灯组位置、预期及实际表现，合入本次审核和一次质量失败；必要返修保留其它正确设计，局部状态及光池问题与整图照明基础错误按原返修规则区分。

4. **检查曝光与氛围。** 本图要求可见的入口、主要布局及绑定物件可辨，避免严重过曝、死黑或为提亮破坏原有时段。白天暗房、夜间明亮室内、暖色夜灯、冷色日光都可能合理，不能仅凭亮暗或色温判昼夜。完全封闭、只使用人工照明的房间若无可见时段标志，记录“可见光照与设计相容，无法仅凭画面确认昼夜”，不凭空补窗或虚报已看见天色。
5. **局部修改对照原图。** 小物件调整后比较整体时段、主光方向、明暗冷暖及灯具状态是否漂移；只允许本次目标物件及其必要接触阴影／反射变化。相邻新空间核对该空间确定的时段与真实建筑连接，不机械复制参考图的光斑或画面左右方向。
6. **记录并处理。** 将“预期时段及依据、实际可见线索、光源／阴影／曝光结论、局部修改后的保持情况”合并写入现有 `checked.note`，不新增表格列或自动评分。明确不符用 `approved=false, code=scene_lighting_mismatch`，同次多个缺陷只计一次失败；局部阴影瑕疵可引用图修正，整图时段／光照基础错误按严重问题改提示词重生成，合并累计预算不变。文件／几何脚本不能替代实际时间光影判断。

同场景后续仅调整剧情时间仍按 [时间复用规则](visual-specs.md#同场景时间复用) 使用原图，不为使用时段不同生成昼夜版。已有时间光影结论与文件、基准设计一致时复用；缺少该项实际审核时补查，只有发现原图本身不符合其出图基准或存在质量缺陷才按返修规则处理，不伪称已经把原图改成新时段。

### 不合格后的重生成

1. 先分清拿到的是预览／缩略图、未完成下载还是实际原始成图。传输或下载问题按原流程恢复对应操作，不先消耗生图次数；确认源成图本身有问题后才作为质量失败返修。
2. 在现有 `checked` 记录 `approved=false`，`note` 写明问题区域、实际缺陷和改正目标；模糊／细节不足用 `scene_quality_blur`，材质错误用 `scene_material_artifact`，明显渲染残缺用 `scene_render_artifact`。透视、光影、重复和入口问题沿用已有对应错误码；应绑定道具遗漏用 `scene_prop_missing`，错误位置／数量／状态用 `scene_prop_continuity_mismatch`，应排除道具误画入及其它错误内容用 `scene_content_mismatch`；未绑定道具不出现不算遗漏。多个问题同次只计一次质量失败；技术检查报错按已有 failed/quality 流程记一次，不重复扣次数。
3. 已授权的场景生图范围内直接修正完整提示词、必要参考及 preflight，再提交新的生成尝试，不为每次常规返修追加确认。按 [返修方式](repair-policy.md) 判断：整体模糊、结构大范围损坏、布局或整体风格错误等严重问题，改写完整提示词后重新生成当前场景，禁止将问题图作为底图、编辑输入或图生图参考；基础正确的局部小问题及 [场景小物件调整](repair-policy.md#场景小物件调整) 可引用已生成场景图修改，明确变动位置、数量或摆放，保持主体结构和未涉及内容。保留正确的布局、光影目标、必要陈设和符合绑定条件的道具；应排除的临时道具须移除，不能把“保护关联道具”当作保留它们的理由，也不能靠清空应绑定的物件让画面显得干净，也不能只改文件名、像素数字或锐化滤镜冒充重生成。
4. 返修结果仍先落盘待审，再重新查看整张图及关键局部，确认旧问题解决且没有新增缺陷。未通过的新图不作为合格参考，不正式归档、交付或存入项目资产；前述局部小问题可在本项修正时引用基础正确的待审图，用户对合格图的小物件调整也可引用该合格源图。严重问题的新请求必须排除问题图；允许局部引用不等于修改结果已通过审核，不据此解锁依赖新结果的其它场景。已有版本与尝试记录按原规则保留。
5. 首次加最多 5 次返修，本轮生成与质量合并累计第 6 次失败暂停本项并报告剩余问题；换错误码、提示词或通道不重置。成功即停止返修，用户停止要求优先。其它独立资产照常继续，不因这张图待修暂停整个生成队列。

以上结论与重复、入口和关联空间检查合并记录到现有 `checked.note`，不增加表格列或 state 字段。保存脚本仅验证文件与几何，不会自动鉴定这些画质问题；后台必须实际看图，前台核验文件／尝试／设计对应后统一落账。
