# 运行与逐张保存

使用当前环境 Python；图像检查／保存需要 Pillow，可由工作区依赖工具定位。脚本不调用生成接口、不绑定旧机器运行时路径；表格取数与导出另见 workbook.md。命令相对于本技能目录；实际调用用已解析的绝对路径。

按 [上下文控制](context-control.md) 管理读取、输出与恢复；原状态即时落盘，精简摘要按阶段更新，完整数据不反复进入对话。

## 生产入口

按 [请求字段](request-options.md) 写内部请求；通过 prepare.py 的 extract 和 index 两阶段完成 [正文索引](content-index.md)。已有请求校验和索引结果直接复用，不再次执行同一检查命令或打印全量证据。缺失或无效输入合并指出，不扩大范围、不创建资产目录。

先完成共用完整提示词计划及所选资产表。generate_images=false 时交付表格／提示词结束；明确仅图片不强加 Excel。需要图片而未指定平台默认剧梦，明确 Codex 时沿用。剧梦须用户指定项目名并按 [完整流程](jumeng-workflow.md) 处理人物、三视图、群像、场景和道具。已有结果继续共用检查与保存；只对新请求执行当前平台选择。

## 连续队列

剧梦先按 [操作模式选择](jumeng-workflow.md) 明确网页或 Dreama CLI；CLI 提交、回查与结果下载遵守 [CLI 流程](jumeng-cli-workflow.md)，本地存储不变。剧梦使用 [多分镜并发调度](jumeng-workflow.md#多分镜并发调度) 和 [生成与后台审核双队列](result-recovery.md)：前台持续提交独立资产并及时下载，后台工作者逐张审核，前台统一归档和平台保存；不因后处理积压暂停新增生成。每分镜最多 5 个在途，当前分镜满额等该分镜空位，不转其他分镜补交；平台更低限制优先，真实引用仍须等待前图合格。

以下 2／4 个在途的派发方式只属于 Codex 图片生成，不限制剧梦；表格初次整理及保存已在共用前期完成。图片返回后的接收、检查和存储为共用步骤，不随出图方式变化。

1. 一次固定本次正文范围、别名、版本与身份/空间连续性；为就绪项完成四项 preflight。按 `next --actions generate retry_generation --limit 2 --include-prompt --no-summary` 选择可执行项，得到足够条目即停止扫描；该模式的数量可能仅覆盖已扫描项，完整 next 用于必要的续跑或收尾。
2. 仅当工具允许并发时先最多 2 个在途请求，稳定且有余量时最多 4 个；遵循工具更低限制，限流或错误增加就降低并发。每次只生成一个资产，工具不支持时串行。优先能解锁后续任务的基准照；一张已就绪就先提交，不等待另一张设计，也不加未选资产。
3. 每项提交前生成唯一 attempt_id，工具编排保存 asset_id、attempt_id 与真实句柄的对应关系；已有句柄就继续等待，不因超时重复提交。每个 Promise 分支在返回时立即保存工具结果对象、提取可靠源路径，并调用下方 receive_asset.py 接收及保存待审副本，再交回控制进行实际查看；不得先 await 整批 all/allSettled 再统一处理。工具不能逐项回收时降低并发，交叠提示词／表格工作，不虚称并行提速。
4. 待审副本保存后及时给出实际本地路径和“待审核”状态。每张按 [几何与视觉检查](visual-specs.md) 实际查看后调用 finish_asset.py，让它完成 checked 的几何检查及有路径时的正式归档和 saved 更新；无路径跳过保存，不创建分类目录。待审保存不代表审核通过或成品交付，只有合格图片实际原生显示后才能记 delivered。
5. 三视图只用已启用且通过检查的单人原照；有路径先归档，无路径先交付并确保源图可读。多人照跳过，人数不明先处理；人物不同服装／状态也遵守基准照依赖。
6. 只修复失败或变更项，按 [返修方式](repair-policy.md) 区分严重问题重生成与局部小问题修改；严重问题的新提交必须移除问题图引用。保存失败重试保存，不重生原图、不解锁后续。同项本轮生成与质量失败合并累计六次暂停，按独立尝试计数；换错误码、修改提示词不能绕过暂停。恢复逻辑见 progress.md。

工具及模板依赖只发现一次，首次进入对应阶段读取规则。首次出图前完成所选表格；出图等待期间可处理返修后的提示词、表格更新及必要预览；已选资产表整理并检查完成后，立即按 [总表交付](workbook.md) 保存到本地目标并提供实际文件链接，不等全部图片完成。图片结果返回即处理，不为排版延迟单图归档；表格后续内容变更使用原路径覆盖已保存文件，不套用下方图片的 -v2/-v3 另存规则。输出原生图片和必要状态，不输出 base64、完整工具响应或重复全量提示词；完整响应仅存工具运行上下文。每项精简通知包含资产 ID、attempt_id、真实源路径与状态，输出预算须足够保留路径。路径缺失时继续读取对应请求结果，不能按生成目录时间、文件顺序猜对应关系。

进度事件可用同一 event.json 数组顺序提交，合并已实际发生的 generated/checked 或 saved/delivered，避免逐事件启动多个自制脚本。checked 已包含解码、比例、尺寸和哈希检查，不重复调用 image_check.py；视觉结论仍由实际查看得到。

## 返回即保存待审副本

工具一旦返回真实源文件，先执行这一条命令，不等待视觉审查、关联空间对照、人物风险初筛或 Excel 排版：

~~~text
python scripts/receive_asset.py state.json --id 资产ID --attempt-id 本次编号 --source 真实源图绝对路径
~~~

助手先记录 generated，再在已指定主路径的“待审／人物、场景或道具”中保存该次尝试并记录 staged。源文件已在对应待审目标且哈希一致时直接复用，否则复制；只核对字节完整性，不做视觉批准、不消耗质量失败次数，不将待审记为 saved/delivered，也不解锁依赖图。文件名含尝试标识以区分返修版本，正式成品仍使用原命名规则。共用默认保留源图、待审及历史尝试，剧梦按下方专用清理规则执行。未知格式可暂存为 .bin，实际格式和几何检查仍由正式验收处理。

返回 pending_saved/pending_reused 才能说明待审图已保存，并提供真实路径；不得称为最终成品。无主路径时只接收源图，返回 received_not_archived，不额外创建待审目录。待审保存失败返回 received=true、pending_save_failed，已接收记录和源图仍在；修复文件占用、权限或路径后，省略 --source 重试同一命令，不重新生图。请求范围或目录已变化时先重新 init；不写入旧目录。旧 generated 事件入口兼容，但常规任务使用此接收命令，避免两次重复记录。

### 剧梦下载直接进入待审

下载工具支持自定目标、已指定本地主路径且已记录真实提交时，先取该尝试的目标：

~~~text
python scripts/receive_asset.py state.json --id 资产ID --attempt-id 本次编号 --prepare-download
~~~

`download_destination_ready` 只返回 `partial_path` 与 `download_path`，不下载、不创建图片、不记接收成功。将已核对任务 ID 的真实完成结果下载到该 `.part`，确认下载成功且传输完整，再无覆盖地完成到 `download_path`；调用上方 receive 命令接收这个实际文件，复用原位文件，省去下载目录到待审目录的复制。下载器核对传输结果，正式解码与几何检查由 checked 完成，不另跑同样的 image_check。

`reconcile_existing` 表示已有目标或部分下载，先核对任务、文件和传输记录再恢复，不能覆盖或另开重复下载；`already_received` 则先恢复已有接收／归档。网页只能下载到默认目录或工具不支持指定目标时沿用原复制方式。无论哪种方式，待审落盘后才分派视觉审核；未完成文件不当图片使用。直达待审的文件就是待审原件，不能套用“删除下载副本”提前删掉它。

## 待审清理与编辑参考保护

剧梦正式归档成功后，当前待审由 finish_asset.py 调用共享清理函数；历史待审使用：

~~~text
python scripts/cleanup_pending.py state.json --id 资产ID
~~~

只处理该资产尝试记录中的待审路径，正式图须可读且哈希匹配审核结果。持有同一个 state 写锁后，逐项核对实际路径在主目录的“待审”下、各自哈希未变，并排除当前 `reference_paths`、已有原照引用、在途尝试引用以及其它资产正在使用的文件。引用保护优先于“归档后清理”；被保护或内容变化的文件保留，不删除正式图，不递归清空目录。清理失败不撤销归档、不触发生图，按原恢复规则处理。

下载副本等原流程另行管理的路径，删除前使用 `python scripts/cleanup_pending.py state.json --check-reference 图片绝对路径`；`protected=true` 必须保留。该命令仅查询引用保护，`protected=false` 不代表授权删除，仍须通过原流程的来源、重复副本、目录和哈希检查；唯一前台按操作边界串行处理查询与删除。

已审核并正式归档的图若历史静态参考意外丢失，脚本核对 accepted attempt、设计、参考快照和正式图哈希后允许继续交付及恢复同一设计，不倒退成等待历史参考；这不是主动删除许可。参考文件实际变更、活跃资产依赖变化仍需重新核对，任何新编辑／新生成都必须恢复其实际需要的参考，不能拿历史快照当可读图片。

## 减少重复检查与准确计时

一次 finish、receive、record 或 next 操作内复用未变化的 JSON 读取、请求／正文索引校验、哈希及同规格几何检查。JSON 结果独立复制，避免修改缓存污染后续读者；请求校验以请求文件、剧本文件及内容索引的身份、大小、高精度修改／变更时间失效。操作结束即清空，不跨命令或进程保留校验缓存。各状态事件仍即时原子落盘，写后重新读到新状态，不延迟提交或删减失败记录。保存仍核对真实图片和目标哈希，尺寸、引用变化、覆盖保护及审核要求不放宽。不在外层另跑相同的 input_check／image_check；剧梦每轮双队列用 context-control.md 的单次 --lanes 查询，收尾用完整 next 确认总数。

metrics 中 pending_copy_seconds、archive_copy_seconds 是实际复制及同步计算哈希耗时，原位复用或同盘链接时为 0，不代表整个保存没有耗时；geometry_seconds 为几何检查，archive_verify_seconds 为归档验证，pending_save_seconds／archive_save_seconds 为对应保存函数耗时。原 generation/review/archive/pending_seconds 是事件间隔，可能包含等待及部分检查，不能当作纯磁盘写入耗时。老记录缺少实测字段时保留 null，不回填估算；这些嵌套时间不可相加。

## 检查后立即归档

接收和待审保存完成后，实际查看可读待审副本（无主路径时查看源图），把真实结论写入 review.json（approved、note；人物原照另含 single_person），调用：

~~~text
python scripts/finish_asset.py state.json --id 资产ID --attempt-id 本次编号 --review review.json
~~~

默认按当前资产名称和版本派生文件名；必要时用 --name 明确主干。助手只处理这一张：不合格记录质量失败，合格时归档并写 saved。它不会代替视觉判断，也不会生成或显示图片。只有图片实际显示才加 `--displayed`，否则保留 deliver。保存失败恢复时同一命令省略 --review，只补保存；重复调用复用已保存结果。旧版保存助手与下方会话方式保留兼容，但常规任务优先用此入口，避免另造事件拼接脚本。

剧梦通过 finish 归档时，当前源图确实位于本次类别的待审目录则尝试同盘硬链接：独占创建正式目标 → 校验源／目标内容及可读性 → 成功提交 saved → 再删除当前待审路径。文件系统不支持时回退原复制；同名保护不变。saved 未落盘不删待审，恢复时复用已存在的同内容正式文件，不另建版本。仅链接成功不是归档成功；清理受阻返回 pending_cleanup=pending，保留两处文件，恢复清理不重生图。该优化只用于已合格的剧梦待审文件，不能对仍在写入的下载启用，也不移动用户原始参考。旧失败尝试和其它下载副本仍按剧梦记录逐项清理，脚本不会扫描删除它们。

## 单图保存

仅 save_assets=true 时调用：

~~~text
python scripts/save_one_asset.py request.json --source 真实图片绝对路径 --category 人物 --name 角色名-服装描述 --asset-id 正文匹配ID
~~~

- 每次只收一个源文件，不接受目录、通配符或批次。始终传 asset-id，使图片关联精确选择结果；可选 --kind 为 original/group/turnaround/scene/prop，显式类型须与计划一致。只有同类别及类型唯一一项时才可省略 ID。
- 先验证正文选择、类别、源文件、真实格式、方向、比例及最低像素，再创建分类目录。尺寸合格不等于视觉合格，调用前仍须实际查看。
- name 为不带扩展名的命名主干；人物“角色中文名-服装”，场景“地点-空间-时间”，时段沿用索引中基准图的确定值，后续剧情时间调整不改原图名字或生成新版本，仅仍无法合理确定时省略末段及多余连接符，道具“具体名称”。三视图使用已保存原照的实际文件主名加 -三视图，保留原照 -v2 等后缀。
- 保留源图，按真实格式选择扩展名；目标须在本次主路径内。同名同内容 reused，不同内容另存 -v2/-v3，并发时也不覆盖。复制后检查可读性、源文件是否变化和目标内容哈希；失败只清理本次创建的不完整目标。
- saved/reused 返回实际目标、像素、格式和哈希，才可记录归档成功。ready/closed 不代表图片保存。未提供路径时误调用返回 not_saved，仅表示未归档，不能当作图片检查或交付证据。只要提示词／表格模式拒绝图片保存。

## 复用保存会话

工具支持保持标准输入时，在首图等待期间或首次需要保存时启动一次，不阻塞首图提交：

~~~text
python -X utf8 -u scripts/save_one_asset.py request.json --stream
~~~

收到 status=ready 后，每张已查看合格的图由一个协调者立即写入一行 JSON：

~~~json
{"id":"本次保存请求ID","asset_id":"正文匹配ID","source":"真实绝对源路径","category":"人物","name":"角色名-服装描述"}
~~~

必填 id/source/category/name，另可传 asset_id/kind。使用 JSON 序列化编码，不手拼 Windows 路径。每行独立保存并立即返回同一 id 的结果；错误不丢弃后续请求，不按最终进程退出码推断各图成功。它复用进程和参数，不积攒图片。

会话固定使用启动时的请求。用户改范围、输出类型、路径或正文时关闭旧会话，重新校验并开启；不会热更新。结束发送 `{"op":"close"}` 或正常关闭标准输入，不遗留后台服务。若不能保持标准输入，可复用 `AssetSaver(request_path)` 并逐张 `.save(source_path, category, name, asset_id)`；再不支持就使用单次 CLI，不搭建额外服务或修改系统权限。

沙箱阻止已授权路径保存时，仅为必要目标和操作申请权限，保留源图待保存。收尾按计划核对实际文件与数量，可合并核验以减少进程开销；不能因此改成批量保存。

剧梦各类资产的下载和待审副本采用 [剧梦审核归档清理规则](jumeng-workflow.md#9-下载审核返修及清理)，覆盖本页默认保留源图／历史图片的约定；finish 已清理当前待审路径时据实复用结果，其余按记录精确清理，不重复复制、归档或删除。直接调用 save_one_asset.py 仍按原方式保留源图。
