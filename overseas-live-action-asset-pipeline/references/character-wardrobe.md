# 人物重要性与服装设计

在建立人物索引和完整提示词之前读取。本规则适用于国内、海外及拟人动物题材；仅作用于本次选定人物与范围。默认仍只整理并保存表格，不自动开启图片或三视图。

衣服从 [独立服装库 C](character-clothing-library.md) 按风格与场合选择，面貌从 [形象库 A](character-appearance-library.md) 另选；执行 [组合流程](character-genres.md)。服装不绑定某张脸，换衣不重新选脸。

## 重要性与人物顺序

- 用户明确指定的主角、重要人物及重要性等级优先。未指定时，根据正文中的叙事中心、核心冲突、持续推动情节及关键关系判断，不以社会地位、财富、正反派身份或最早出场替代戏份重要性，不依据人物小传。
- 为人物填写 `role_priority`：1＝主角（男女主或群像叙事的核心人物），2＝重要配角（含关键反派），3＝普通配角，4＝群演／背景群像。1、2 级均属于重要角色；同一角色的所有服装、状态和派生三视图使用同一等级。
- 人物表按重要性升序排列，同级按正文首次出场排列；同一角色所有资产连续，不因先出场的群演把主角挤到后面。角色内部主要常服优先，其余服装按首次使用顺序，必要状态按首次出现顺序，候选图保持原顺序。
- 等级属于整理判断，不写入最终表格新列或文生图提示词。在内部分析及 `preflight.body_basis` 记录判断依据。旧索引缺少等级时普通单人按 3、群像按 4 兼容处理；新任务应先判定等级再建表。

## 主要常服

- 每位重要角色确定一套主要常服，优先直接选用正文中已有的合适服装，将对应原资产标记 `outfit_role=main_daily`；“主要常服”是服装用途，不代表必须额外新设计一套。它是符合时代、地域、身份、生活条件及人物气质的代表性日常穿搭；可为职业日常服或符合世界观的常用服，不强制现代休闲装。
- 每位重要角色只确定一个主要常服基础款。后续日常场次优先复用；同款雨湿、脏污、破损等属于必要状态，不另算一套主要常服。正文另有明确日常换装时保留，标记 other。
- 正文有合适服装时，直接复用其原资产 ID、统一 outfit 标签、实际使用场次、完整设计及已合格图片，不额外建立“主要常服”副本、不重复加表格行或生成任务。仅补足原文未写的鞋履、材质等细节，不把细节补全当作新套装。多套都合适时，优先选择最能代表角色日常身份、且适合复用的一套，其余正文服装照常保留。
- 只有正文没有合适的现成服装时，才结合身份和用户参考补充设计主要常服；补充内容记为美术设计，不虚构原文描写。
- 仅当正文没有可用作主要常服的合适衣着、需要补充设计，且没有实际日常使用场次时，才新增主要常服基础定装并标记 `design_only=true`；不能仅因角色出现在婚礼等专门场合就自动另加常服。此时以角色真实出场作为设计依据；不声称其在该场穿了常服。表格的场次列写“基础定装（美术设计）”，场景列留空；真实依据仍保留在内部 occurrences 和 preflight。直接选用正文既有服装时标记 false，保留其真实使用场次；补充设计已有适用日常场次时也标记 false，按实际场次列出。

## 重要场所与场合专用服装

- 对本次范围内有正式礼仪、明确着装功能、关键身份展示或重大剧情意义的场所／场合，为参与人物单独设计合适服装，标记 `outfit_role=occasion`。即使正文没有写“换装”或衣服细节，也应根据身份与场景补齐，不能直接沿用“未写换装就始终同套”的旧限制。
- 例如婚礼、正式宴会、颁奖、重要商务谈判、庭审、葬礼、关键舞台活动；职业操作、防护或特殊环境需要专用服时同样处理。这些是判断示例，不是每部剧必须建立的服装清单。普通办公室、走廊或餐厅不因换地点就自动新增一套。
- 先看角色在该场的实际身份与行为，再设计服装：新人与宾客、主办人与服务人员、出庭人与旁听者不套同一套礼服。明确内外层、下装、鞋履、必要配饰、颜色、材质、剪裁及当前状态，并与主要常服形成合理区别。
- 正文明示的衣着或连续动作限制优先。例如穿睡衣突然被带到宴会、身着制服直接追进酒店，不凭场所擅自换礼服；保留剧情服装并记录例外依据。场合设计不能改写事件、增加未出场人物或虚构更衣过程。
- 在场次证据中引用真实地点、活动、角色行为或身份线索；在 `preflight.body_basis` 明确“场合事实＋身份依据＋服装美术补充”。不要求原文出现设计出的衣服名称，也不把补充设计写成原文引文。
- 同一活动跨房间、跨场次延续同套专用服；后续相同要求且无剧情差异时可复用。不同重要场合分别评估并单独完成设计，只有服装需求及完整设计确实相同才合并，不能仅改场合名复制提示词。

## 状态、索引与去重

- 日常连续场次沿用主要常服；跨日不是自动换装依据，但重要场合专用服不受“正文未明确换装”的限制。正文指定的其他换装照常保留。
- 淋湿、脏污、染血、破损、戴头套、脱外套、挽袖或解领带等，如基础衣物未更换，按同套的必要状态处理；实际更换核心衣物且改变整体搭配时另建服装版本。只为剧情连续性或静态参考确有必要的变化建状态，不为每个动作重复建图。
- `variant.outfit` 使用统一且可辨的服装标签，例如“米色针织衫与深灰长裤”“婚礼礼服·深蓝三件套”；已有合适服装选为主要常服时，只更新 outfit_role 用途元数据，不为加“主要常服”前缀修改原 outfit 或另建 ID；同款不同状态保持相同 outfit，变化写入 `variant.state`。同角色的“黑西装／黑色西服”等同义名称先归一，再去重和合并。
- `role_priority`、`outfit_role`、`design_only` 位于 annotations 的人物资产顶层，不放进 variant。outfit_role 为 main_daily／occasion／other；design_only 默认为 false，仅主要常服基础定装可为 true。同角色同套服装的 outfit_role 和 design_only 保持一致。
- 在 annotations／正文索引阶段先核对已有服装并复用，缺少的常服或专用服才新增条目；同一服装不因被选作主要常服而复制资产，随后进入完整 plan、state 和资产表；不能仅在提示词里新增而遗漏资产行。真实 scene_id、逐字引文和角色名／别名仍须通过原索引校验。仅新增整理元数据不会改变资产 ID 或使已通过图片失效。
- 用户只点名某套服装、某状态或限定张数时遵守精确范围，不为补常服扩大该次任务；在内部记录未纳入的基础设计需求。人物表仍为原五列、角色及同角色完整服装标签纵向合并，三视图不入表。后续图片按已选类别生成、校验和保存。
