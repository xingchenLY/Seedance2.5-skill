# 生成与后台审核双队列

人物、三视图、群像、场景和道具共用；首次进入剧梦生成阶段读取一次。本规则替代旧的回收优先阻断提交、待本地处理 3 张／待平台保存 5 张停发及降至 1／2 张恢复机制。队列数量仅用于进度监控，不作为停止生成的条件。

## 分工与启动

- 前台生成协调者负责所选网页／Dreama CLI 通道的提交、在途回查、下载落盘、统一状态写入及平台资产保存。CLI 模式使用 [CLI 流程](jumeng-cli-workflow.md) 及其必要网页补齐；后台审核分工不因切换通道改变。后台审核工作者负责实际查看已落盘图片，按现有视觉规格给出审核结果。开始生产时，在支持独立子代理且可读取本地图片的环境启动一个审核子代理；这是本流程明确授权的分工。只传当前资产、attempt_id、文件路径／哈希、设计及引用信息和必要审核规则，不传整段历史或全项目提示词。
- 审核工作者不操作共享浏览器，不提交生成、不删除文件、不改写共享 state。每次领取一个实际待审尝试，在工作区独立结果文件记录 asset_id、attempt_id、源图哈希、设计版本、approved、具体原因和需要的 single_person 等现有审核字段；不能将尺寸检查代替视觉检查。前台核验结果仍对应当前尝试、设计和引用后，调用既有 finish_asset.py 统一审核落账与正式归档。过期或重复结果不能覆盖新尝试，也不能解锁依赖。
- 审核工作者完成后持续领取下一项；无任务就等待前台通知，不高频空查。前台不等待单项审核返回即可继续提交独立资产，定期接收审核消息并分派新待办。后台审核必须实际启动并确认接单，只有待办列表不能称为已在后台审核。
- 沿用同一审核工作者逐项派单，不为每张图新建工作者或重复加载整套规则。后台已实际完成且文件哈希、attempt、设计和引用均匹配的视觉结论，前台只核对这些对应关系并统一落账，不再逐项打开同图重复全套视觉审核。结果缺项、冲突、文件／设计变化才补审受影响项；平台保存时预览核对选中了哪张图仍保留。重复反馈按 asset_id + attempt_id + 哈希去重，归档重试省略 --review，不重复记 checked。
- 人物反馈必须包含 [跨角色外貌对照](character-distinction.md) 的实际结论与基准索引版本。前台批准前核对期间新增或变化的角色是否已覆盖，缺项只交回后台补查增量；不能将两份基于旧名单的反馈同时批准。该检查与原单图审核合并，沿用一个工作者和项目基准索引；前台仍继续提交独立资产，不等全组生成完成。
- 环境不能运行独立审核工作者时，明确说明当前只能交错执行。保留生成优先并在平台等待／回查间隙处理审核，不编造后台服务，不把所有审核拖到生成结束。单次聊天结束不意味着审核进程仍在持续；收尾前等待并处理工作者结果。

## 前台生成与接收

1. 保持原资产排序、范围和依赖约束，查询可生成项后连续提交。不因有待审核、待归档或待平台保存项而停发，不等待审核队列清空。已解锁派生图可优先；依赖未通过时继续其它可执行独立项，受当前分镜满额等待规则约束。
2. 每次提交立即记录真实句柄、asset_id 和 attempt_id。每新增提交最多 2 次或到达 15–30 秒回查间隔（先到者）针对性轮查到期任务，以游标覆盖全部在途，不扫全项目。平台完成后释放真实槽位；结果不明不重复提交。
3. 发现完成结果及时下载并用 receive_asset.py 保存待审，按真实结果定位绑定任务，随即交给审核工作者；不等待审核完再下载下一张，也不等所有生成提交完才开始下载。下载与提交共享页面时在操作边界交错，不能同时争抢页面。这类短暂收件操作不是因积压停止生成。
4. 审核反馈合格后及时统一归档，登记平台保存；不合格则记录原因并安排该项返修。首次生成加最多 5 次返修，同一 generation 或 quality 阶段连续第 6 次失败暂停该项；换错误码／提示词不重置预算。前台保持其他独立生成继续。

## 平台保存、异常与完成

- 本地合格归档后平台保存／改名独立排队，由唯一浏览器操作者在提交间隙或平台等待时分小批处理（每轮最多 2 张），不等全部生成结束；按剧梦第 10 节核对具体成图与名称。平台保存完成不是无关资产继续提交的前置条件；实际引用必须先存库的基准图仍先完成必要保存。定妆照引用上传若已核对同一合格图、正确项目／角色组及第 7 节特例名称，就直接完成该图的平台保存待办，不再走一遍历史“保存”。各类图片按具体版本及真实库 ID 去重，不能只凭同名跳过保存。
- 每分镜最多 5 个在途，当前分镜满额必须等该分镜空位，不切到其他分镜补交；其他分镜已有请求继续。平台实际更低限制、不可用、缺少必需参考、用户停止及该项返修上限仍有效。“不停生成”不代表突破平台限额或凭空增加资产。
- 下载、归档、平台保存失败只对该操作作一次有针对性的即时恢复重试，仍失败标记该项阻塞、保留真实文件与平台结果并继续其它独立项。不得因保存失败重生图。磁盘不可写、登录失效等使后续提交或安全接收确实不可执行时，说明实际阻塞；普通审核积压不触发全项目暂停。
- 工作区记录在途、待下载、待审核／已领取、审核反馈、待归档、待平台保存及阻塞项；队列条目以 asset_id + attempt_id 标识，保留真实路径／哈希、设计版本、结果定位、工作者与时间。记录放独立编排文件，不向 state 增加不支持字段。共享 state 只由前台串行写入；重启先核对文件、状态和工作者是否仍存活，失联领取项核对结果后再分派，防止重复审核或重复提交。
- 摘要只写数量、当前等待分镜、工作者状态及队列路径。旧积压暂停标志不再参与调度，真实失败和依赖状态仍保留。收尾等待所有已提交结果与审核工作者，处理全部可执行归档和平台保存，逐项说明阻塞；只有本地与项目保存均完成才报告整体完成。记录真实耗时，不宣称未经测量的提速。
