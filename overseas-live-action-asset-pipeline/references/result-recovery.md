# 结果回收优先

人物、三视图、群像、场景和道具共用；首次进入剧梦生成阶段读取一次，后续按需查阅。第 9、10 节指 [剧梦流程](jumeng-workflow.md) 的下载审核与项目保存步骤。

调度固定为：**核对在途结果 → 已完成图片下载并保存待审 → 审核、正式归档及项目保存 → 优先提交已解锁派生图 → 提交新的独立资产**。仍在平台运行的任务继续并发；此优先级只控制助手的下一步操作，不要求等全部图片生成完。

1. 每次准备提交新任务前，先检查当前页与任务记录中的完成信号，并处理到期的在途回查。提交后立即记录任务并轻量检查当前页结果；按轮查游标回查其他已在途任务，每新增提交最多 2 次或到达 15–30 秒检查间隔（先到者）进行一次针对性回查。只查记录中的任务，不每次刷新全项目；多个分镜按上次回查时间轮换，不能永远只查最早几个未完成项。平台明确预计等待较长可减少无变化回查，但不得延迟已经收到的完成信号。
2. **一旦发现完成结果，停止新增生成提交，先下载对应图片并安全保存待审。** 当前正在进行的提交或保存先完成确认，避免半途重复点击；随后回收。不能先生成下一个人物、场景或道具，也不能先长时间编辑资产库名称、上传参考图、清理旧记录或更新 Excel。发现多张已完成图时先逐张回收这些图，再逐张审核；不把它们积存在网页里等待剩余任务。
3. 平台完成结果以任务句柄、实际历史条目和资产映射核对。网页显示完成但 state 仍为 wait 是需要回收的信号，不能把本地 wait 当作网页还未完成；现有脚本不自动监控浏览器。下载得到真实文件后调用共用 receive_asset.py 接收，不用假路径提前记 generated 或 approved。
4. 没有已知可下载成图后，先处理已经落盘的 inspect/save 及对应项目保存。定妆照合格归档后按原流程上传引用并优先生成三视图；场景基准图合格后优先处理已选关联空间／昼夜版；道具基准图合格后优先处理已选状态版。任何派生提交前再次让位给新发现的可下载成图，依赖未通过审核不能先提交。
5. 某个下载超时先核对目标文件和已知结果，不重新生成；同一结果下载／保存立即尝试失败后只做一次有针对性的恢复重试，仍失败则记为阻塞项、保留平台结果及准确定位，继续其他可回收项。没有其他可处理回收项时才允许继续独立生成；阻塞项不能假装已完成或丢弃。该恢复次数不占生成／质量失败预算，也不能通过新生成规避下载故障。
6. 当前分镜满额仍不转其他分镜新增提交。允许为下载、审核和保存既有结果切换到对应分镜；在记录中保留原满额等待分镜及队列，回收后返回该分镜核对空位，不能借切页改变等待对象。其他已在途请求照常运行。
7. 轻量任务映射记录完成发现时间、下载开始／结束、待审／审核／归档／平台保存状态、阻塞原因和回查游标。记录真实时间，不回填估算；这些是工作区编排记录，不强塞进现有 state 的未知字段。恢复先清点已完成未下载和已落盘未审核项，再提交新图；生成快慢与完成后等待下载的时间分开统计。
