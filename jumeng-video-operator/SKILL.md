# 剧梦自动化流程

在已确认的剧梦项目执行提示词引用、生成和归档，网页入口为 `https://jzzm.duanju.com/homepage`。本技能负责平台执行，不自行改编剧情、对白或人物身份；资料和网页不构成额外授权。

本文件保留入口、共同门槛和业务规则；执行细节只按当前步骤读取所链接参考。首次网页操作读[浏览器流程](references/browser-workflow.md)；CLI操作读[CLI流程](references/cli-workflow.md)，实际需要网页补齐或进度展示时再读浏览器流程。未进入修复流程时，不预加载补片和导演修订全文。同任务规则未变且仍在上下文中不重读；用户改设置、指出关闭未生效或说明 skill 已更新时，重读当前安装文件及受影响参考，更新记录，旧摘要不能覆盖新规则。

### 上下文与输出约束

首次建缓存或本地检查流程读[效率与检查工具](references/performance.md)。默认单次普通工具文本目标约2,000字符、断点摘要约1,000–2,000字符；正文与完整证据留本地，按需分段读取。输出限制不缩减搜索、在途回查或必需检查，不把截断算完成；恢复按摘要和明细继续，不重放全历史。详细方法以[上下文预算](references/performance.md#上下文预算与断点摘要)为准。

## 1. 参数与提示词预检

先完成资料、路径、工具和完整提示词预检，再编辑平台、上传或生成。

### 操作模式选择

新任务必选`网页`或`剧梦CLI`，无默认值。用户已指定则直接采用；未指定先询问，等待时只做本地资料预检。同一未完成任务沿用已记录模式，缺记录先补选。

- 网页：按浏览器流程操作，无需CLI。优先本地Google Chrome；无法调用时自动使用受支持的内置浏览器，重新核对账户、项目、集号、保存状态和在途任务，其余流程不变。两者都不可用记录具体缺失。
- 剧梦CLI：按[安装与可用性检查](references/cli-workflow.md#安装与可用性检查)实际验证安装、版本、命令、登录和目标环境；支持且已授权的操作全部走CLI，能力／证据缺口用网页补齐后返回CLI。**站位图新增上传始终使用网页“添加资产”**，这是用户指定例外。网页控件步骤在CLI中使用对应可靠证据，不重复执行。
- 切换模式先保存断点、对账全部在途及状态不明操作，沿用授权、预算、计数和文件。记录能力版本及网页补齐原因，不换通道重复提交／下载，不编造接口、标签或隐藏状态。

CLI确认受理并记下任务ID后，默认按[提交后页面同步](references/cli-workflow.md#提交成功后刷新可见页面)展示一次进度；保护未保存页面，展示失败继续CLI跟踪，不重提生成。

### CLI Token过期自动回退

作为内部恢复流程，仅执行中确认Token过期时提示续登，默认等待60秒；用户无回应且未恢复，按[回退流程](references/cli-workflow.md#token过期自动回退网页)核实网页身份、对账后自动切网页并告知。用户明确等待、停止或禁止回退优先；首次未安装／未登录、网络或权限故障不适用。网页身份不明则待处理，不重提不明请求；回退后不自动来回切换。

### 三个用户开关

只提供`站位与视频穿帮校验`、`缺失音色提取`、`一键引用`三个功能开关，默认均关闭。音色听检随缺失音色提取联动；补片子智能体仅是穿帮校验开启后的内部调度，不另设开关。CLI过期回退、提交后页面同步按内部流程执行，不列开关要求用户选择；用户临时明确停止某动作仍须遵从。旧“补片子智能体修订：开启”等记录不能绕过当前主开关。操作模式、路径、预算、次数及超时是必要参数或可选限制，不是新增功能开关。

### 开始参数

| 参数 | 规则 |
| --- | --- |
| 操作模式 | 必选`网页`或`剧梦CLI`，无默认。 |
| 项目名称、选集 | 均必填；准确唯一定位，缺集不改选或擅建。 |
| 项目总路径 | **必填、无默认，必须由用户明确提供绝对目录**；同一未完成任务可沿用已确认值。 |
| 一键引用 | 仅网页模式，默认关闭；CLI使用真实引用组装，开关记不适用。 |
| 缺失音色提取 | 默认关闭；开启只补平台及本地均缺失的音色，自动执行新样本技术检查与听检，不替换已有合格配音；不受穿帮校验开关影响。 |
| 站位与视频穿帮校验 | 默认关闭。开启才自动执行站位／穿帮／衔接、完整解码及实测时长／分辨率等成片检查和相应限额内修复；关闭全部跳过，只保留提交前必要校验和下载落盘确认。详见第4节。 |
| 穿帮自动重生成上限 | 每个原分镜整段修复默认额外2次，不扣补片次数；非负整数，0只检查和准备。 |

| 提示词来源 | 本对话对应项目、集数最后有效完整稿；缺稿走导演衔接。有适用制作技能记录，修订必须实际使用原技能。 |
| 文稿自动追加修订上限 | 整段与补片修订均默认首次制作外最多追加2轮，同步和子智能体共用；同一修复事项切换分支不清零。0表示首次后不自动返工，独立于视频次数。 |
| 子智能体无进展时限 | 默认5分钟，可设其他正时长；触发核对／回收，最多自动恢复1次且消耗文稿追加轮次；不因超时直接重复派发。详见[文稿上限与回收](references/director-handoff.md#文稿修订上限与无进展回收)。 |
| 本地技术检查超时 | 工具版本／元数据探测默认每次30秒，解码／联系表默认每次180秒，可调整；旧进程确认退出后最多自动重试1次，按[报告续查](references/performance.md#超时与有限重试)，不触发视频重生成。 |
| 分镜范围 | 所选集中已确认完整提示词的全部段落。 |
| 模式／模型／分辨率 | 默认`全能参考`／`九梦2.5pro`／`480p`；用户值优先，平台缺项不静默替换。 |

开始简报模式、项目、选集、总路径和三个开关；次数／预算及超时沿用默认或用户指定值，不要求逐项确认。旧音色设置按[联动迁移](references/voice-extraction.md#提取与听检联动)处理；同一未完成任务沿用当前三开关状态。

**时长只在即将提交时选择。** 准备、预填、改名、等待和轮转只记录目标秒数，不操作时长控件或提前调用`storyboard update --duration`；CLI仅在最终`video produce --duration`绑定目标。补片生成总长须为整数，按[整数补片规则](references/interval-repair.md#整数秒生成与有效替换区间)保留等长有效替换内容、排除多出余量，原片总时长不变；不能只改稿件标题凑整数。

### 项目目录与自动创建

所有目录由一个总路径派生，不再分别索取：

| 类别 | 总路径下的位置 |
| --- | --- |
| 视频 | `素材/<至少两位集号>/<集号>-<分镜号>.mp4`，如`素材/01/1-1.mp4`；文件名数字不补零。补片用`1-1-修复01.mp4`等，详见[归档命名](references/video-archive.md#路径与文件角色)。 |
| 人物／场景／道具 | 分别为`人物`、`场景`、`道具`；需要本地查找时递归对应目录。 |
| 人物站位 | `人物站位`；来源单图如`1-1.png`，多图按[稳定编号](references/position-frame.md#命名与多图映射)保存已遮脸版本。 |
| 音色 | `音色`；新增`<规范人物名>.wav`及音色索引。 |

路径连接不重复追加项目名或集号。首次生成前创建实际需要的输出目录及父目录并验证可写；每次保存前确保存在。有效绝对目录尚不存在不算缺参；只读查找缺目录可记录缺失，不强建不用的目录。权限受限不另存别处，不移动旧目录或清理无关文件。

### 工具能力预检

首次付费提交前确认平台参数读取、下载定位和归档能力。穿帮校验开启才要求视频完整解码及实测参数工具；关闭不因缺少ffmpeg／ffprobe或成片检查报告阻塞生成／归档。实际需要取图、遮脸或音色提取时，再核对应素材处理能力。开启检查时优先复用[本地技术检查](references/performance.md#本地技术检查)，不重复探测同环境已核能力。

视觉关闭且无单独要求时不要求全段取帧能力，关联前段也不因此阻塞；局部检查及素材准入只需实际对应范围。遮脸失败不得用原帧上传。提取能力不足仅保留提取待办，仍可用已有合格平台／本地音色；无替代按音色缺项规则记录，不上传未检样本、不擅改开关或购买／上传外部服务。平台已有音色不要求听检能力。其他必需能力缺失先解决，不提交受影响任务。

### 确认对应集数的完整提示词

读取最新完整正文、段号、时长、场景、人物、道具及全部台词／VO／OS，记录来源版本；摘要、文件名、原剧本或他集稿不算就绪。时间轴矛盾、缺台词、时长超限先解决，不裁词。缺稿或实质修订时读[导演衔接](references/director-handoff.md)：有适用实际调用记录必须应用同一制作技能；不可用先查找，仍缺只暂停受影响修订，不换陌生技能或冒称调用。无记录且缺完整稿时请补稿；完整稿的定向修订例外按该参考执行。

建立段号→真实分镜ID→稿件／素材版本及依赖映射，按第4节区分开启校验时的关联验收依赖与关闭时的实际产物依赖。计划从前段新视频获取音色、站位帧或首尾帧时仍等待所需产物就绪；已具备可复用素材不虚设生成后检查依赖。首次提交前按[依赖说明](references/multi-episode-scheduling.md#依赖说明与独立段就绪检查)说明具体等待原因，不只写“同场景／有关联”。

### 剧情内文字默认放行

剧情必要短信、定位、来电界面、合同、收据、招牌等文字与载体默认允许，不因可读／未遮字拦截、询问或重生。旧稿“无任何文字／无UI”冲突时另存修订为“允许剧情必要的道具文字与屏幕界面；禁止额外字幕、水印、LOGO及无关片头片尾文字”，保留原版与剧情。平台同步先查历史及授权；导演稿同样遵守。用户对具体文字的新要求优先，实质连续性错误不豁免。

### 预检不通过时

只询问真实缺项，沿用已确认参数。**总路径空白、占位、非绝对或冲突未解时，不编辑平台、上传、生成或自行保存到推定目录**；不从项目名、工作／下载目录、旧分类路径或其他任务推断。等待可做路径无关的资料检查，平台已有素材不能免填。

```text
$jumeng-video-operator
操作模式：<网页或剧梦CLI，必选>
项目名称：<准确项目名>
选集：<集号或列表>
项目总路径：<必填绝对目录>
一键引用：关闭
```

## 2. 平台定位与已有结果

按当前模式定位真实项目／集／分镜，先检查目标和历史再编辑。网页关键操作前处理[遮挡浮层](references/browser-workflow.md#关键操作前处理遮挡浮层)，保护未保存内容；操作结果不明先对账，不连点。CLI取不到必要历史证据用网页补证。只使用受支持接口；需要原生UI时读取 computer-use。各组动作后观察结果，切页不复用失效句柄；纯回查不重读完整正文。

普通缺卡片按已确认段数顺序创建。修复先按[整段与补片分流](references/continuity-review.md#两端问题的整段重生成门槛)判断，再创建／编辑对应卡片，不能先付费补一端再核整体条件。生成中或提交不明先对账。

### 分镜命名与补片位置

- 普通名称与已核实提示词编号一致，如`25-1`；用真实ID映射，不凭位置猜号，插入补片不顺延原编号。名称正确不重改。
- 首补紧接原卡片，名`25-1（补）`；同原片后续独立补片依稳定补号为`25-1（补2）`等，组成连续一组。同区间映射重试复用卡片／补号；多源补片以主问题分镜命名及插入，全部来源另记映射。
- 按[CLI命名与插入](references/cli-workflow.md#分镜插入与改名)或[网页操作](references/browser-workflow.md#分镜名称与补片插入)执行。可创建时命名就一次完成，不操作时长；读回真实ID、名称、实际位置和原后邻卡片，不能只看成功提示。
- 改名仅维护元数据，不授权覆盖正文、历史或选用视频；有歧义先解决。记录编号／ID／名称／补号／插入锚点与本地文件对应，不因改名重下。补片按替换关系进入剪辑／导出，不追加重复剧情。

### 已有视频的覆盖确认

任务开始前已有成功视频，列项目／集／分镜／版本，确认保留或覆盖；空卡片不证明无历史，普通“生成整集”不含覆盖授权。未决定或保留时不改正文、引用和选用结果。已有明确覆盖／定向修复授权不重复问，覆盖不包含删除历史；确需问时说明并链接本节要求。

本次已授权生成范围内，穿帮校验开启后的实质问题可在预算、上限和停止条件内自动归因并修复；关闭不新增成片检查、自动补片或重抽，旧检查／修复待办不再作为无实际输入依赖后段的等待理由。已经明确不可用的参考素材不能继续引用，具体处理按第4节。用户此后明确要求单次定向修复时只按指定范围处理，不自动开启全段检查，且关闭状态下不委派补片子智能体。次数0／耗尽只准备方案，失败／取消／停止不自动重试。

## 3. 素材与音色引用

**顺序固定：当前项目平台全部素材→对应本地目录递归查找→按类别处理缺项。** CLI查无单集筛选的项目素材并覆盖分页；网页每次进入素材选择先把“本集素材”切到[全部素材](references/browser-workflow.md#素材范围先切换为全部素材)并核实生效，人物、场景、道具、站位、音色及一键引用均适用，不改变编辑集数。

按准确名称／确认别名及类别核对身份造型、空间日夜、用途、来源版本或音色准入。平台有合格素材直接用，不先扫本地、不要求同名本地文件、不重传；真实缺失／不可用才查本地。搜索／加载失败、未读完分页或范围不明不等于缺失；同名歧义不选首个，不跨项目盲搜。场景保留用户图名，平台简称只做映射；有效证据按[素材缓存](references/performance.md#任务内素材缓存)复用。

- **所有出镜人物（含无台词者）的正确形象及真实引用必须齐备，缺失禁止生成该段。** 平台无素材再查`人物`目录并看图核验上传；仍缺记录范围与原因，继续独立段，不删人物、不用文字或别人代替。全段仅画外发声不要求形象素材。
- 场景、道具、音色平台和对应本地递归查找均无可用者，记录路径、名称、候选及原因后可跳过，不再询问；音色须查索引，提取关闭也查已有样本。有可用者必须用，保留剧情／完整对白、删除空标签。权限或查找未完成暂停受影响提交。
- 按[CLI真实引用](references/cli-workflow.md#素材与真实引用)或网页真实`@`流程逐处绑定、保存、回读；纯文字、未应用关系行和“请选择”不是引用。错误站位图停用并移除未提交后段引用，按第4节处理，不能解除人物与依赖门槛。
- 音色按[上传与复用准入](references/voice-extraction.md#上传与复用准入)逐句对应台词／VO／OS的说话人，实际音频标签放在“参考”和“音色”之间；中间有括号时按[括号替换](references/browser-workflow.md#音色括号替换)整体替换括号及内容。独立旁白沿用原稿及用户约定，不冒用他人声音。

### 一键引用开关

网页开启时必读[一键引用流程](references/one-click-reference.md)：先“全部素材”检齐人物／道具并完成必要补齐，再进入面板；第一项编辑为“一键清空”，按提示词原名新增关系并绑定，删除已确认无可用可选素材的未匹配行，最后“确认并引用”并回读保存。人物缺失不进入面板，不靠删除人物行解锁。关闭用手动`@`；CLI不执行此面板；场景、站位和音色沿用各自流程。

### 缺失音色提取与存储

音色涉及上传／复用读[准入](references/voice-extraction.md#上传与复用准入)，开启提取才读对应提取、听检和存储步骤。平台已有合格音色（含原生、自定义、角色绑定）仅核身份／版本和可用状态，不列听检待办，不强要本地文件／来源视频，保护已有配音。确需取样时先按[采用音轨选择来源](references/voice-extraction.md#按采用音轨选择取样来源)，不取补片已弃用的声音。新提取样本须实际同人连续独立讲话3–5秒并通过技术与听检后才上传，不能先上传再借“平台已有”免检。

计划给后段复用的样本先完成来源及样本准入，客观无合格样本才按缺项规则跳过；不主动取消依赖抢提交。其他人物及末段的提取可在等待窗口完成，未清待办不称全部完成。关闭提取停止后续提取及听检，待核样本不变为可用；不额外生成视频取样。细节、角色保存及索引以[音色流程](references/voice-extraction.md)为准。

## 4. 关联分镜顺序生成与站位复用

**先按“站位与视频穿帮校验”决定检查和等待范围。** 开启时，对实际采用内容及接点执行视觉／站位检查，对整文件执行解码和实际参数检查，必要修复按授权、预算及次数处理。关闭时不执行全段／局部穿帮、首尾帧衔接验收、完整解码、时长／分辨率／旋转实测或组合验收，也不调用成片检查脚本；不以“最低验收”“技术检查”或“已知问题复核”恢复自动检查。记录“成片检查按设置跳过”，不得写成已检查通过。

**开启时，关联后段等待直接前置的当前原视频或[组合衔接版本](references/interval-repair.md#组合验收与后段放行)完成所需验收。关闭时，不因剧情连续、同场景或相邻编号等待前段生成／验收。** 只检查提交时真正需要的输入是否已有：例如两段可复用同一已核验站位图、提示词位置关系没有变化，且不需要前段新产出的图像／声音，就分别通过自身预检后提交，无需先生成前段来证明站位不变。仍遵守平台容量、预算、去重和用户明确的提交顺序。

关闭时仍需等待的，是尚未取得的真实产物：要从前段新视频截站位图、引用其首尾帧，或提取计划复用的音色。等待仅至所需文件生成、落盘且对应素材可用，不追加整视频质量验收。能使用已有适配图／音色时先复用；不能用未存在的文件、错误参考或伪造引用提前提交。关闭穿帮校验不关闭独立的音色提取及其样本检查，也不免除提交前人物齐备、真实引用、遮脸参考准入、授权和费用核验。

中途关闭立即停止新增成片检查、自动修复及补片文稿委派，清除仅因这些检查形成的等待；正在运行的本任务本地检查／补片子智能体有安全中断能力时停止并确认，无能力则收回结果后不继续展开，状态不明不重复启动。保留已有稿件和真实计数，不自动取消／重提已付费视频任务。已知错误留在记录中，不强称成片合格；仅当错误确实使本次需用的参考／输入不可用时阻塞相应素材，不扩大为整条剧情链等待。旧单独检查与旧子智能体开启记录不能覆盖本次关闭。用户此后另有明确单次检查／修复指令，只执行其具体范围，仍不委派补片子智能体。

中途开启只处理当前未完成范围需要的检查／修复，保留已有在途任务，不因开关改变自动重做已交付视频。切换状态更新依赖表：关闭改按真实产物依赖，开启按关联验收依赖；不得取消在途生成或重置费用／次数。

站位素材仍先平台、再本地`人物站位`，已有适配图直接复用；不为复用旧图要求无关前段先出片。需要新取图时按[站位候选](references/position-frame.md#候选帧选择与跳过边界)仅处理实际素材所需范围，关闭不扫全片。修复自身的[正常画面来源](references/interval-repair.md#站位图优先复用与修复专用来源)不建立“先修好才能修”的循环；提交等待范围始终服从本节。

### 站位图先遮脸再使用

首次取图／复用读[站位图流程](references/position-frame.md)。所有实际使用的站位图必须遮住全部可见脸并核验，采用白色不透明实心椭圆，优先当前内置图片编辑；只改面部、保留真实布局，不补画站位或改变人物身份。此为素材准入，视觉关闭仍执行，仅看采用图及必要局部。

完成候选→遮脸核验→保存→网页“添加资产”→真实引用，取帧成功不等于引用完成；禁止“本地上传”或CLI上传捷径，平台已有合格图直接复用。稿件人物位置字段补一次用途说明：仅参考空间姿态，**遮脸色块不得进入成片，面貌以对应人物素材为准**。处理、命名、证据及旧图例外仅按该参考执行。

### 等待与多集轮转

出现等待即按[调度规则](references/multi-episode-scheduling.md)执行，单集同样适用：回查全部在途（含提交不明）及待检结果，优先当前集；合并相邻重复扫描。利用等待推进已选范围内独立段／后续集可保存单元，通常30秒、最迟60秒回安全点；尚未满足本节相应依赖的分镜只预备不提交；关闭校验且实际输入齐备的同场景后段可提交，不把检查等待扩大为停工。

仅穿帮校验开启、确需新制补片稿且还有其他生成流程任务需同时推进时，按[内部修订分工](references/director-handoff.md#子智能体并行修订)委派一个子智能体；只剩写稿或工具不可用时主流程应用原技能。关闭时不自动制补片稿，也不新增或恢复子智能体，用户另行明确的单次修复由主流程处理。版本、轮次与超时仍按导演参考，收到稿不等于视频通过。

## 5. 每次生成前的最终校验

有效证据按[共用检查](references/performance.md#相邻步骤共用检查证据)复用；不能证明平台未变时完整回读。动态费用、容量、去重、授权、依赖和最终时长每次核对。CLI按[提交前校验](references/cli-workflow.md#提交前校验)提供等效证据，下列网页顺序的业务门槛共同适用。

1. 目标项目／集／真实ID、提示词编号／名称及补片位置正确；范围、总路径、唯一归档目标、目录可写及工具就绪。
2. 已保存完整正文与有效稿一致、台词／VO／OS顺序完整。只按实际引用节点对应位置规范化：一键引用按[正文核对](references/one-click-reference.md#应用保存与正文核对)还原具体名称，音色只替换已记录位置的括号；不全局忽略人物名或括号内容。真实标签及逐句归属另外核对。需要原技能修订的稿件已实际调用并验明当前版本。
3. 全部出镜人物和真实引用正确；无空标签、残留搜索词、失效图。平台“全部素材”范围有证据，可选跳过有有效本地递归查找记录；一键引用已按完整顺序应用保存，音色准入有效。
4. 按第4节当前开关核对依赖：开启时直接前置完成要求的验收；关闭时只核真正需要的输入已可用，不要求前段完成成片检查。站位真实引用及必要音色样本已就绪，依赖未就绪不提交。
5. 模式／模型／分辨率实际正确，档位与画幅／像素映射已核实；“8K”等风格文字不作实际规格。目标秒数来自有效稿；补片整数`G`、源范围／有效长度`L`及余量明确，费用按`G`，开启成片检查时整文件技术检查也按`G`。**至此不操作时长。**
6. 无在途／不明重复任务；历史及修复授权明确，所属各修复链次数、容量、任务预算／已花费用／在途预留允许提交。存在阻塞留在准备阶段。
7. **现在就要提交才选时长**：先模式／模型／分辨率，再设目标秒数、失焦关面板并读回生成区实显值；已正确则只核对，不重设。不能用稿件、旧时间线或缓存代替。CLI在最终请求绑定目标时长。
8. 点击前确认1–7仍有效、保存及前置版本未变，按当前时长后的实际费用核算已花＋预留＋本次，并复核容量／授权／次数。未知费用不当0；必需项失败、待核或不明不得提交。设置时长后又改正文／引用／参数或切页，旧放行失效，下次提交前重核受影响项及最终状态。

全部通过才简报实际参数、费用和允许跳过项，生成一次，立即登记受理ID和状态；不先提交后补验。已有授权不再询问。购买、充值、订阅不在授权内。

## 6. 结果检查、修复与归档

失败、取消、停止不自动重试，“重新校验”不恢复生成。首次下载或恢复归档读[视频归档](references/video-archive.md)：同版本一次下载，在实际工作文件上检查并转存唯一正式目标，不在总目录和素材目录分别下载；例外须有真实失败／丢失／损坏依据。所需检查通过才正式归档，旧不同版本按授权保留历史。

### 成片实际参数核对

**仅穿帮校验开启时执行本段成片检查。** 每段含独立／末段完整解码、实测时长／像素／旋转；补片按整数`G`，仅按真实时间基允许帧边界舍入。检查不符保持待核，不改目标掩盖问题；按[技术检查](references/performance.md#本地技术检查)共用报告。关闭时不运行这些检查，平台成功后按[下载归档](references/video-archive.md)确认真实版本、下载完成及文件落盘即归档，报告检查跳过；输入素材处理仅在实际需要时进行。

### 穿帮严重程度

视觉开启或处理具体实质问题时读[视觉检查与修复](references/continuity-review.md)。实际前置动作足以解释切后站位时不算穿帮，可省略中间走位；轻微道具瑕疵不影响剧情／关键动作／衔接则记录放行，不重做、不询问、不阻塞。重大站位、空间、方向或关键道具错误先按[问题归因](references/continuity-review.md#先判断穿帮原因)对照实际提交稿及引用：疑似模型执行偏差保留正确内容提取重抽；提示词问题先分析整段，再把画面取舍指令与修改方案交给原制作技能。按剧情影响定向修复，未解决不放行相关链。

详细分流只依[整段门槛](references/continuity-review.md#两端问题的整段重生成门槛)和[区间补片](references/interval-repair.md)：两端实际问题严格超过全片2/3，或满足规定的两端最短补片覆盖全片例外，才转原卡片整段修复；其余按超过4秒源范围及整数生成规则处理，不借凑时长扩大例外。**先分流，再计数：命中整段条件即结束本轮补片规划，在原卡片重抽，只新增原分镜整段次数，不建合并补片、不扣各补片次数。** 整段额度不足保持待办，不改走补片借额度。只有未触发整段条件、仍有正常内容可保留的局部补片，才按局部计数规则处理；历史已受理次数和费用保留。当前候选、已采用结果、预算及授权始终有效。本段自动归因／修复只在校验开启时运行；开启时弃用余量不触发视觉返工，仍作全文件技术检查，关闭不启动自动修复。

### 下载副本清理

按[归档收尾](references/video-archive.md#归档收尾与恢复)只清理本次已确认冗余副本；不删真实历史、组合仍引用的原片或不明文件。正式文件核验后才清理，成功移动无需再删源／重下。清理失败记待办，不阻塞已就绪依赖，也不重新下载。末段可无需站位图，提取开启仍须处理音色待办。

## 7. 断点记录与交付

在同一任务记录维护[精简摘要和明细](references/performance.md#断点与恢复)，覆盖模式／能力、参数及总路径、授权／停止、当前稿与原制作技能、真实ID／名称／补片位置、素材查找与引用、选用文件及依赖、检查、全部在途／待办、预算／次数及下一动作。专项字段使用相应参考中的记录要求，不另建重复状态源；不保存凭据、令牌或隐藏接口数据。

提交前记意图、来源／依赖、次数归属及预算预留，提交后立即记实际ID／时间／状态；未知先对账，不重提。计数按[稳定链规则](references/continuity-review.md#次数停止与结论)，文稿与视频分别记账；合并任务费用只记一次。下载按[版本与路径记录](references/video-archive.md#下载到归档的顺序)恢复，源文件已移动消失不代表需重下。

恢复核对平台及本地真实状态，沿用同任务授权和计数，不恢复用户已停事项。交付实际完成范围、文件位置、各类检查及未完成项；技术、参数、视觉、听检分别表述。补片另列片段／组合／最终合成／平台回写状态，组合就绪不等于已剪辑，改名不等于原视频被替换；音色待办未清不称全部完成。保留结果定位及可继续操作的页面。
