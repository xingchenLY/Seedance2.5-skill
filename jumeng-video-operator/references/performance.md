# 效率、缓存与本地检查

首次建立任务缓存或本地处理流程时读取；后续沿用，不每轮重读。这里只减少重复操作，生成条件仍以主技能为准。

## 任务内素材缓存

在本任务进度文件旁保存素材索引，按“已确认项目／绝对总路径＋类别＋规范名＋造型、日夜或用途”等适用条件区分。同名但条件不同不是同一素材。

平台查询另记录实际集数范围及生效依据。只有已确认当前项目“全部素材”范围的查无结果才可作为平台缺项缓存；本集／单集范围的旧缺项记录失效，须切到全部重新查。缓存不能代替每次重新进入选择入口时对实际范围的观察，也不跨项目复用；已核验素材内容可继续复用，不因范围切换重看重传。本地递归查找缓存仍按下列文件有效性规则判断。

缓存同样遵守平台优先：已有合格平台素材及有效准入记录时直接引用，不为建立本地索引而扫描目录；仅平台全部范围确无合格素材后，才查询／刷新对应本地缓存。本地正向命中不授权优先上传同名副本，旧平台缺项失效时先重查平台。

- 首次需要本地素材时，实际枚举该类别目录及全部子目录，记录目录和文件的相对路径、大小、修改时间，名称／别名、候选内容核验结果、来源索引版本及平台可见资产标识。只枚举需要的类别，不扫描其他项目或整盘。
- 正向命中：同任务文件仍可读、路径／大小／修改时间未变，适用条件和平台资产版本未变，可复用实际看图或音色准入记录，不逐段重看重传。文件被替换、元数据可疑、任务恢复或来源有变化时用哈希复核并使受影响内容记录失效；不能确定同一内容就重新核验。每个分镜的真实引用仍须读回。
- 缺失／不可用记录：保存完整搜索范围、准确名称／确认别名、候选及排除理由。复用前刷新对应子树的轻量文件清单，比较路径、大小、修改时间及音色索引；没有变化才沿用旧的内容核验。同一准备单元内相同查询可共用一次刷新，最终提交前确认快照仍有效。目录原先不存在要重新检查存在性；只看根目录时间不能证明子目录未变。
- 新增／删除／替换文件、上传资产、提取音色、用户补资料、造型／日夜改变或音色开关变化时，只刷新受影响类别、候选和使用它的分镜。不要全项目重新核验。无法可靠确认缓存有效时重新实际搜索。
- 权限不足、枚举失败、未读完子目录的结果不能缓存为缺失。重连后重新观察平台资产，不能复用 DOM 节点、光标或上传句柄。缓存不跨项目自动生效，也不解除人物缺失阻塞。

## 本地技术检查

随附 [media_check.py](../scripts/media_check.py)，仅需 Python 标准库及实际可用的 ffmpeg、ffprobe。运行前确认路径及工具可执行，不硬编码开发机器路径；可传入工具绝对路径。它只读输入，创建报告／检查图，不上传、不付费、不修改源视频、不删除下载、不更新最终选用文件。

示例参数中的目标尺寸必须来自已核实的平台档位／画幅映射；未知时省略，报告为待核，不能猜数值填入凑通过。

```text
python scripts/media_check.py --video <实际待检视频绝对路径> --download <已记录的实际下载原件路径> --output <本任务检查缓存目录> --expected-seconds <提交秒数> --expected-width <实际显示宽度> --expected-height <实际显示高度> --ffmpeg <工具路径> --ffprobe <工具路径>
```

默认直接检查唯一下载原件，此时`--video`和`--download`可以指向同一实际文件，报告中的`distinct_path: false`只表示没有独立副本，不能宣称完成了两份文件对比，也不需要为凑参数创建副本。记下本次检查的SHA-256；按[视频归档流程](video-archive.md)转存后，再核对正式路径上的哈希等于该值，才完成归档内容一致性确认。确有不同路径的下载原件／工作副本时才分别传入并核对双方哈希。文件仍在写入时不得检查或移动。

- 一次运行完成元数据、源与下载副本 SHA-256、全段视频和存在的音轨解码、参数比较。仅开启站位与视频穿帮校验或用户单独要求全段视觉检查时按需加`--contact-sheet`；关闭且无单独要求时，关联前段也不生成联系表、不逐镜抽查。全段解码是文件完整性检查，仍须执行，不等于人工观看全片。需要联系表时与完整解码合并在一次 ffmpeg 处理内，按1fps输出4×4分页初筛图；它不是逐帧验收。按实际要求查看切点／关键动作，必要时加密抽帧或播放；局部要求只取对应范围，不扩大为全段检查。不要把缩略图直接当可靠站位图。
- 报告记录实际时长、帧率／时间基、像素尺寸／旋转、目标与差异、工具版本、解码结果、缓存命中和阶段耗时；只给技术状态，不给视觉／音色验收结论。每次保留独立报告，进度记录采用工具返回的`report`路径；`report.json`仅是最近一次结果，不能充当旧版本的持久记录。退出码0为本次技术项通过，2为待核，1为执行错误；读取本次报告，无新报告时不能沿用旧成功结果。
- 元数据中的平均／标称帧率一致且时间基有效时，记录该帧率依据并允许最多一帧加一个时间基单位的舍入误差；信息不一致时不自动放宽。解码异常、尺寸／时长不符、未知旋转／目标映射和副本哈希不符均待核。报告失败或缓存不完整不得作为通过证据。
- 原始解码与取帧缓存绑定视频SHA-256、脚本版本、工具版本和取帧设置；每次仍实际读文件计算哈希、重新核对本次目标／下载副本。缓存损坏、输出图变化或视频变化就重做，不凭同名文件复用。
- 技术缓存与人工视觉结论分开：视觉结论还绑定提示词版本、前置选用版本、场景／站位依据、检查范围和当前开关及用户要求。只有这些均未变才复用；只变目标时重新比较参数，需要视觉检查且剧情依据变化时才复核对应视觉，不无理由重复全段解码。关闭时将全段视觉记为按设置跳过，不记失败或待核；通过技术检查且其余依赖与预检完成后可放行关联后段，不能仅凭缓存报告自动提交。
- 报告为待核时按主技能查原因，不通过改目标或处理视频伪装合格。未提供已记录的下载原件时，脚本会把来源哈希列为待核；先定位现有原件或可追溯的原下载哈希记录，不因此再次下载或新建副本。已移动且原路径不再存在时，用保存的来源哈希与正式文件重新核对，配合仍有效的同内容技术报告完成归档验证；不能拿正式文件同时充当两个输入，伪称重新核验了已丢失的原下载。脚本不可用时可使用已验证的等效本地工具，保持相同证据要求。脚本不负责命名、转存或清理，这些仍须实际执行并记录。

## 耗时与恢复

任务记录里保存提交时间、首次观察完成时间、回查次数／耗时、页面切换、素材枚举／核验、下载、技术检查、视觉检查及音色处理耗时。首次观察完成不是平台精确完成时刻；区分平台等待、自动化操作和检查时间，不声称未经实测的提速比例。

恢复时先读本任务记录并检查缓存对应文件和版本，不重复读全部提示词、扫描全部素材或重跑已通过视频。只有内容未变且检查依据仍有效才复用。时长在预填／等待阶段只记录目标，不操作平台控件；仅准备立即提交时选择并读取当前实际值，缓存不能代替这次读回。全部最终预检通过才可生成。主技能和参考未变、上下文仍可用时不重复加载；用户改变校验设置、反馈关闭无效或说明 skill 更新时，重新读取当前安装的主技能和相关参考，按最新指令更新待检／阻塞，旧摘要和缓存里的“必须衔接验收”不能代替现行规则。

本地脚本可由受支持的工具异步执行，等待期间推进无依赖准备，并按调度返回回查；领取脚本结果前保持“待检”。不创建常驻服务、外部任务或新代理。进度展示聚焦发生的变化和异常，长正文与完整工具日志留在文件中按需读取。
