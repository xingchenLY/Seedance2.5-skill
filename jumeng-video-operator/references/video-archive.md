# 视频下载、命名与归档

首次下载、下载状态不明或恢复未完成归档时读取。一个生成版本在正常流程中只下载一次，失败或文件确实丢失／损坏的例外按下文处理；下载落点、待检工作文件和正式成片是同一内容的处理阶段，不是三个各自下载一次的目录。归档不改变当前视觉校验开关、历史覆盖授权及生成顺序。

## 成片检查关闭时的归档

“站位与视频穿帮校验”关闭时，只核对正确任务／版本、工具下载完成、实际文件可读且不再写入、正式路径与命名及转存成功；不调用ffprobe／ffmpeg／media_check，不实测时长、分辨率或完整解码，也不观看成片。必要的源／目标哈希用于复制、覆盖和副本身份确认，不作为恢复视频质量检查的理由。技术／视觉状态记“按设置跳过”，可以按原编号归档，不称检查通过。

下文检查报告、技术通过等条件仅在主开关开启或用户此后明确指定该次检查时要求；关闭以落盘确认代替归档检查门槛。下载失败、部分文件、身份不明或目标冲突仍需处理，不能把真正的下载失败记成完成。旧“已下载未检”状态关闭后接续归档，不重新下载、不等待检查。

## 剧梦CLI结果下载

剧梦CLI模式先用 `task status` 取得成功任务对应的资源 URL，核对项目／集数／分镜／任务版本和视频资源类型，不盲取第一条 URL。只有CLI未覆盖取结果能力时才用网页补齐；当前CLI无下载命令时用环境允许的下载工具获取该实际返回的结果，不能猜接口、拼资源地址或把剧梦凭据发给资源域名。将下载意图、工具、版本及实际落点纳入下面同一去重记录，不能CLI下载后又点网页下载。签名URL不输出到聊天或普通日志，受保护的临时记录仅保留任务所需信息；失效时重查同一任务取得新地址，不重新生成。

支持指定路径时只下载到下表 `.待归档` 位置（允许受控的部分下载后缀），完成后在该文件上检查，再移动到唯一正式名称。无路径选项则登记真实落点并按原流程转存。下表“下载事件／工具路径”同时包括CLI配套下载工具，不要求浏览器事件才能证明完成。当前开关要求的检查、下载落盘、转存身份与清理规则对两种模式完全相同，关闭不以下载完整性为由追加全段解码。

## 路径与文件角色

先辨别原分镜视频与独立区间修复片段。后者按[修复片段归档](interval-repair.md#归档验收与后续衔接)使用`<源集号>-<源分镜号>-修复NN.mp4`，保留原视频；以下待归档／历史路径中的文件名及分镜目录键相应替换为该修复身份。下载去重、技术检查、哈希、历史保护及副本清理共用本文件，不因新增修复卡片覆盖原`<集号>-<分镜号>.mp4`或再下载一份。

平台普通名称`25-1`对应`素材/25/25-1.mp4`；`25-1（补）`对应`25-1-修复01.mp4`，`25-1（补2）`对应`25-1-修复02.mp4`。用真实ID、源编号和稳定补号关联；插入后的卡片位置、自动显示序号或平台下载原名都不改变正式目标。改名／调整补片位置不触发重新下载、另存副本或修改已归档文件名。只修画面而选择原音轨时，完整保留独立补片原始文件，音轨选用记在映射中，不在归档阶段擅自混音或覆盖原视频。

组合衔接通过不等于原文件已剪辑修好；仍被组合引用的原文件须持久保存在本项目并记录精确路径／哈希，可沿用`.待归档`位置及待剪辑状态，不发布为合格原成片，也不作为冗余临时副本清理。修复片段按整数生成总长`G`完整解码、实测并原样归档，保留余量，正式文件不裁成小数长度。组合记录仅采用已核实的有效区间`L`，明确排除余量；时长检查不将`L`误当`G`。无需复制／拼接一份视频来解锁后段。实际剪辑完成时另按授权核验最终版本。

| 角色 | 规则 |
| --- | --- |
| 原分镜正式成片 | 唯一目标为`<项目总路径>/素材/<集号至少两位>/<集号>-<分镜号>.mp4`。例如第1集第3段为`素材/01/1-3.mp4`，第12集第4段为`素材/12/12-4.mp4`。文件名中的集号、分镜号用已确认段号的十进制数字，不补零，不用卡片位置、平台随机名、时间戳、`(1)`或版本后缀代替；独立修复片段使用本节上述专用名称。 |
| 下载落点 | 以本次浏览器下载事件／工具返回的实际本地路径为准；平台原文件名可以临时保留。工具允许指定路径时可使用下行待归档位置。不假定外部和内置浏览器落点相同，不为改文件名或换目录再次点下载。 |
| 待检工作文件 | 默认就是已完整下载的原件。确需从工具管理的临时区复制出来时，只转存到`<项目总路径>/素材/.待归档/<本任务记录键>/<生成版本记录键>/<集号>-<分镜号>.mp4`；记录键须为安全的单层目录名，不含路径分隔符或`..`，不能伪造平台版本号。只在需要时创建。不要再在项目总目录或另建“视频总文件夹”留一份。 |
| 历史版本 | 仅保留确实不同且需要留存的旧选用版本，位置为`<项目总路径>/素材/.历史版本/<集号>-<分镜号>/<旧版本记录键>/<集号>-<分镜号>.mp4`；旧版本记录键同样须为安全单层目录名，不含路径分隔符或`..`。本次同内容下载原件或中间副本不是历史版本；不每次归档都额外复制一份备份。 |

上述临时与历史目录不属于正式成片的集号目录。正式成片始终按主技能第1节路径交付，不在总目录、`素材`根目录及其他位置各建一套。若浏览器自身已落到项目总目录，把该文件作为本次来源处理，归档后按收尾规则移走／清理，不主动再存另一份。

## 下载到归档的顺序

1. **先确定唯一目标和版本。** 从已确认映射读取项目、集号、分镜和平台可见生成版本／任务标识，预先算出正式目标。以这组身份查本任务记录和精确已知路径，不只看文件名。正确版本已归档则复用；已下载未归档则从该文件继续；正在下载或状态不明则先查下载记录和实际落点，不重复触发。技术检查、取站位帧、提音色和多集回查共用同一下载记录。
2. **一次下载并立即登记。** 保存下载意图后触发一次，记录浏览器／工具、下载标识、实际路径和版本关系。等待工具确认完成、文件可读且不再写入；部分下载文件、按钮已点击或文件名出现不等于完成。工具已返回可用本地文件时直接使用，不再从同一结果链接下载第二份。只有确认下载失败且无法续用，或同版本所有已知本地文件确实丢失／损坏，才记录具体原因后重新下载；生成失败、取消、停止的处理仍遵守主技能。
3. **按开关处理同一个工作文件。** 开启时记录大小、SHA-256、技术报告及当前要求的成片检查，未通过保留待核；关闭时仅完成上节落盘确认，记录技术／视觉跳过，不生成技术报告。只有原位置不能用于后续处理才建立待归档副本，核对内容身份；不为检查另复制一份或重复下载。
4. **本地转存并落实正式名称。** 开启时检查通过、关闭时落盘确认完成后，将工作文件移动／重命名为预先计算的正式路径；支持同一文件系统的安全移动时优先使用移动。每次转存或历史备份前先记录源、正式目标、临时目标、历史路径、各版本哈希及待执行阶段，动作后立即记录结果。无法直接移动或跨文件系统时，先在目标目录内写唯一临时文件，完成复制并核对源／目标哈希后再改为正式名；不要让未完成的复制占用正式名称。转存前后均验证解析后的路径位于对应允许目录内，执行中发现未记录的新同名文件就停止并按下节处理，不能强制覆盖。源与正式目标本就是同一文件时无需移动、复制或删除。
5. **读回文件再记完成。** 确认正式路径和文件名完全符合规则，文件可读、实际大小和哈希等于已记录的下载内容；仅改路径且内容未变可复用同哈希的技术／视觉结论，无须重新全段解码。把报告中的旧工作路径与新正式路径关联记录，提音色及取帧后续使用正式路径。随后完成下节临时副本收尾，再将下载归档事项标为完成；“复制命令成功”或“平台下载完成”都不能直接当作归档完成。

## 同名目标与历史保护

- 正式目标已存在时，先核对来源版本、内容哈希及实际选用记录。同版本、同内容且已有相应归档记录（开启时另有适用检查记录），直接复用并处理本次多余临时文件，不再下载，不生成`1-3 (1).mp4`或`1-3_新.mp4`作为另一个正式文件。
- 目标属于不同历史版本时，沿用主技能已有覆盖／修复授权；未授权则保留目标和新工作文件，记录待决定。已授权替换时，先将旧版安全保留在上表历史位置并验证，再发布新正式文件。历史位置已有同一已确认旧版且哈希一致时复用该备份，不另建重复备份；不同内容或关系不明则保留现场并记录冲突，不强制覆盖。不能借“命名规范”删除或覆盖用户旧视频。
- 原下载文件名、相同大小或时间接近不能单独证明属于该段／该版本。关系不明时保留待核，查清任务与下载记录后再操作，不能随便选一个视频改名交付。

## 归档收尾与恢复

- 只处理本次记录中明确归属该版本的下载原件和临时工作文件，不扫描全盘或项目下所有同名／同哈希文件进行删除。真正历史版本和用户已有文件不属于本次副本清理范围。
- 最终文件已确认完整且哈希与已检内容一致，候选临时副本也同哈希，路径经解析并确认是不同文件，且用户未要求保留时，精确删除该临时副本后再次确认正式文件仍在。路径别名、大小写变化、符号链接或硬链接不能仅靠路径字符串不同判断；不能确认独立文件则不删，记录原因。严禁递归删除目录或通配清理。
- 已成功移动的源文件本来就应不存在，不补下、不为保留“下载原件”再复制回去。同一版本收尾后仅保留一份正式成片；明确要求保留的原件、待核结果和真正不同版本分别记录用途及状态，不混称重复下载。
- 文件占用、权限或其他原因导致临时副本清理失败时，保留“正式文件已归档，副本清理待完成”和准确路径；不谎称已清理，也不因此再次下载、再次归档或阻塞已具备条件的关联后段。下次先核对正式文件及剩余副本，再只重试该清理。
- 中断恢复先对照状态：下载中／不明查原下载；已下载未检继续检查；已检未归档继续转存；正式文件已发布但源路径仍在则只核对并收尾。转存后源路径消失或旧记录尚未更新时，先检查已知正式目标及临时目标，不能仅因源路径不存在重下。
- 替换中断、旧版已移入历史而正式路径暂空时，先核对记录中的旧版历史路径／哈希和新版工作或临时文件，保留旧版并从尚未完成的发布阶段继续。新版仍在就不重下；新版丢失或损坏时记录该异常，旧版历史不删，不把“正式路径暂空”误当从未生成。

没有实际项目路径、文件和下载记录时，只能指出流程缺口，不能把“两处有视频”直接断言为两次网络下载。核实某次问题时对照下载事件、两个绝对路径、生成版本和SHA-256；仅同哈希可证明内容相同，不能单独证明下载次数。
