# 剧梦CLI执行流程

仅在用户已选择`操作模式：剧梦CLI`时读取。CLI 是执行通道，不替代主技能的素材准入、关联等待、授权、预算、生成前校验及文件归档。以下命令依据本次核对的 Dreama 1.0.5；运行时以实际安装版本的帮助和返回结构为准，不锁定版本号、不猜新参数、不调用未公开接口。

## 安装与可用性检查

1. **先查安装，再查平台。** 使用系统命令发现工具定位 `Dreama`／`Dreama.exe`（Windows 可用 `Get-Command`），找不到时仅检查标准安装位置，例如当前用户 `%LOCALAPPDATA%/Programs/Dreama/Dreama.exe` 或用户明确提供的位置，不整盘扫描。记录实际可执行绝对路径。文件存在不算安装成功，必须实际执行 `version` 和 `--help`，核验可运行、版本、环境及所需命令。
2. 未找到、无法启动或必要命令缺失时记录具体原因；缺少CLI时说明需要先安装，可提供已核实的安装途径并请求安装所需操作，不擅自下载运行未知安装脚本，不静默改为网页模式。用户选择改用网页时才改变模式。仅缺某项功能时按下节网页补齐，不把整套CLI判作不可用。
3. 安装通过后调用 `auth status`，再以 `auth whoami` 核对账户和可用积分、以 `ping` 检查服务可达。只展示必要的状态及账号区分信息，不输出 token。未登录／过期时请用户通过CLI支持的登录方式完成认证；不要求把token发到聊天，不复制浏览器凭据。网络失败和权限不足如实区分，不当作素材缺失。
4. 从 `version` 核对目标环境及服务地址。CLI 与网页补齐必须对应同一已确认账户和项目环境；不通过猜测 `--server`／`--env` 切换。没有证据不得把测试环境结果当生产结果。
5. 首次使用相关功能时读对应 `--help`，建立按版本绑定的能力记录；同环境同版本沿用，不每轮重读整套帮助。恢复时核对可执行路径、版本与登录状态，变化后只重查受影响能力。不要将开发机器用户名或固定安装绝对路径写成所有用户的必需路径。

## 定位与能力分配

**已支持且属于本次授权范围的操作全部调用 CLI；用户指定的站位图上传入口除外。** 站位图新增上传必须通过网页[添加资产](position-frame.md#站位图固定使用添加资产)，禁止“本地上传”入口，也不改用CLI上传命令；完成后回到CLI。 不因网页习惯、已开页面或网页按钮名称出现在旧规则中而重复操作。使用本地程序运行 CLI 不属于浏览器内部接口；不从浏览器读取隐藏状态或自行实现未公开HTTP请求。具体命令参数先经当前帮助确认。

| 操作 | 已核实的CLI入口 | 核验要求 |
| --- | --- | --- |
| 版本、账户、连通性 | `version`、`auth status`、`auth whoami`、`ping` | 安装、登录、权限及网络分开判断 |
| 项目与成员 | `project list/get/members` | 按返回的真实ID唯一定位；成员仅实际需要时查 |
| 剧集、分镜定位 | `series list/get`、`storyboard list` | 分页读完目标范围，名称／段号不当ID |
| 创建已授权的缺失分镜 | `storyboard create` | 按主技能已确认段数及顺序；不自行创建缺失剧集或项目 |
| 保存正文／定向修改 | `storyboard set-video-prompt`、`storyboard update` | 只传本次需改字段，回读完整正文及真实引用；预填不改时长 |
| 全项目素材与既有音色查询 | `library list` | 仅当前项目，无单集过滤，处理分页及形象变体 |
| 组装真实图片／音频引用 | `prompt assemble` | 使用返回的原始标签，按下节放到指定位置并回读 |
| 模型与参数枚举 | `capability list` | 用真实 `eid` 及支持枚举，不从显示名称推ID |
| 单次费用预估 | `point calc` | 最终提交前按实际目标时长、模型及计费参数核价 |
| 单段视频生成 | `video produce` | 全部检查通过后执行一次；保存任务ID，按依赖逐段提交 |
| 回查状态、错误与队列 | `task status/get/queue` | 批量查已知任务、队列分页；不把队列当完整历史或完整容量证明 |
| 获取生成结果地址 | `task status` | 核对成功任务与资源类型，再交给合法下载工具归档 |

能力表是当前基线。遇到新功能先检查当前版本帮助；已经新增并能提供所需证据的命令应使用CLI。命令存在不等于满足业务要求：例如 `library add-image` 新增形象记录不等于上传本地文件，`produceType=5` 不证明已选择“全能参考”。

当前尚未核实的本地图片／站位图／参考视频／音色上传、完整历史与选用版本管理、全能参考设置、完整任务容量及剧集占用信息，按实际缺口用网页补齐。记录“缺少的能力／证据 → 网页执行项 → 结果”，完成后回到CLI；上传后由CLI重新查询真实素材ID。网页补齐仍按[浏览器流程](browser-workflow.md)先外部浏览器，不能调用时用内置浏览器，保持同一账户／环境／项目。必要证据无法取得则阻塞对应操作，不降低门槛。

同一分镜的网页补齐按依赖阶段集中安排：编辑前一次核查必要历史与授权，再集中完成当时已就绪且获准的上传；提交前集中核查尚缺的生成模式、容量和当前费用证据，随后返回CLI提交。不要对每个素材反复开关网页，也不跨越历史检查或未就绪依赖提前编辑；不能为等待后续集素材攒批次而拖延当前就绪单元。记录稳定证据的适用范围／版本，只有这些条件可确认未变才复用；容量、费用和在途状态仍按本次提交时点核对，不用准备阶段的旧页面代替。

临时CLI报错不等于不支持。先处理认证、权限、参数或网络原因；写入／提交结果不明先查询对账，不换网页再次写入、创建或生成。未解决时保留断点，不擅自改变用户选择的操作模式。

CLI 中新增资产、付费生图、批量生视频等能力不会自动扩大任务范围。缺失人物仍先按主技能查本地并上传，未找到禁止生成；不为了补缺调用 `library generate/batch`。现有任务按单段 `video produce` 执行，不用 `video batch` 绕过逐段检查、依赖或覆盖授权。用户另行明确要求的资产修改等操作，CLI支持时也使用CLI，并只改授权字段。

## 素材与真实引用

1. `project get` 确认项目及 `promptMode`（如 `drama`／`comic`），以 `library list --project-id <真实ID> --type <类别>` 查素材；不传 `--series-id`，相当于当前项目“全部素材”，不需要先在网页切筛选。搜索按准确名称及已确认别名，逐页确认结束；无单集过滤、类别、搜索词、分页范围和结果均入缓存。站位图或音频若不能从当前命令可靠查询，先用网页补齐该类别范围，不能据普通人物／场景／道具列表无结果直接判缺失。
2. 核验角色身份、造型及所选形象、场景日夜、道具用途、音色资格。保存 `assetId/elementId`、`imageId`、音色ID／版本等实际返回映射，不能混淆。多造型按提示词及已有用户选择匹配，确有歧义才问，不因主形象标记而选错造型。平台素材优先，本地仅在平台全部范围确无合格素材后查找；人物缺失阻塞，道具／场景／音色按原规则完成本地查找后才可跳过。
3. 调用 `prompt assemble` 取得CLI生成的真实引用标签。`--ref` 仅用当前帮助支持的选定形象名或精确引用格式，验证返回身份；同名歧义不选首项。`--kind video` 可能自动加入音色、替换多处名称或添加前缀，所以组装结果不能直接覆盖有效稿。按实际 `promptMode` 使用CLI支持的输入语法，必要时只用临时组装文本获取已核实素材的标签；临时文本不是改写原稿的授权。
4. 从组装结果提取原始完整引用节点，保留节点字节内容，建立“类别、素材身份、原始标签”映射。在完整有效稿中定位：图片插在对应场景名／出镜人物名／特殊道具名之后；不替换原名称、不在运镜和正文每次提及处重复加图；站位图须先通过[遮脸准入](position-frame.md)，只将已遮脸且站位有效的图放人物位置字段；音频逐句放在对应说话人的“参考”和“音色”之间，其中有括号则整体替换括号及内容，保留说话人前缀、情绪时间和原对白。同一人多句分别引用同一已核验版本。
5. 不手写或伪造span，不改变返回标签的属性、编码或内部内容，不把素材名／空格／换行塞到空标签中。允许整体移动或复用已确认的原始标签到指定位置，但不能用一个人物标签冒充另一个。保留完整有效稿，按明确的位置映射比较预期文本；不把自动添加的字幕禁令、对白格式改写或未请求的多余标签带进最终稿。
6. `failed` 项、缺标签、类型／身份错误、未核实音色均不能当引用成功；修正映射或补齐素材后再组装。准许跳过的可选项保留原文字和缺项证据，不留下空标签。人物仍缺时不提交生成。若CLI不能生成某一特殊引用，记录该能力缺口并用网页补齐，仅该处例外，不改成全部手动引用。
7. 用 `storyboard set-video-prompt` 写入最终完整稿，安全传递含引号／换行的参数，不拼接可执行shell字符串、不假定CLI支持未公开的 `--prompt-file`。保存后 `storyboard list` 精确读回该分镜，完整比对文本和每个真实节点的类型、身份、位置、数量、音色版本及保存结果；完整响应留本地，仅输出差异／状态。平台确有无害排版序列化变化时按记录规范化，不能全局忽略名称或括号来掩盖丢字、错引用。

CLI模式统一使用这套引用流程；网页“一键引用”开关记为“不适用（CLI组装）”，无需点击“一键清空／确认并引用”，不能声称执行过面板动作。只有用户另行明确指定必须操作该面板时才遵从其要求并记录网页例外，不同时重复插入相同引用。

## 提交前校验

每次生成（含独立段、关联后段及修复）都先完成以下检查；准备和紧接提交可按[共用检查证据](performance.md#相邻步骤共用检查证据)合并完整回读，不能因两个步骤都写“核验”而机械重复。这是主技能网页最终校验的CLI等效流程。不能先 `video produce --yes` 再验证。CLI 的 `--yes` 是执行参数，不产生新授权；本任务已有授权且范围、费用及修复上限允许时无需逐次询问，历史覆盖和真实新增授权仍按主技能。

1. **身份与工具：** 模式确为剧梦CLI，安装、登录、环境就绪；项目／剧集／分镜真实ID与段号映射、选集范围、必填总路径和输出可写性核对一致。历史编辑／覆盖已核实；CLI无法提供完整历史时先网页核查，空分镜或空队列不证明无历史。
2. **正文与引用：** 完整稿已保存并实际回读，逐处真实标签正确；全部出镜人物齐备，包括无台词人物。素材查询覆盖当前项目全部集数，可选缺项有有效的本地查找与跳过依据，音色满足当前听检／未听检复用要求，站位图实际引用版本已完成全部人脸遮挡核验，不能只拿组装成功当保存成功。
3. **依赖与检查：** 全部直接前置当前版本已生成、归档并通过文件及当前开关要求的检查；计划复用音色已完成来源和样本准入。视觉关闭仍不做关联前段最低限度衔接验收。独立段有独立依据；已知实质错误、停止条件或待核未解除时不提交。
4. **参数与容量：** 用 `capability list` 得到当前可用模型EID、分辨率及格式等支持值；核实模式与比例等未覆盖配置。CLI参数不提供的生成模式必须网页补证，不能用项目 `promptMode` 代替“全能参考”。核对目标时长合法、画幅／像素映射及任务容量；容量／占用不能由CLI证明时查网页，未知不当无限。此时仍不更新平台时长。
5. **预算与去重：** 查询当前已知在途及不明任务，核对修复计数、覆盖范围、已花费用及预留。已有任务或提交不明先对账，失败／取消／停止不自动重试。有阻塞就停在准备阶段，不预设时长等候。
6. **现在才绑定时长并核价：** 前项就绪、现在要提交时，将有效稿目标秒数绑定到最终 `video produce --duration <秒>` 参数，显式核对项目、剧集、分镜ID、模型EID、分辨率、格式等当前帮助支持参数。不得预填时调用 `storyboard update --duration`；不得用智能时长 `-1` 代替已确定秒数。用 `point calc --kind video ... --duration <同一秒数> --number 1` 预估费用，它不设置平台时长。若当前计费命令不能表达最终分辨率等影响费用的参数，补查网页费用／其他已核实的CLI报价证据，不把不匹配报价视为准确值。未知费用不当零；按当前报价重算已花＋在途预留＋本次，满足预算才继续。
7. **执行前最终核对：** 请求参数、已保存正文／真实引用、身份、前置版本、容量及授权仍与上述证据一致，所有必需项已通过或按规则可跳过，简报实际参数、费用及跳过项。保存提交意图、参数／正文版本、前置和预算预留，再调用一次 `video produce ... --yes`。不要单独提前写时长，也不为读取网页时长多做一遍UI提交。任何字段／前置／设置变化撤销相关检查并重新核价核验。
8. **提交后确认，不是补做准入：** 核对退出码、JSON `ok/action` 及新任务标识，登记请求与实际任务的对应关系、时间和状态，回读平台已保存时长／配置（当前CLI能提供的字段），生成完成后仍以文件实测验证。当前版本 `video produce --yes` 会先更新分镜时长及生视频类型再发起生成，后续报错可能已发生部分写入；不明结果保留预留并查分镜／队列／历史，不能重复调用或切网页重提。发现不符标为待核并阻塞后续依赖，不能倒推本次已全部通过。

## 回查、归档与故障

- 按[轮转调度](multi-episode-scheduling.md)覆盖全部在途ID，支持时一次 `task status` 查多项；缺漏、分页或不明任务用 `task queue` 补查，错误详情用 `task get`。返回结果按ID映射，不靠数组顺序。状态未变只更新时间／计数，不输出完整提示词或重复开网页；保留30–60秒有界等待与结果优先顺序。
- 成功任务返回结果URL后按[CLI结果下载](video-archive.md#剧梦cli结果下载)下载同一版本一次，统一工作文件、正式命名、完整解码、参数与哈希核对；本地取帧／音色处理和视觉开关不变。网页下载与CLI配套下载共用去重记录，不能两种通道各下载一次。
- 同时看进程退出码、`ok` 和 `action`；JSON缺失／解析失败不当成功。`login`先恢复认证，`fix_params`核查真实参数，`abort`停止该操作；`retry`只说明错误可重试，不授权重复副作用。只读查询可以有界重试（同一故障最多再试2次，间隔不超过60秒），仍失败记录阻塞。创建／编辑／上传／生成超时一律先对账，确认未执行且原授权仍有效后才可重试；已失败、取消、停止的视频仍不自动重生。
- `confirm`或退出码3时检查是否仅缺执行标志且本操作已在授权内；满足主技能全部门槛才带 `--yes`，不把程序确认提示变成每段额外审批，也不将 `--dry-run` 结果记为真实写入／生成。CLI更新不自动带来新增付费功能授权。
- 默认裁剪JSON，完整结果与提示词按主技能保存在本地任务记录，输出约2,000字符以内的状态／差异；不请求 `--raw` 扩大上下文。仅需要核查的错误字段进入上下文，不输出凭据或签名资源地址。读回全文和引用校验仍实际完成，输出受限不等于可截断检查。
