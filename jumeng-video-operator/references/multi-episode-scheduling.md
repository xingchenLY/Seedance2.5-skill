# 等待、回查与多集轮转

存在生成或提示词修订等待时读取，单集也执行完整回查与独立分镜调度；多集轮转仅在当前任务和已选范围内，不新建用户聊天；补片文稿仅在需要同时推进其他生成流程任务时按[修订分工](director-handoff.md#子智能体并行修订)委派，平台操作仍只由主流程执行。生成门槛以主技能第5节为准。

## 操作模式与回查通道

网页模式沿用下文页面／列表动作。剧梦CLI模式按[CLI流程](cli-workflow.md)以真实项目／剧集／分镜／任务 ID 执行同一调度：用 `task status` 批量查本任务已知在途 ID、必要时用 `task queue` 分页补查，异常用 `task get`；不每轮打开网页。下文“返回当前集”在CLI中指恢复当前集的查询与调度上下文，不要求实际切页；“预填保存”用CLI写入并回读；“选择时长／点击生成”用CLI最终请求校验及单次提交。仅缺失的历史、模式或容量证据用网页补齐，不能用空队列推断没有历史或容量无限。

## 状态记录

- “当前集”是主推进集，临时切集不改变它。记录返回集号／分镜／任务标识／版本用于定位，同时保留当前集全部在途任务（含提交状态不明）、待检、音色待办及编辑断点。
- 已验收的相同版本移出待检，受阻者记录恢复条件，条件未变不反复处理。音色待办与视觉／文件待检分开，避免重复下载和解码。视觉开关与中途关闭后的待办清理统一执行[主技能第4节](../SKILL.md#4-关联分镜顺序生成与站位复用)，不得以旧的最低限度衔接验收继续阻塞；关闭时视频技术及视觉待检均移除，已知问题留记录；只有当前真正不可用的素材或未取得产物继续阻塞。
- 切页前保存可恢复的编辑状态。句柄、光标、DOM节点、搜索和上传窗口不能跨切页或重连沿用。

## 依赖说明与独立段就绪检查

先按[主技能开关范围](../SKILL.md#4-关联分镜顺序生成与站位复用)建表：开启时使用关联验收依赖；关闭时只保留必须读取前段新产物的依赖，不做成片或衔接检查。已有站位图可支持两个位置关系不变的分镜，且无新帧／音色依赖时，二者可分别预检提交；不要求先查看生成结果来证明无变化。表中记录“所需产物／已有素材／等待原因”，关闭后清除旧验收阻塞，保留真实未取得输入。

首次提交前，按已确认提示词为所选范围建立精简依赖表：分镜、直接前置、承接的具体人物／动作／持物／空间或音色产物、当前是否就绪及阻塞原因。向用户简报可独立推进的段号和需要等待的链；同一表未变不反复全文输出，只报告变化。不按编号相邻或同集标签一律串行，也不只因换场景／换地点就判独立；开启时同一连续场景及明确状态承接按关联要求；关闭时剧情承接本身不产生生成等待，具体产物缺失才等待。

没有独立段时在开始说明具体原因，例如“后段需引用前段新生成的末帧，该图尚未取得，所以等待”，不能只写“有关联”，也不为制造并行改写提示词、取消音色依赖或扩展到未选集数。原稿确无前段状态／产物依赖的分镜按其自身预检放行，独立调度无需另开开关。

每次准备进入等待时，共用本轮已取得的任务状态和依赖记录，检查已选范围内未提交的独立段及已解锁段。存在完整预检通过且预算、容量允许的分镜时进入提交单元；尚未预检齐备则完成一个可保存准备单元后回查。不能只盯当前链而遗漏就绪独立段；没有可提交者时记录依赖、素材、授权、预算或容量等实际原因。结果处理仍优先，全部在途回查、30–60秒轮转及动态提交门槛不变，不为这张就绪清单额外重复查询或全文重读。

## 等待提示词修订

- 修复段记录原分镜ID、问题证据、待修订版本及恢复条件；依赖它的后段保持待提交。自动修复及补片委派仅在穿帮校验开启时进入本节；按[修订分工](director-handoff.md#子智能体并行修订)核对当前队列：还有可独立推进的生成准备／提交、已完成视频处理或在途视频回查时，满足委派条件才交给一个临时子智能体实际调用原制作技能，主流程同时推进这些工作。只剩补片写稿，或子智能体工具不可用时，由主流程在剩余文稿轮次内直接调用同技能，不声称写稿与平台操作同时进行。已派发的在途文稿不因其他工作结束就改为同步重写；但关闭穿帮校验时按主技能停止委派，不继续自动制稿；后续新轮次重新判断。等用户资料或其他真实异步工具时仍可调度独立工作。
- 沿用本文件的结果优先及30–60秒回查边界；仅有在途委派时读取子智能体的必要短状态或领取结果，无视频在途时不空查平台，只剩主流程写稿时不虚设等待。修订稿完成后核对修订键、实际使用技能、原剧情／对白、整数生成时长、有效区间及余量和变更范围；能解除已记录后段阻塞的补片按[补片优先机会](#阻塞后段的补片优先机会)安排验稿／预检，其余进入正常队列。已有同版本验稿结果直接复用；不因等待过就直接提交，也不重复请求同一修订，待修订旧稿不抢先生成。
- 两种修订方式共用[文稿上限与无进展回收](director-handoff.md#文稿修订上限与无进展回收)中的首次／追加轮次，默认首次之外追加2轮；仅实际在途委派按默认5分钟无进展核实、最多自动恢复1次，不给主流程同步写稿虚设子智能体超时。读取状态不刷新进展时间，超时不重复派发，文稿耗尽不占用视频生成次数；只暂停该事项及依赖链，独立工作继续。
- 站位准备遵守[素材优先级和关联门槛](../SKILL.md#4-关联分镜顺序生成与站位复用)：平台已有合格图直接复用；没有再查本地，仍无图才从已通过当前所需检查的真实归档视频找适配帧。片尾不合适可用同段其他正常且在衔接点仍有效的画面，按[候选规则](position-frame.md#候选帧选择与跳过边界)确认后遮脸、核验、上传及引用；不为获得站位图单独重生成视频，不重复处理已有合格图。
- 区间修复（含4秒以内补入最短邻镜头）按[修复专用来源](interval-repair.md#站位图优先复用与修复专用来源)复用原图或正常画面，所需缺失音色按待修来源例外校验，不要求先修好原视频。普通后段可在[组合衔接验收通过](interval-repair.md#组合验收与后段放行)后提交，不必等物理拼接；开启校验时仅有站位图或修复片段生成成功仍不足；关闭按主技能只核真实输入，不要求组合验收。站位准备、片段合格、组合就绪和最终合成分别记录；无依赖分镜仍按自身预检推进。

## 回查边界去重

“完成一个准备／结果单元后返回当前集回查”就是下一轮的首次扫描，不是先扫一次再进入下一轮再扫一次。为每次扫描记录范围、全部目标ID／版本、结果时间和对应工作单元；同一边界的选择结果、待检队列整理及调度判断共用这一份结果。CLI可一次查询本任务多集已知在途ID，按集分组供本轮使用；未覆盖、分页、异常或身份不清才补查，不再对已覆盖ID额外逐个执行status、queue和get。

完成下一个工作单元、到达下一回查时间、新提交／取消／用户变更、恢复连接或出现状态异常时取得新状态；不能跨这些边界无限复用。返回仍覆盖当前集全部在途及待检，不延长既定30–60秒准备窗口。生成前的动态去重／容量检查只有在当前证据仍有效时才能共用同一次查询，不为减少轮询漏掉不明任务。

## 阻塞后段的补片优先机会

本节为穿帮校验开启后的修复调度，关闭不发起自动补片或按此保留验收等待；用户后来明确的单次修复按其范围处理。

- 已有完整、当前版本补片稿，且它用于解决已选后段依赖链中的已知阻塞时，在下一安全工作边界先完成应有的在途回查，再安排一次有界验稿／预检单元；不用等所有集的已完成视频处理完。依次核对原技能及稿件、引用、源版本、修复授权、次数、预算、容量和去重，全部通过且马上提交时才选时长；符合全部最终校验就提交一次。多个候选按当前集优先、其次就绪时间排序，不中断正在上传、下载或提交的操作。
- **与“刚解锁后段”的优先提交共用一次机会。** 有其他可处理成片时，相邻两个成片处理单元之间最多使用一次优先单元；同一机会同时出现补片与普通后段候选时，先处理上述补片。只做了验稿／准备、尚未提交也算使用，不能连续以优先名义处理多个补片。使用后先返回回查并处理一个可执行成片单元，再获得下一次机会；查询状态、换集或重复领取同一稿件不刷新机会。在已有调度记录中保存已用状态，恢复任务不清零。
- 优先单元沿用通常30秒、上限60秒的准备窗口；不能安全完成时保存断点返回，有真实缺项就记恢复条件，不占着机会等资料或反复预检不变阻塞。已有合格稿但暂时不能生成时不重新写稿。没有其他可处理成片时，按正常就绪队列继续准备／提交，不为重置机会空查或虚构成片处理。这里优先的是修复片段，相关后段仍须等实际修复结果及组合验收通过后才能放行。

## 每轮工作

1. **回查当前集全部目标。** 按上节合并相邻轮次边界，刚完成的返回扫描直接作为本轮扫描；否则先确认项目／集号并获取新状态。需要新状态时读取可见列表，已有本边界完整结果则直接使用，一次对照本任务所有在途任务的标识、版本和状态，并核对待检队列；列表已经覆盖的目标不再逐卡重复打开。未展示、身份／版本不清、提交状态不明或状态异常的目标才补查卡片／历史。不能只看返回目标、最早或最近一个任务。新出片进入待检，失败／取消／停止单列；生成中只记状态。
2. **选择可处理结果。** 先按[补片优先机会](#阻塞后段的补片优先机会)判断是否可插入一次补片单元，已使用则先处理成片；其余默认顺序：当前集已完成结果 → 其他已选集已完成结果 → 音色待办或准备／提交单元。同一集优先检查能解锁待生成后段的成片，其余按已选顺序。当前集没有结果时，核对其他已选集在途及待检，不让其成片因一直预填而积压。
3. **验收并考虑一次优先提交。** 先查[同版本下载与归档记录](video-archive.md)，已有文件继续处理，缺失才下载；开启时使用同一文件完成技术／成片检查；关闭时只确认下载已完成、文件可读及真实版本对应，不解码／测时长／测分辨率，随后本地转存到唯一正式名称，核对路径／哈希并收尾，不另下副本。原视频验收或区间修复的组合验收通过后更新选用依据；组合仍待物理拼接不阻塞。仅副本清理失败单列待办。成片处理单元完成后，先按上节检查阻塞后段的补片候选；没有可执行候选时，刚解锁后段的全部直接前置、站位、计划复用音色和自身准备均就绪，容量／预算允许，可用同一次机会完成完整预检并提交，再返回其他待检。补片与普通后段不各占一次机会，不借此长时间编辑、等待缺项或连续提交其他段；开启校验的普通后段须前置完成必需验收；关闭时实际素材齐备即可按正常队列提交，无需验收机会；补片按修复来源例外核验自身准入，不要求待修原片先通过修复后的组合验收。
4. **处理后续集一个单元后返回。** 一个结果完成必要处理（可含上述一次提交）后返回当前集整集回查；先记非紧急音色待办，不等全集音色整理完。准备单元以“一组完整引用／一次上传关联／一个分镜预填／一次预检提交”为边界，不每填一个字段就切集。准备窗口通常30秒、上限60秒，单元提前完成就返回；到上限在最近安全保存点停止扩展工作。上传、下载、提交等不可中断动作先核清结果再返回，记录超时原因，不切页制造状态不明。
5. **继续等待期间工作。** 所有可处理成片已处理后，优先完成下一就绪段真正需要的音色／站位和准备；其余音色待办与准备事项交替，每完成一个准备单元后若有可执行音色待办，下轮先处理一个，避免遗忘。独立就绪段可按容量提交，按当前开关仍有真实阻塞的后段只预填，关闭时不以同场景／未验收为阻塞。当前集全数完成后转下个未完成集；受阻集保留条件，可继续无依赖工作。

优先提交只改变顺序，不豁免准入。检查和前置等待统一按[主技能第4节](../SKILL.md#4-关联分镜顺序生成与站位复用)：开启时依赖原视频或组合验收；关闭时只等待真实所需素材，不以技术／视觉检查或修复待办阻塞已具备输入的后段。音色提取开启时样本准入仍执行，不能伪造或跳过尚未取得的样本。

## 回查与编辑分开

纯状态回查只确认项目、集号、任务标识／版本、状态及队列变化，不展开长正文、逐句引用或操作时长。页面信息不足才补查。重新进入编辑时核对目标、已保存正文版本与引用，从断点继续；预填后续段、准备后续集或等待依赖时，只记录目标秒数，不选择平台时长。独立段、刚解锁后段及修复段都只有在马上提交时，才按主技能第5节先完成其他前置项，再选择时长、失焦读回并完成全部最终校验；任何必需项未通过就不生成。读状态的缓存不能代替提交预检，选过的时长也不能替代提交许可。

仅穿帮校验开启或用户此后明确要求本次技术检查时运行本地技术脚本；支持异步返回时，运行期间可推进无依赖准备并定期回查；结果未领取、检查未完成时保持待检，不提前放行。超时按[本地检查续查规则](performance.md#超时与有限重试)处理：只有旧进程确认退出且仍有那一次自动重试时，才带原报告续查；状态不明或次数耗尽只挂起该检查及依赖链，不重复启动进程、不重下视频、不触发平台重生成。

## 容量、等待与停止

- 全部集共用实际平台容量、预算和在途预留，各原分镜／补片链的独立修复计数持续累计，满额时做准备／结果处理，不反复点生成。
- 无可执行工作才作有界等待，初始可30秒，状态持续未变可延至60秒；有新结果／用户输入即恢复处理，不密集刷新、不单次长时间阻塞。这里的秒数是初始调度值，按耗时记录调整，不宣称平台固定多久出片。
- 每轮只做一次完整当前集扫描，再选择工作；发现状态不明先查历史并保留预留，不重新提交探测。前置版本或用户条件变化时更新依赖，不沿用旧放行。
- 全局停止禁止任何集的新提交；局部停止遵从明确范围。失败、取消、停止不算等待，不自动恢复。轮转不改段号、成片顺序、目录或累计次数。

例：1-1在生成、独立1-3已完成，先验收1-3；若它解锁1-4且1-4已齐备，可优先提交一次1-4，然后恢复成片队列。当前集无结果才处理第2集一个结果或准备单元，再回查第1集全部在途。第2集计划复用1-1的声音，则仍等1-1验收和音色准入，不提前提交。
