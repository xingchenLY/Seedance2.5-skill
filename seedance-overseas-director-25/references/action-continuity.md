# 动作链记录与输出校验

生成或校验含动作的提示词时，按 [动作起始与跨镜承接](source-continuity.md#动作起始与跨镜承接) 和 [连续动作之间的承接](source-continuity.md#连续动作之间的承接) 使用。本文件定义内部记录；正式模板不增加字段，无工具时按同口径设计和复核，不输出 JSON。

完整动作链指因果与必要阶段完整，不要求把无信息中段全程拍完。用户已授权在节奏受拖累时按 [运动过程省略](motion-ellipsis.md) 保留可见发起与结果、明确剪辑省略；下列逐阶段连续承接适用于未采用有效省略的区间，关键接触、归属与证据仍须保留。

## 从原文建立动作链

最终交付的记录顶层填写 `action_tracks`。先从本次原文动作及已设计的自然表演确认需要承接的变化，再安排镜头；没有相关变化才填写 `[]`。渲染器不自动补空列表，不能将“没有重要动作特写”当成“没有动作”。起身、转向、行走、抓握、放手、持物改变和需要跨镜保持的手势／姿态均按实际需要覆盖，不给每次眨眼、呼吸或微表情建状态表。

每条链只追踪当前容易跳变的状态，不为每镜复制全身姿态和全部人物。连续的同一行为，以及前一行为结果决定后一行为起点的相邻动作，使用同一条链；例如放杯后转身，必须把杯子落稳、松手收回与身体转向连接起来。同一状态在同集、同一时间层只由一条链维护，不为下一镜或下一个动词另建一条链以重置状态；相互独立的角色动作可分别记录，涉及双方的交接／抓握宜合为一条共同链。

`action_tracks` 每项包含：

| 字段 | 填写要求 |
| --- | --- |
| `id`、`episode` | 本任务唯一动作链 ID、所属已选集 ID；不进入正式提示词 |
| `time_layer` | 同一连续剧情时点的稳定标识，例如 `present`、`memory-three-years-ago`；现实与过去分开，返回现实接回原链。不能因切镜、分段或同一动作途中的换地点而重新命名 |
| `basis` | 具体原文位置／行为，或当前对白允许的自然表演依据；区分原文明示与合理导演补全，不虚称原文有新增动作 |
| `end_state` | 按本次原文范围确定的该链必要结束状态；片段只到伸手途中就停在那里，不替原文完成尚未发生的结果。不能从漏动作的成稿倒推结束状态 |
| `beats` | 按成片顺序列本链有动作或必要状态承接的实际镜头；不要求所有镜头都填，不给切走期间不可见的人物补画外行为 |

每个 `beat` 填：

- `segment_id`、`shot_start`：精确指向一个实际镜头的段 ID 与起始秒数。不是父分镜区间，也不是动作在镜内开始的微时点；镜内触发写入下列文字。同链在同一实际镜头内的连续步骤合并为一个 beat，不逐步骤拆镜或重复时间。
- `before`、`after`：同一组状态键到简短状态值的映射，例如 `Mara.right_hand`、`key.owner`、`Mara.posture`；保留需要核对的手别、接触对象、运动阶段、位置／朝向及持物归属。全链键集合固定，无变化的值原样复用，不用同义改写制造差异；这份状态信息只供内部比较，不自动逐项输出。
- `action_text`：一段可直接写入本镜“画面内容”的自然动作句，点名人物，落实**具体承接状态 → 必要运动或解除接触 → 当前动作／下一动作 → 切出阶段或结果**。按该镜实际阶段取用，不机械套四步。禁止只写“动作连贯”“承接上镜”“完成动作”；未采用有效剪辑省略时，不能只列两个姿态而没有让状态改变的动作。需有发起的回落、收手和放手不能省略；已开始的动作从原进度继续，不重演起始。

状态值一致只证明记录一致，不能证明动作文字与状态吻合。`action_text` 是相关动作的唯一正文来源；`shot.visual_text` 保留空间语境、口型及非重复表情，不再另写同一动作的不同版本。前镜切出时的未完成阶段和后镜切入时的承接必须在各自文字中清楚；过程完全位于一个镜头内时，直接连贯写完，不强加切镜、特写、准备或停顿。对白按 [情绪优先取景](shot-selection.md#对白情绪优先与动作取景) 由连续镜头共同交代必要动作，状态链完整不要求同镜展示全身；画外状态不写成可见动作，必看的接触和结果不能借切走跳过。

## 双手分工与下一动作的条件

涉及同时持物、抓握或支撑时，用现有 `before/after` 记录相关左右手／手臂占用、接触对象与归属；不为每根手指建表。交接先接稳再松开，伸手高度和距离服从当下姿态与可达范围。下一动作若实际受到抓握、支撑或物件阻挡，须先在同一动作链落实必要的松开／撤回；仅在妨碍确实存在时处理，不把“蹲下前一律松手”当通则，也不为腾手新增放物或换手。

这些条件按 [双手分工案例](continuity-repair-cases.md#双手分工接触解除与可达范围) 落进实际可见过程，可与原台词共用时间，不逐步骤增加镜头或停顿。切回时接当前进度；段首只记录初态，不能把之后的放手状态反写成开场状态。

## 记录示例

下面只示范“伸出钥匙 → 对方接稳 → 原持有人松开”的内部记录；镜头时间、原文身份与身体条件以本次剧情为准。状态键是内部标识，正式文字仍使用原人物名。

```json
{
  "action_tracks": [{
    "id": "key-handoff",
    "episode": "current",
    "time_layer": "present",
    "basis": "原文 Mara 把钥匙交给 Elias；接稳与松手须可见。",
    "end_state": {"key.owner": "Elias左手", "Mara.right_hand": "交接处已松开"},
    "beats": [{
      "segment_id": "S1", "shot_start": 0,
      "before": {"key.owner": "Mara右手", "Mara.right_hand": "腹前握钥匙"},
      "after": {"key.owner": "Mara右手", "Mara.right_hand": "向桌对面伸出途中"},
      "action_text": "Mara 右手从腹前握钥匙的状态向桌对面伸出，切出时仍在伸出途中，钥匙尚未离手。"
    }, {
      "segment_id": "S1", "shot_start": 1,
      "before": {"key.owner": "Mara右手", "Mara.right_hand": "向桌对面伸出途中"},
      "after": {"key.owner": "Elias左手", "Mara.right_hand": "交接处已松开"},
      "action_text": "承接 Mara 右手已伸出的进度，钥匙继续移向 Elias；Elias 左手从桌沿抬起接稳，Mara 随即松开，钥匙由 Elias 左手握持。"
    }]
  }]
}
```

## 切走、跳时与返回

同一链下一 beat 的 `before` 默认必须等于前一 beat 的 `after`，包括内部切镜、切听者后切回、跨段和成片剪辑顺序。没有新的可见动作时继承已知状态；前镜已经发起的动作可以在有依据的剧情经过时间内推进，不把一切画外变化都禁止。

确有状态差异时，后一个 beat 可填写 `break_before`，仅限：

- `kind: "offscreen_progress"`：前镜已发起的非关键过程，在切走后的实际剧情时间内自然推进；必须确有中间镜头和成片经过时间，紧贴的切点没有时间间隔不能使用。不得借此隐藏必须看清的关键接触、交接、放手、证据或结果，也不能让原本静止的人无依据开始新行为。回忆画面经过几秒不自动等于现实也经过几秒，须核实叙事时间。
- `kind: "motion_ellipsis"`：按 [人物运动过程省略](motion-ellipsis.md) 剪掉拖慢节奏的非关键中段；前镜发起与后镜结果必须可见，逐项声明省略内容、变化的运动状态键及两端证据。此为明确剪辑跳时，可在相邻实际切点发生，不能冒充同镜连续运动；不跳过关键接触、归属、证据或原声。
- `kind: "source_time_jump"`：原文明确的时间省略、跳时，或原文概括性／重复过程、用户对具体片段的省略要求支持的 [时间跳切](cut-techniques.md#跳跃组接的两种用途)，允许在新的时点承接状态；换机位、反打、普通停顿和提示词段号改变不构成依据。

`jump_cut_before` 只说明镜头切法，不自动授权动作状态变化；有实际状态差异时，本节记录仍独立必查。

该对象还必填 `basis`（具体原文／已建立动作及经过时间依据）与 `resume_text`（切回后实际可见的当前状态及时间关系说明）。渲染器先写适用的运动省略提示，再写恢复说明和当前动作句；只描述此时可见状态，不把切走期间的动作伪装成被拍到。首个 beat、状态没有变化的衔接不得保留该例外。例外不放宽原文覆盖、必要动作可见性和关键过程；其语义须复核，非空理由不证明合理。

## 检查与修复

`scripts/action_continuity.py` 按实际 `playback` 顺序核对镜头引用、状态键、相邻状态、必要结束状态及例外。删除最后完成步骤、动作从初始状态重开、无记录地换手／变持物等，在状态记录体现后会报错。基础模式检查已提供的动作链；最终模式和渲染流程要求显式提供适用性记录，不能改用基础模式绕过。

渲染器将每个 `action_text` 和必要的 `resume_text` 写入对应实际镜头的“画面内容”；不会自行猜动作、补剧情、改时间或增加声音。最终检查按该镜区间绑定这段文字，移到段首、另一镜、“运镜”字段或删掉后重新计算摘要都不能通过。手工排版并使用脚本时，先调用 `action_context(plan, errors, required=True)`，再用 `action_prose(segment, shot, context)` 取得对应文字；无工具时写等价的具体承接并人工核对。

返回前内容复核必须同时检查：原文／已设计动作是否全覆盖；动作句与 before／after 是否相符；不同动作之间必要的松开、收回、转向、重心或接触转换是否真实可见；切走后推进有无依据；时间与取景是否足够，且不为承接添加冗余步骤。尤其排除 `visual_text` 与动作句互相矛盾、用空动作表漏项、改键名或时间层逃避比较、把动作结果当成过程。发现缺口先补进原镜或调整切点／取景，在已有时间内利落完成；确需更多时间才据实重估，不硬塞或机械加时。

将实际动作链、相邻动作过渡、例外及修复情况记入已有 `delivery_review.visual_continuity`，不用一句“动作连贯”代替。脚本不理解自然语言动作的物理含义，也不验证视频，记录完整和文本绑定通过仍须上述复核。
