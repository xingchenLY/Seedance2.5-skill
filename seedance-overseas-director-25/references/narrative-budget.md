# 推文发声预算锁定

用于推文／3D漫推文，优先于原来的声画合计后向下取整。真人剧／3D漫真人剧不采用本项。先计算本段实际总发声，再锁定整数段长，最后生成提示词；镜头不能反过来决定或扩大这个预算。

## 先计数并锁定

1. 固定用户授权范围、实际目标语种及本段原文，完成必要名称替换／忠实译文和既定授权的旁白删减。总发声包含保留的叙事旁白、人物对白及内心声，不只数人物对白；标签、画面说明和无人朗读的文字不计。同一句跨镜只计一次，数字按既定真实读法展开。
2. 按原语种计算：中文实际汉字数÷7；英语、西班牙语和葡萄牙语统一按对应原语种实际发声词数÷3.4，不翻译成英文再计词。三种外语沿用相同空格分词口径，标点不单独计词，数字先按实际读法展开；重音符不改变计词。混语各部分分算，只对本段总和取整，不逐句取整。英／西／葡语3.4词／秒是本项统一预算基准，不为迁就已设计画面改慢；已有实际测量音频时，在锁定前用真实时长替代对应估值并保留测量依据。中文必要停顿沿用 `chinese_timing`，不能与实测重复计算。
3. 原文确需的独立声音停顿在生成前登记 `segment.narrative_pauses`，每项 `{start,end,basis}` 使用段内时点；只计没有包含在声音估值／音频中的自然气口或明确停声，不把动作、表情、摄影、读屏、场景转换或任意缓冲伪装成声音停顿。内部停顿已含于中文估时或实测声音时不另填；真实拆句仍保留原声音承接及停顿依据。两种语言声音的重叠须有原文／用户依据，不能为省时自行叠声；本项总发声预算不因切镜或叠声减少计数。
4. `T锁定 = ceil(T全部实际发声 + T未重复计算的必要声音停顿)`。例如中文75字为75÷7≈10.714秒，锁定11秒；英／西／葡语34词均为10秒，锁定10秒；96词均约28.235秒，锁定29秒。不是默认30秒，不另加动作／反应／镜头数量秒数。向上取整的不足1秒余量仅是网格余量，不要求追加定格或固定片尾等待。
5. 先检查默认30秒、96英文词及完整发声可行性；既有用户明确要求的 `limits`／`limits_basis` 仍按其范围生效，不为迁就画面自行放宽。超限在自然语义／剧情边界重新分组并重新计算，不截断原句、不改语速、不给旧段额外加秒。原文必须保留的停顿、不可压缩过程或短镜下限导致不可行时，在生成提示词前识别。纯无声段不能用零词生成零秒提示词，先检查能否与相邻原声合理分组；仍无发声依据则报告需明确独立画面预算，不删除原动作或自行编台词。

## 在锁定时间内制作

先完成整段声音时序，再安排实际镜头。段首预估时长、全部实际镜头时长之和及末镜结束点必须严格等于 `T锁定`；正式分镜与内部镜头不重复相加。动作、反应、证据阅读、摄影和转场均在该窗口内，能同期就共用时间，但不提前知情、弱化关键表演、漏掉接触或必要证据。

先比较合法切点、取景和兼容的同期安排；不能把自然1秒的动作拖到旁白末尾，也不能为赶预算把复杂过程加速。若内容确实放不下，不能把锁定11秒改成13秒后继续生成；只能回到生成前调整原文自然分组，保留原顺序、原词和旧预算记录，对新分组重新锁定并重做受影响镜头；无法解决则报告具体冲突，不能通过反复重组掩盖不可能条件。更改原声、读法、语种、停顿或实测依据同样使旧预算失效。

近景／特写、长镜、静态停留和推文最短镜头规则仍有效。完整一集50秒约定不允许人为扩大各段预算，不足按既有冲突规则说明。分批处理2–3段和上下文软预算不改变本项计时。

## 工具与记录

有工具时，复用本次设计记录的 `mode`、`sources` 与 `segments[].speech`，先建立尚无实际镜头的声音输入。来源含既有语种、发声原文等字段；声音事件保留准确 `source_id/text` 和必要读法／混语记录。英／西／葡语及混语中这三种片段均按统一词速计算，普通 `estimated_seconds` 不覆盖公式。计时锁定程序不需要摄影描述，不会生成动作、声音或素材。

```text
python scripts/narrative_budget.py speech-input.json --output authored.json
```

输出同一设计稿及 `segment.narrative_budget = {version, speech_sha256, raw_seconds, duration}`，同时设置 `pre_round_duration` 为未取整的发声总时间、`duration` 为向上取整值；之后在该稿补齐声音区间、镜头等内容，不再另写一份完整方案。已存在锁定或实际镜头的输入不直接重锁；确需重组／改词时从新声音输入重算，保留原记录用于核对，不用事后刷新摘要迁就成稿。

公开 `render_prompt.py` 与 `validate_plan.py`（含 `--timing-only`、`--final-prompt`）要求两种推文具有预算记录，并复核发声绑定、公式、整数值与实际结束点。渲染器不能从镜尾反向覆盖预算或自动挪动声画区间；已有旧稿缺少记录时，回到原声预计算并重新核对镜头，不直接填“通过”。直接调用内部函数的无锁旧测试兼容不代表制作入口放宽。`--timing-only` 可用于预先核对已锁声音及已有不可压缩过程，仍不能代替成稿审阅。

不能从普通英文估值、外语估值或“有测量依据”字段推导音频已验证。程序检查数字与内容绑定，无法证明先算后写的真实执行顺序或自然表演；独立成稿审阅需核对实际原声、生成前记录与画面可行性。没有工具时按同一公式在已有任务状态记录总发声量、停顿依据和锁定秒数并人工比对，不声称自动校验通过。最终正式提示词保留原模板，不额外输出内部预算表或摘要字段。
