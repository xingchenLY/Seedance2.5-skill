# 独立成稿审阅与优化落实

四模式最终交付共用，接在 [复核处理](review-closure.md) 与实际渲染之后、最终交付之前。目的在于补足首稿生成者的判断盲区，不以再填一份通过说明代替阅读。自动检查覆盖有限；当前候选全部关闭，也不能推导全部内容正确。

按 [上下文与输出预算](workflow.md#上下文与输出预算) 采用路径与必要上下文委托、分块完整审阅、只返回差异。完整审阅是覆盖要求，不要求一次性把所有文件塞入上下文；分块不得遗漏原文、交付段、跨段边界及全局约束，既有当前版本绑定与验收字段仍完整填写。不为节省输出删除实际问题或省略必要来源证据。

## 实际执行顺序

1. **形成可审阅的真实成稿。** 保留本次原始正文、已确认要求、模式、前后状态与实际采用素材依据；先处理已知硬错误。审阅的是准备返回的完整文本，不仅是 JSON、摘要或自己列出的疑点。
2. **另行审稿。** 有可用独立审阅代理工具时，实际委托一个独立代理，提供上述来源、当前成稿和本技能适用规则，要求覆盖全部交付段并报告具体错误和有效优化。首次审阅不灌输生成者原有保留理由，让审阅者先自行判断；随后核对全部当前 `REVIEW` 项及其处理依据。不要只问“能否通过”，不设必须找出几个问题的配额。没有可用独立代理能力时，在生成和修订结束后另起一遍从原文到最终文本的审阅，记录 `separate_pass` 及实际限制；同一执行者自称另一角色不等于独立代理。
3. **区分有效改进与任意偏好。** 错误须指向原文、既有要求或实际矛盾；优化须指向可观察收益，如去掉无信息等待、让关键情绪更可见、补清接收反应或减轻重复说明，同时不损失原信息。不是每种另一拍法都优于现稿。与来源／用户锁定要求冲突的提议应撤回或改为兼容方案，说明具体冲突；不能为了凑优化数量强行改动。
4. **确认成立就修改。** 本用户要求优化建议也落实，所有已确认错误和有效优化都修入实际设计及成稿，不停在建议清单，也不能仅填 `retain`、理由或“建议以后调整”。保留发现的具体原文摘录、修改点及修改后证据；不能在记录中删除尚未解决的已确认问题来宣告零问题。
5. **修后验收。** 同步时间、原声、切点、动作链、人物／道具、后续状态及模式依赖，重新渲染。审阅者检查改后实际文本，逐项验收已确认问题和受影响范围，再整体核对来源覆盖、顺序、声画时间、相邻切点及模式。若出现新问题继续修；无新改动、失败或未解决事项时，不为凑轮数重复重写。已有检查复用条件沿用 [高效执行](workflow.md#高效执行与回修)。
6. **绑定当前版本并执行最终校验。** 实际审阅完成后才记录本次版本，运行 `validate_plan.py --final-prompt`；交付同一份文本。程序失败必须修复，不能以审阅者认可覆盖硬错误。资料缺失或条件不可兼容时报告具体缺口，先完成能独立解决的部分，不虚构证据或无限自检。

独立审阅逐段从原文反查人物、道具、关键事实与声音，再沿实际镜头顺序检查情绪／身体／音色、旁白口型、画面信息密度、景别／机位／轴线、跨段重复、必要特写、同期占时与冗余。关键情绪另按 [取景复核](shot-selection.md#关键情绪取景复核) 从原文回查，按模式检查两种剧是否被普通景别偏好压低情绪、两种推文是否忽视中近景偏好或漏掉必要细节；两秒限制不取消必要取景；保留现构图须有实际观看重点与落点，不只凭表情文字或通过记录。动作省略按 [运动过程省略](motion-ellipsis.md) 判断。语言、品牌／地名、面部变化及模式差异仍按各自规则检查；没有自动候选也要查。不能把正文出现的“PASS”等剧情文字误判为审阅结论。

独立审阅代理只执行受托审阅并返回具体发现／验收结果，不再递归委托另一审阅代理，也不把审阅报告当作正式提示词另走一轮交付流程。主执行者负责修订和最终交付，修改后可请同一审阅者复核；无需每次换人重建完整上下文。

`shoulder_axis` 候选不能用 `retain` 放行已知几何不一致；标准面对面正反打的同肩／同前景错误应修实际机位和画面。真实特殊几何造成误报时才可 `false_positive`，逐侧核对人物朝向、轴线、真实肩侧及画面左右，独立审阅者须核实，不只看填了理由。程序不能证明任意自然语言几何或判断正确。

## 内部记录

最终 `delivery_review.editorial_review` 必填，不进入正式提示词：

```json
{
  "method": "independent_agent",
  "reviewer_ref": "本次实际审阅代理或审阅运行的可追溯标识",
  "plan_sha256": "当前设计摘要",
  "prompt_sha256": "当前实际定稿摘要",
  "reviewed_segments": ["S1"],
  "finding_keys": ["本次报告实际存在的key"],
  "scan_basis": "本次实际核对的原文范围、非自动提示事项及修改后整体检查情况",
  "issues": [{
    "id": "E1",
    "kind": "improvement",
    "status": "applied",
    "rule_or_goal": "原文只有从桌边走到门口，中间没有新事件；完整路程挤占下一句反击的节奏",
    "before": "甲从桌边起步，镜头连续跟随走完中间走廊后停在门口。",
    "change": "保留桌边起步与门口停稳，用明确剪辑省略中段步行，原声与持物保持",
    "after": [{"segment_id": "S1", "shot_start": 2, "text": "摘录修改后本镜实际画面中的省略提示与结果"}],
    "verification": "对照原文确认途中无新信息，复查两端方向、持物、声音覆盖及后镜时间"
  }]
}
```

示例不是可直接复制的审阅记录。`method` 只有 `independent_agent` 或 `separate_pass`；后者必填 `fallback_basis` 说明独立审阅能力实际不可用的原因。不能因省时间自行跳过已有独立能力。`reviewer_ref` 必须对应实际执行记录，不能假造；程序仅检查字段，不认证审阅者身份。

- `reviewed_segments` 覆盖全部交付段；`finding_keys` 覆盖当前自动候选，确无候选才 `[]`。`scan_basis` 说明本次整稿实审，不用笼统“全部通过”。
- `issues` 保留本轮已确认的错误与优化，`kind` 分别为 `error`、`improvement`，交付时只允许已实际完成的 `status: applied`。确实完整审阅且未发现成立的问题才允许 `[]`，不是看到无自动报错就填空。
- `before` 摘录真实修改前文本；`after` 引用修改后具体字段，不能用未变化的相同摘录证明已经优化。视觉／运镜用 `segment_id + shot_start + text`，多镜修复逐侧绑定。
- 修改段首人物、位置、道具或声音行时，允许 `after: [{"segment_id":"S1","scope":"segment","text":"出镜人物：甲、乙、丙"}]`；文本须包含实际字段／声音标签及其内容，并存在于指定段。不要为了提供证据而给全段画外人物强加镜头。声音行引用在内部审阅记录中，不重复写入正式画面。
- 两个摘要在修后实审完成后更新；改时间、源文、设计或文本都须重新核对相应范围。不能只刷新摘要保留旧“已审”状态。

程序拒绝缺失记录、漏段／漏候选、过期版本、未落实的问题和错位置证据；它不证明审阅真实发生、原文完整、改后含义正确或视频生成一定符合。禁止用维护测试辅助函数自动填生产复核记录。最终只报告实际执行的检查和范围，没有样片不声称已经验收口型、节奏或画面。
