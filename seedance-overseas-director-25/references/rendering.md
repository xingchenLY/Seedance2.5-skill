# 自动填写模板

两种推文先按连续剧情合理分组，再按 [发声预算锁定](narrative-budget.md) 计算各组时长，通过4–30秒检查后生成 `narrative_budget`，最后补齐镜头并调用渲染器；禁止从已写镜尾反算预算。英／西／葡语统一按3.4词／秒，中文按7字／秒，整段向上取整。

最终校验额外要求 [独立成稿审阅记录](editorial-review.md)；渲染器不会替人审稿或自动填通过记录。需要删减拖慢节奏的非关键运动过程时，按 [运动省略记录](motion-ellipsis.md#内部动作链记录) 使用 `motion_ellipsis`，不删动作链、原声或关键接触来通过检查。

先完成主技能的必选模式，记录顶层 `mode`，值严格为3D漫推文／3D漫真人剧／真人剧／推文；不由脚本猜测。以下流程四模式共用，声音类别、旁白清单、3D规格与时长差异先读 [模式记录](mode-records.md)。无mode的历史测试数据仅供内部回归函数，命令行制作入口拒绝无mode。

有本地 Python／文件工具时使用 `scripts/render_prompt.py`。填写所有将进入提示词的文字前，按 [具体视听表达](concrete-language.md) 完成抽象词清理；渲染器不做会误改原文／素材名的自动词表替换。它只排版已经完成的导演设计，使用标准库，不联网、不生成视频、不改写原句、不替代内容复核。无工具时直接依原模板填写并人工核验。

中文声音按 [每秒7字估时](chinese-timing.md) 单独计算；数字按实际中文读法展开，混语各部分分算。渲染器仅在中文估值缺失时补入计算值，已有错误估值或声音区间会报错，不自动挪动动作与镜头；非中文独立发声的估时保持原规则。

## 一份设计记录

先从源文固定 `sources`，镜头设计用同一份 `authored.json`。按 [高效执行顺序](workflow.md#高效执行与回修) 先在此记录中排声音与镜头骨架，再补齐具体设计；不先手写整份正式提示词后重新转录成JSON，也不另维护一份手写成稿。记录包含 `episodes`、`sources`、`segments` 和 `action_tracks`；普通记录字段按下表与示例，特殊情况按需查 [计词、数字、混合语言与回忆记录](validation.md)。基础校验示例没有完整镜头元数据，不能直接当成可交付记录。

`segments` 每项必填唯一 `id`、所属 `episode` ID、从 0 连续覆盖本段的 `shots`、按起始时间排列的 `speech`（无声时为 `[]`）及 `presentation`。`frame_id` 使用原模板的“分镜1”等标题，连续多个实际镜头可共用同一标题；非连续重复标题不允许。整段总长按 [整数时长](timing.md#整段整数时长) 去掉估值小数并同步全部区间，末镜必须结束于整数；可用 `pre_round_duration` 保留取整前估值，不由渲染器裁断内容。实际拆出的无关联前段填写 `unrelated_prefix: true`；多人例外、数字展开、混合语言和独立回忆沿用既有记录，不因自动排版省略其依据。

| 位置 | 填写内容 |
| --- | --- |
| `content_language` | 顶层共用发声与画面文字目标，按 [语种选择](source-continuity.md#剧本语种与台词画面文字) 写 `zh`、`en`、`pt`、`es` 或用户明确的其他目标语种代码，可带地区如 `pt-BR`；先确定再翻译，纯无声段也填写。渲染器生成两项限制中的实际语种，不自动翻译文字 |
| `episodes` | 原内部 ID、`complete`；已知集号时单集和多集都填原标题 `title: "第 12 集"` 或 `"第十二集"`，渲染段号为12-1、12-2。每集默认从1开始；同集续作或重做指定段时，可用正整数 `segment_start` 填本批已确定的起始段序号。无原集号不虚构、不从ID推断，暂用普通段号；两个剧模式完整集不设最低时长；两个推文模式默认至少50秒 |
| `action_tracks` | 按 [动作链记录与输出校验](action-continuity.md) 填原文／已设计动作的依据、时间层、必要结束状态及逐镜前后状态和具体动作句；无相关变化才显式填 `[]`，不能由渲染器自动猜空表 |
| `sources` | 从源文提取的唯一 `id`、所属 `episode`、`speaker`、`kind`（剧模式`dialogue`／`VO`／`OS`，推文模式`dialogue`／`narration`／`inner`）、最终 `language`、原句或固定译文 `text`；保持原叙事顺序 |
| `segment.presentation` | 原模板中的 `整体风格`、`对话氛围`、`场景`、`环境光影`、`人物位置关系`；相关道具用下行 `segment.props` 声明并派生 `特殊道具`，旧稿已有非空字段可沿用。规格、声音限制、画面限制有对应模式及 `content_language` 的默认值；通常省略这三项让渲染器填写，确需自定义时保留自动语种声明原句，不能覆盖成另一目标语种，中文目标不能夹带禁止中文 |
| `shots` | 每个实际镜头的 `start/end`、`frame_id`、`start_scale/end_scale`、`start_camera/end_camera`、`visible_characters`、`relation`；四种有条件切换、同景别或同集跨段切点填两侧 `view`，镜内构图改变再填 `end_view`。同场同主体的跨段后镜另填 `cut_change_before`，证据取自两侧实际首尾构图，见 [真实机位校验](camera-continuity.md)。含义见 [交付元数据](delivery-validation.md#二-生成并同步记录) |
| `segment.props` | 每段的相关道具字符串列表，如 `["伊森左手手机", "伊森右手花束"]`；新稿明确填写，经核对无相关物品用 `[]`，不把缺项默认成空列表。渲染器生成原 `特殊道具` 字段；依据、范围与旧稿兼容见 [道具清单与成稿绑定](#道具清单与成稿绑定) |
| `shot.static_spans` | 每镜必填，按 [实际镜头与静态展示](timing.md#实际镜头与静态展示) 标出纯停留的起止与可见状态；确无静态展示才填 `[]`。渲染器将时点与状态写入本镜画面内容，不自动猜测或补空列表 |
| `shot.camera_text` | 导演已确定的取景边界、清晰重点与持机质感；角度复用真实高度和朝向，有运动时补触发、路径、速度或相对距离及结束构图，采用手持时写具体浮动与实际稳定性变化，不让笼统“固定／落稳”抵消；按 [拍摄技巧](shooting-techniques.md) 保持指令相容；有 `view/end_view` 时摄影位置、主拍和关系前景自动写入原“运镜”，不重复或另写矛盾的构图。区间及景别也由记录自动添加，不再手写。主体朝向／运动方向与摄影机朝向／运动方向分别写清；同段回忆进入在实际入口写可执行视觉转场效果，复用原区间而不加时。内部硬切仍在此描述实际切法；时间跳切按 [局部例外](cut-techniques.md#时间跳切的内部记录) 填 `jump_cut_before`，渲染器将其省略说明与切入时点接入本镜，不重复填写；不能靠字段编号暗示切镜 |
| `shot.visual_text` | 对应实际镜头能看见的情境、表情与动作方向；屏幕背向镜头时不写屏幕内部。现场嘴部可见且发声时明确开口／继续讲话与同步口型；听者及 VO／OS 不代开口；已在 `action_tracks.beats.action_text` 写出的动作过程由渲染器接入，不在此复制或另写矛盾版本。普通可见行为同样按需记录必要状态变化。同场位置句从 `relation.placements` 自动接入，不在此重复整组描述，但动作须与其一致。过肩镜头在本字段、位置句及动作文字中均按 [过肩画面描述](shot-selection.md#过肩镜头的画面描述) 非必要不写侧脸，先纠正设计再渲染，不用全局删词误伤台词或其他机位。时间微节点可写“第 X 秒”或对应词句；不要重复写“X–Y 秒”完整区间 |
| 同场正反打引用 | 不新增一套构图数据：按 [分视角引用](asset-library.md#同一场景的正反打与多角度参考) 在已有素材记录对应实际图名、同一空间与所用段镜；`segment.presentation.场景` 列实际引用图并注明同一空间，`人物位置关系` 先共同站位再按图与区间分别描述。各实际镜头在 `camera_text` 写所用场景图原名，`view.space` 保持共同空间；各自 `relation.placements` 独立写画面位置，由渲染器放入本镜画面，`visual_text` 补本视角动作和可见信息，不另重复整组自动位置句。内部切镜也逐个实际shot对应，不能只在段首列图后混写 |
| `shot.relation` | `mode`、`characters`、按原文先定的 `scene_characters`；同场另填 `placements`，仅一人可见再填 `single_reason`，详见 [逐镜关系记录](delivery-validation.md#逐镜关系记录)。`evidence` 省略时，同场取自动生成的位置句，其他模式取 `visual_text` 中明确点名的关系说明；不必在动作文字里重复同场位置。自行提供的证据也须来自对应镜头，不从段首或其他镜头借用 |
| `speech` | `source_id`、`speaker`、`kind`、`start/end`、`estimated_seconds`、实际发声 `text`；`performance` 按 [人物声音表演](spoken-emotion-camera.md#人物声音的表演与音色) 写主要声态、起句与关键原词上的演法及收尾，区分参考音色与动态语气，独立叙事旁白仍中性。不在 `performance` 重复区间或加台词引号；同句优先一条跨镜记录，确需拆句且有真实间隔时在后条填 `pause_before`，见 [拆句停顿](delivery-validation.md#拆句停顿与声音承接校验) |
| `segment.appearance_reviews` | 仅实际面部／眼部颜色描述命中有限检测且确有依据需要保留时，按 [允许项记录](appearance-validation.md#按范围绑定允许项) 填范围、原句证据、对象、类别及具体来源；眼眶微红不能扩为明显通红，原文明示面部视效可按范围保留。渲染后也扫描实际字段，记录不足时退回修订，不自动补通过记录，正式模板不增加字段 |
| `segment.sound_events` | 有音效才按 [声效事件](sound-timing.md) 填声源、触发／持续区间及依据，由渲染器按各实际镜头交集写入原音效字段；没有时省略或填 `[]` |
| `segment.frame_notes` | 仅填写各 `frame_id` 的可选 `transition`。旧 `sound_effects` 须按剧情迁移为事件，不再接收自由音效清单；最后分镜省略外出转场，内部切镜填在镜头描述 |
| `shot.closeup_spans` | 仅实际镜头超过2秒且含特写时（含镜内进入／退出），按 [特写区间记录](closeup-duration.md#结构记录) 填实际区间、任务、结束证据与适用的必要延长依据；整个实际镜头≤2秒无需额外记录。渲染器只补取景区间，结束证据复用已有画面／动作描述，内部理由不输出 |
| `shot.short_shot` | 仅不足1秒时按 [短镜例外](timing.md#短于1秒的特殊例外) 填 `reason/basis/readability`；不新增正式字段，不放宽声音与切点 |
| `segment.timing_feasibility` | 按 [可行性预检](timing.md#排镜前的可行性检查) 记录最低所需时间和依据；有实测声音另填 `speech.measured_seconds/measurement_basis`，不压短音频 |

先按 [整段估时口径](timing.md#默认计算口径) 对本段总词数做初筛并统一调整时间线，再填写各分镜／实际镜头的区间，不能逐镜加缓冲。渲染器从这些区间自动派生本段时长、英文词数、场景在场人物合集、分镜区间和所有声音标签，不在镜头或整段末尾再次加时；将动作链中已设计的具体承接句写入对应“画面内容”，再根据声音覆盖与本镜主体补入原声承接句，不会复制引号内台词或改变声音类别；作者不必再独立手算／复制这些值。`duration`、`english_words` 按同份镜头／声音重算，`cast` 按本段所有实际场景的 `scene_characters` 合集派生，包含全段画外、无独立镜头及无戏份者；段首“人物位置关系”必须保留这些人的位置，缺少全段画外人员的站位会报错；已有 `cast` 若有姓名将被移除，按 [出镜人物检查](output-template.md#出镜人物与静默角色) 报错并核对，不能直接覆盖；**不会调整实际声音、镜头区间或原文来过检**。派生后的记录仍需全部结构检查。旧记录缺少在场表或同场位置条目时，按原文和本镜实际构图补齐，不能由可见名单自动猜在场者，或改用基础模式绕过。

单个实际镜头可写成：

```json
{
  "start": 0, "end": 2, "frame_id": "分镜1",
  "static_spans": [],
  "start_scale": "中近景", "end_scale": "中近景",
  "start_camera": "桌边A", "end_camera": "桌边A",
  "visible_characters": ["林晚", "沈砚"],
  "relation": {
    "mode": "same_scene", "characters": ["林晚", "沈砚"],
    "scene_characters": ["林晚", "沈砚"],
    "placements": [
      {"character": "林晚", "visibility": "visible", "placement": "位于右后方桌北端，面向沈砚"},
      {"character": "沈砚", "visibility": "visible", "placement": "以肩背留在左前景桌南端，与林晚隔桌相对"}
    ]
  },
  "view": {"space": "大厅", "position": "长桌南端东侧沈砚右肩后", "direction": "北端的林晚", "height": "林晚眼高", "subject": "林晚", "foreground": ["沈砚"], "background": "林晚身后的北窗"},
  "camera_text": "过肩固定，保持稳定。",
  "visual_text": "林晚直视沈砚开口，口型与本人原词同步，延续上一句音量和咬字力度；沈砚保持原姿态听着。"

```

姓名标签、现场／VO／OS 类别、词数、台词覆盖均来自同份原声音记录。跨实际镜头的声音只渲染一次；同一人多句可逐行输出，换人、混类及多人例外仍按现有规则。多个镜头的区间同步写进运镜与画面内容，关系证据与双方位置句绑定该镜区间，在场表和单人取景理由只供内部核对。

### 名称与原声的制作版本

按 [名称替换记录](name-policy.md#原声替换的内部记录) 固定制作文本后再排镜。`sources.text` 与 `speech.text` 使用替换后版本，必要时在同一 source 内填 `name_adaptation` 保留替换前文本和精确范围；两种推文的 `narration_sources.original_text` 仍是真实原文，不能伪改原始清单过检。`presentation`、镜内文字、动作、重音词和素材输出别名同步更新，重新估时与渲染。脚本只验证限定替换的字符范围与覆盖，不识别所有品牌／真实地名；最终语义复核继续执行。

### 初态与动作正文的分工

`segment.presentation.人物位置关系` 写所有同场在场者（含全段画外者）的初始场内位置与关系，后入场／离场和入画分别注明时点，不混淆人物移动与镜头改变；`relation.placements` 写该镜投影中的人物方位、朝向、视线与必要阶段，不复述整条动作链。相关变化只在 `action_tracks.beats.action_text` 写一次完整过程，由渲染器接入；`visual_text` 补非重复的可见表情、口型和情境。前镜末态、后镜起态及道具清单的必要短承接保留，不按词语出现次数机械删减。

如段首持续“抱住”、位置句已“松开”、动作句又“开始抱住”，先按实际时点修正对应来源字段，再渲染检查最终合并文本；不能只删成稿中的绑定句，也不把未来结果写入全段初态。见 [状态分工案例](continuity-repair-cases.md#段首初态与镜内变化)。无需新增 JSON 字段。

## 内部节奏总览

需要横向检查当前批次的节奏时，在原渲染命令追加 `--rhythm-output "/path/rhythm.md"`；该可选输出与输入、正式稿、派生计划使用不同路径。`scripts/rhythm_overview.py` 从通过结构检查的同一计划生成各段实际镜头的局部区间、镜长、起止景别和主拍人物变化；同一 `frame_id` 下的内部切镜分别列出，镜内收近仍是一行，不把摄影运动冒充切镜。未声明主拍标为“未记录”，明确为 `null` 则显示“无主拍人物”，不推断画面无人或从台词猜主拍。

表格按生成段顺序覆盖本批全部镜头；存在 `playback` 时另列真实剪辑引用及其原段区间，不把生成顺序冒充成片顺序。各段合计仅加实际镜长，不再累加同期声音。摘要不抄原句、完整画面、机位或审阅结论，不进入正式提示词，也不产生新的必填字段或 `REVIEW` 放行项。它不校验真实取景、自动判断主要观看目的或承诺节奏合格；用它定位后仍对照相关原文和具体表演，按 [主要观看重点](shot-selection.md#每镜的主要观看重点) 与现有模式规则判断。

只读取本批需要的摘要；同版无需反复导出，镜头调整后重新派生。没有工具时直接顺读已有镜头记录，不另抄表。两种推文仍先按连续剧情分组、算发声预算、通过4–30秒检查再排镜；总览不据景别倒推镜长、不改变已锁时长，也不引入固定开场长度或长短交替模板。

## 生成、复核、最终检查

```text
python scripts/render_prompt.py "/path/authored.json" --output "/path/final.txt" --plan-output "/path/plan.json"
```

三条路径必须不同；输出在本次工作目录，不写入技能目录。校验失败先修设计数据；工具不会通过添加剧情、改词或虚构例外修复问题。`plan.json` 是派生记录，`final.txt` 是原正式模板，工具同时显示最终文本与设计记录 SHA-256，按 [复核处理记录](review-closure.md) 分别绑定本次最终版本。有条件切点缺少构图记录、构图与主拍字段不一致会拒绝排版，不从任意机位编号猜真实变化；补齐设计后重试。输入中旧的 `delivery_review` 会失效并从派生记录移除，**自动排版不等于完成内容复核**。

按 [交付流程](delivery-validation.md) 核对实际 `final.txt`，并完成 [提示词冗余校验](concrete-language.md#提示词冗余校验)，尤其检查手写字段与自动生成的机位、位置、动作、静态及原声承接句是否重复。重复优先从对应手写字段删并；必要绑定句保留并同步来源，不直接删成稿凑简短。修订时重新生成、复核受影响内容，之后将四项真实复核说明、逐段光影复核记录、真人剧适用的 [独立占时记录](timing-overlap-records.md) 及 [复核处理记录](review-closure.md) 的 `findings / source_audit / plan_sha256` 填入派生 `plan.json` 的 `delivery_review`，再运行：

```text
python scripts/validate_plan.py "/path/plan.json" --final-prompt "/path/final.txt"
```

涉及导演描述、原声或时间的修改优先更新 `authored.json`，按 [回修依赖范围](workflow.md#高效执行与回修) 追踪受影响内容及后续状态，再重渲染；最终程序仍检查本次完整成稿。渲染已完成设计记录的结构检查，成功后无需为相同版本另跑一次无 `--final-prompt` 的基础检查；完成内容复核、填写完整 `delivery_review` 后直接运行最终命令。原声承接默认生成简短句，仍保留声源、当前区间、续说／停顿状态与口型边界；校验接受同一记录的简短句及旧版完整句，不再强制新稿使用旧长句。工具不替你确认翻译、图片匹配、动作可拍、情绪自然或实际视频质量。

两种推文模式另自动生成 [旁白与画内讲话分离](narration-mouth-isolation.md) 的声源前缀、独立声轨说明与逐镜时段约束；旁白首镜及叙述者本人出镜也覆盖。`visual_text` 补充当前可见的具体嘴部状态与原有非语言动作，不重复自动句，不把限制延伸到实际对白。最终校验按新格式核对，旧成稿须重渲染并复核，不只更改检查摘要。

四种模式都把实际内部切点写入对应运镜区间：同一 `frame_id` 下第二个及后续 `shots` 若没有作者已写切法，默认补“内部硬切至本镜。”；保留已写转场，不覆盖明确禁用硬切或与前镜连续的意图。程序不会替作者把一条长镜自动拆成多镜，也不会据此拆旁白。两种推文按 [连续旁白的镜头设计](narration-editing.md) 硬检承载旁白的每个实际镜头小于3秒；旧长镜记录不豁免。

两种推文另按 [画面信息覆盖](narration-coverage.md) 填写本段 `narration_coverage`，先丰富实际镜头内容，再把原文片段与对应镜头证据登记；渲染器不会为清单自动添加剧情或拆句，最终检查证据必须存在于对应“画面内容”。

两种推文的命令行渲染及校验完成结构检查后，自动用 `narrative_framing.py` 输出 [景别复核提示](shot-selection.md#推文景别成稿复核)：按成片顺序定位连续3个及以上中景或更宽的旁白／内心声镜头，以及覆盖记录中细节／反应与较宽取景可能不匹配的镜头。提示独立于正式文本，属于需要结合内容判断的 `REVIEW`，不自动改镜头或使合法宽景失败。调用Python函数接口时另调用 `review_narrative_framing(plan)` 获取同一组候选问题；函数不改记录。逐项核对实际画面，修订设计或在既有 `delivery_review.visual_continuity` 中写具体保留依据；既有复核不能用一句“已通过”代替。无提示仍须检查关键细节可读性，`--timing-only` 不运行此项。

四种模式的长对白及关键听者反应记录见 [听者接收与反应](dialogue-reception.md)。`dialogue_review` 放在按成片顺序合并后本轮第一条声音；精确 `trigger.quote` 留在内部核对来源与时序。渲染器只将实际时段和 `evidence` 中具体的语义因果及反应写入对应“画面内容”，不再输出触发引文，不重复填写到 `visual_text`。最终校验将这段因果、反应与可见性证据绑定同一实际镜头，删掉或挪错仍需回修；内容复核另核对语义是否确实对应原词。内部判断理由和索引不输出，原声内容、类别与实际切点不变。

反应记录格式不增加必填字段。旧计划可用原记录重新渲染，但需按 [触发与阶段](spoken-emotion-camera.md#反应合并前的触发与阶段判断) 实审当前原词、真实信息到达点、可同期阶段及反应含义，再重建定稿复核；旧最终文本带有重复触发引文或含糊重新起句说明时应重渲染，不直接沿用旧通过结论。起声瞬间标记已听清、同一声音中唯一定位片段的听见顺序倒置会被拒绝；重复片段不猜出现次数，精确词句时刻及语义兼容仍须内容判断，不能批量微调秒数过检。新渲染不自动缩时、拆声或合并镜头，不要求取得音频后才制作提示词。

源句 `reaction_channels` 声明必须看到的 `face / body` 通道，同时建立该听者的覆盖要求。承载对白且总长超过6秒的实际 `shot` 另需该页的 `dialogue_visual`，或重新设计真实切镜；渲染器不会自动编造切点或长镜依据。其阶段表演连同区间写入“画面内容”，内部 `basis / long_take / cut_review` 不输出。结构和最终检查覆盖实际长镜、阶段时间、必要通道与最终证据，旧长镜记录不能只补一句 `hold_speaker` 通过。

真人剧的命令行渲染及计划／最终校验在结构检查成功后，自动调用 `live_visual_pacing.py` 输出 [纯画面内容定时](timing.md#真人剧纯画面按内容定时) 提示：按生成段汇总所有无发声覆盖的实际镜头（包含3秒以内），另标出混合镜头中超过3秒的无发声区间。VO／OS与跨正式分镜原声按实际区间扣除；环境声和动作音效不冒充发声覆盖。`REVIEW` 表示需要内容判断，不是超时错误或自动缩时；定位器不改计划、正式文本或原声，但最终交付必须逐项处理，缺少当前处理记录会失败。该纯画面定位器自身不要求新字段；最终仍有独立时间时另按下节 [声画同期定位](#声画同期与独立占时定位) 的条件性记录执行。正常短镜也须按本次画面实审，不能照搬旧“通过”。

调用函数接口时另用 `review_live_visual_pacing(plan)` 获取同样的复核位置，返回结果不修改输入；`--timing-only` 没有完整镜头信息，不运行此项。简短的混合镜头空隙仍按内容检查，自然起声／收尾间隔不自动判为冗余；无提示不表示已经验证最优节奏。将实际修订或保留依据合并进既有 `delivery_review.timing`，再按交付流程校验同一份定稿。

四模式的 [关键信息内容复核](shot-selection.md#关键信息的可读性与特写) 不依赖新的字段或自动识别器。现有 `narrative_framing.py` 只提醒部分推文景别候选，不能覆盖所有任务类别、短旁白、人物中近景中的小物件或两种剧的细节遗漏；`live_visual_pacing.py` 只定位真人剧无发声区间。所有模式均须从原文到最终段镜复查必要证据，结论复用 `delivery_review.source_coverage`／`visual_continuity`；没有提示或程序通过不代表已经完成此项。规则更新不要求迁移旧数据结构，但重用旧稿时必须实审受影响的证据，不能自动沿用旧通过结论。

### 合并的内容复核提示

命令行渲染及基础检查统一调用 `review_report.py`：五个专题定位器保留模式范围、阈值、原始结果和证据，将过肩几何疑点、景别、真人纯画面、推文自然结束点、同期与独立占时按生成段／实际镜头集中显示。每项显示稳定 `key`，R编号仍仅用于本次导航；同位置的不同事项不去重，跨镜保留完整镜头链。最终校验按 [复核处理](review-closure.md) 重新计算当前候选并核对全部处理记录；未处理则失败，成功后不把已处理事项再打印成待处理提示。

这只是上述五类专题 `REVIEW` 的统一入口，不接管口型、原声、反应、特写等其他硬校验与内容复核。所有 `FAIL`、最终文本绑定及完整校验保持；无提示不代表内容已通过。具体判断写入既有 `delivery_review` 的 `findings`，逐项绑定实际镜头；`source_audit` 从原文独立反查遗漏，`plan_sha256` 防止设计变化后沿用旧复核，不新增正式提示词字段。真人剧独立占时的记录仍按下节执行。`--timing-only` 不调用画面定位器，也不能取得最终交付通过。

函数调用可用 `collect_review_report(plan)` 一次取得各专题原始结果及段镜索引，或用 `print_review_report(plan)` 显示同一报告；正常生成采用一个入口，不再叠加调用已有单独打印器。原来的专题函数保留兼容和单项维护用途；下文及其他专题页所说的命令行自动提示均由此统一呈现。它们的适用条件与检查内容不变，报告不进入正式提示词，不改输入或自动裁时、补词、删镜。

### 声画同期与独立占时定位

四模式的命令行渲染、计划／最终校验通过结构检查后，调用 `timing_overlap_review.py` 输出 [同期与新增占时复核](timing.md#同期与新增占时复核) 位置：先合并本段所有发声记录区间，再列其未覆盖区间及相交的实际镜头起点，包含短空档、混合镜尾及整段无发声。各声音类别与跨正式分镜原声一并处理，音效不冒充发声；只计算已填区间，不测量真实音频。报告不把声音与画面相加，也不把未覆盖秒数当作可节省时长。

`REVIEW` 仅供内容复核，不能据此自动删尾、移动反应或把下一句提前；定位器不改计划或正式稿，最终检查会拒绝未完成处理记录。程序不判断语义因果、人物执行能力或观众可读性，全程有声但估时偏长的情况仍须人工核对。报告同时定位区间前后的原声索引与本地时间，仅作比较候选，不表示因果／空间兼容。跨段只取成片顺序中直接相邻、同集剪辑片段内的原声，不跨集或跳过无声片段寻找；不把两个生成段的本地秒数直接叠在一起。结果与其他计时提示在同一遍处理，具体修订／保留依据并入既有 `delivery_review.timing`。仅真人剧在最终校验增加 [条件性独立占时记录](timing-overlap-records.md)：旧制作计划仍可渲染，旧成稿复用前需实审并补齐命中区间；其他模式不增加这项记录。函数接口另用 `review_timing_overlap(plan)` 获取同一位置；`--timing-only` 没有完整分镜，不运行此项。

### 推文画面自然结束点复核

两种推文的命令行渲染、计划与最终校验在结构检查成功后，调用 `narrative_visual_pacing.py` 定位所有被 `narration / inner` 覆盖的实际镜头，3秒以内及同一正式分镜的内部镜头也列出。报告给出完整镜头区间和每条原声在本镜的交集，不将声音结束后的尾部排除出全镜内容复核；无声独立镜头、现场对白及两种剧仍按原检查执行。提示按生成段汇总在正式文本之外，是 `REVIEW`，定位器不改变正式稿、来源、原声、时间或镜头；候选处理按共用 `findings` 记录，未完成时最终检查失败。`--timing-only` 缺少完整画面，不运行此项。

函数接口另调用 `review_narrative_visual_pacing(plan)` 获取相同位置，或按 [声画时长匹配](narration-coverage.md#自然结束点与声画时长匹配) 人工覆盖同一范围。逐镜核对正常速度下动作／阅读／必要情绪的结束点及剩余内容，结果并入已有 `delivery_review.timing / visual_continuity`；脚本不估自然动作速度、不保证真实内容充足，也不替代最终视频验收。已有 `narration_coverage` 仍检查来源映射，长镜检查继续生效；其结构通过不免除本项。

### 同段原声重复检查

按 [同段切镜不重新起句](output-template.md#同段切镜不重新起句) 写本次最终稿。渲染器只在原声起点输出一次声音行，跨实际镜头时自动加入完整区间只执行一次的说明；每镜承接句只覆盖该镜实际可听区间，并明确不因切镜重新起句或重念。既有内部触发字段不迁移、不删词，`evidence` 须提供具体语义因果，不能夹第二份完整台词。

`speech_output_guard.py` 由最终校验及渲染调用：检查非声音正文中双引号／角引号包裹的完整源句拷贝、跨实际镜头的声音行执行标记，以及对应实际镜头内可明确归属续声者的从头重念指令。画面文字须有明确载体或可读标签，单词重音与短词组不作为整句重播，正式原声中的真实重复照原文保留。必要屏幕文字的来源、未加引号的复述、复杂否定或代词、同镜同人多次发言的归属仍需内容复核；检查通过不证明实际生成声音合格。旧承接句的兼容只用于绑定，不豁免本次一次执行及无重复引文检查。

## 改版评估

`assets/evaluation/` 提供固定、虚构的源剧情和设计记录，覆盖对白与肢体、情绪承接、动作特写与状态链、连续原声与反应、电话与回忆、跳切与特写信息链、画面可见性、方向与开口、短镜例外、静态时长及声效时序；另有清透空间、伦勃朗光与反打、焦散与取物、电话异地光源、既有薄雾中的体积光、动作特写受光、人物走出亮区七组光影案例。仅技能维护时使用，不在正常生成时读取或照搬。

```text
python scripts/evaluate_fixtures.py --output "/path/evaluation.json"
```

自动报告排版／结构检查结果及脚本耗时，**不是模型生成速度或导演质量测量**。每个案例的 `evaluation.brief` 可作为相同输入进行改版前后生成比较，`manual_checks` 是复核重点。报告将这些项目列为 `pending_content_checks`，内容复核状态明确为 `not_run`；必须实际阅读成稿后另记结果，不能把复制检查点当作通过。光影案例附有应被内容复核拒绝的反例及原因，脚本不自动判断这些反例。记录实际生成耗时、首次漏词／关系位／时序错误及返工次数；只有实际运行的比较才报告提升比例。普通交付不自动运行这些维护案例。

### 道具清单与成稿绑定

四模式的范围按 [特殊道具清单](output-template.md#特殊道具清单) 从本段正文和实际设计确定。新稿以 `segment.props` 为单一填写来源：非空列表按顿号连接为“特殊道具”；`[]` 表示已核对没有相关物品，正式稿省略该行。列表项用剧情名称及区分所需的归属／起始状态，不填文件路径、素材文件名、未来动作或校验理由。重复项、空项、换行、“无”等占位项及非列表会拒绝；同义物品是否重复仍须内容检查。

旧稿非空 `presentation.特殊道具` 可直接作为已有声明，保留其文本，不凭空拆分物品名称；若同时有 `props`，两者须与列表连接文本一致，冲突要求回修，不能自动择一覆盖。未声明道具的旧计划仍能作结构渲染，但公开四模式最终交付必须明确补上相关列表或经实审的 `[]`，不能直接沿用旧“通过”。渲染器不会从画面、台词或素材名称自动猜物品，也不会因字段缺失自动判断为无道具。

结构与成稿检查绑定已声明的清单：已列出的“特殊道具”被删行、丢一项、换名、改持有者或无依据追加时拒绝，重新填写复核摘要也不能绕过；明确空列表却在成稿加清单也拒绝。未使用 `props` 的旧非空字段同样保护。字段保持原位置与原名称，不增加正式模板字段；台词、切镜、时间和持物动作不会由清单自动改写。

最终仍须对照原文、采用素材、各镜持物／交接／操作／证据及跨段状态核对清单完整性，结果并入已有 `source_coverage / visual_continuity`。程序能检查声明与成稿一致，不能证明作者填 `[]` 是否符合剧情，不能识别所有同义道具或自动补遗漏；不得以填空列表过检。修改清单回到设计稿重渲染，只复核实际受影响内容，不为本项增造镜头或每镜清单。

## 本轮镜头排列与精简输出
