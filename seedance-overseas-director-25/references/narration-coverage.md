# 旁白画面信息覆盖与镜头节奏

“3D漫推文／推文”有叙事旁白时使用。目标是让观众看全原剧情的必要信息，画面随信息发展；增加具体的观看内容，不靠加形容词、重复反应或延长动作。对白和内心声沿用各自规则，不把旁白改成人物开口讲话。

## 先展开信息，再安排镜头

沿完整旁白划分语义单元，结合本段已经提供的场景、动作和前后文，为每个单元确定观众需要看懂什么。内部划分不拆声音记录，不生成新的台词来源。按原文实际需要检查下列维度；**不是每段凑齐六类，也不是每类必须单独一镜**。

| 信息维度 | 应交代的画面内容 | 避免遗漏或虚构 |
| --- | --- | --- |
| 场景与处境 | 当下空间、人物所在位置、必要环境状态或围观关系 | 只有人脸而不知发生在哪里；为丰富画面新增天气、地标或无关空镜 |
| 人物与关系 | 谁在行动、对谁、双方距离／视线与必要旁观者 | 只拍旁白音色对应人物，遗漏真正的行动者或承受者 |
| 动作过程 | 原有起态、动作发起、关键接触／转移和完成后的状态 | 只给开始和结果；每切一镜重新抬手、递花、走近或开门 |
| 关键物件与证据 | 原文所需物件、文字、屏幕、持有者及状态改变 | 提到手机却不让人看清用途；装饰性特写替代真正证据 |
| 接收与反应 | 原信息抵达后，相关人物从什么状态如何应对 | 全程主角表情，其他必要人物反应不可见；提前知情 |
| 结果与后果 | 操作是否完成、归属是否改变、关系或环境发生什么变化 | 按下按钮却没有结果；同一结果反复展示、无依据新增后续事件 |

先优先覆盖原文明确出现的主体、动作、物件、关系和结果，再挑能补足理解的既有环境与反应。抽象叙述、评价或回顾可用原场景中已有的具体行为／状态承载；没有素材依据不插入新回忆、幻想、事件或陌生人物。若原文信息有限，短而清楚地拍完，不为凑镜头加剧情或慢做动作。

每个实际镜头写清：主看谁／什么、可见起态、在本镜发生的具体变化、切出时留下什么状态。承载多个相互关联的信息可以同框完成；主体、证据或因果阶段需要另一个观察位置时再切。补全内容须在实际“画面内容”中落地，不能只在内部清单说“已交代”。

信息完整由镜头组共同完成，不要求每镜同时展示完整环境、全员、全身和局部细节。按 [推文任务与景别](shot-selection.md#推文旁白与内心声的景别选择) 为每个信息单元确定可读范围：人物态度与接收按 [模式优先级](shot-selection.md#情绪与景别的模式优先级) 优先采用中近景，关键变化在该构图中不足以表达时再收近，身体交互按必要部位取景，物件证据按辨读需要靠近，空间规模才使用承担该任务的宽景。不能用一个全景加上“表情／屏幕清晰”代替实际取景设计，也不为修正偏宽而漏掉已有空间与动作。

## 旁白的默认节奏

- 先按动作、阅读或必要反应的自然结束点安排区间；承载任何叙事旁白的整个实际镜头必须 **小于3秒**，3秒整也不通过。能更早读清就及时推进，不默认2.9秒、不均分整段预算；原短镜下限与静态规则仍保留。
- 前一任务完成、观察对象改变或新证据出现时，在原文允许的时点切入有信息的新画面，不等旁白句尾；不能将已完成的动作换角度重新播放。
- 按 [旁白单镜硬限制](narration-editing.md) 检查整个镜头，包括镜内无声或其他声音时段；镜内推近、重编号或旧 `narration_visual.long_take` 记录都不构成实际切镜，也不能放宽限制。必要阅读或接触确实无法兼容时指出具体冲突，不删必要信息、加速或自行延长。
- 单个表情、压耳、停尾、抬眼或一次动作完成后的保持，通常在较短镜头内交代。耳尾可以承担重要反应，但“能写出几项动作”不证明应持续拍同一个对象；同一情绪的不同身体信号不自动变成多个信息节点。
- 同一场景可以切不同主拍对象、必要关系位、动作／物件或反应；遵守真实机位、景别、轴线与跨段构图规则。不能只改编号、景别词或慢推来冒充新画面，也不插无任务的环境镜或重复特写。

增加实际镜头不自动增加生成段、时长或词数。一条完整旁白连续覆盖这些镜头，原句只写一次；不因切到物件、反应或换正式分镜暂停、重复起句。原有非讲话口型规则继续执行。

例如已提供剧情为“走近手机结束直播 → 屏幕变黑 → 周围安静”，可组织为：

| 镜头任务 | 画面覆盖 | 切点依据 |
| --- | --- | --- |
| 接近与起手 | 看清双方关系、走近后的距离，以及右手从身侧伸向手机 | 手已经伸出，接下一镜继续操作 |
| 操作与直接结果 | 看清手指按下按钮、屏幕变黑、手离开，持机人不换手 | 操作与结果已被看懂，不再另拍一段同角度黑屏 |
| 群体反应 | 原本围观的人收住声音、停止交换目光，保持既定站位 | 环境变化有了可见落点，进入下一剧情信息 |

实际秒数按原声与动作核定；只示范原文已有因果链，不要求所有旁白套三镜，也不默认每次都回主角特写。

## 自然结束点与声画时长匹配

先执行 [发声预算锁定](narrative-budget.md)。本节只安排已锁段长内的有效画面，不通过动作、阅读或必要余波加长段落；不足时检查同期与合法切点，确需重新分组则在新一轮提示词生成前重算并锁定，不能修改原预算数字后宣称符合。

两种推文的旁白及内心声画面都按本节逐实际镜头复核，包含3秒以内、已有信息覆盖记录及已经写了“自然速度”的镜头。内心声仍按原人物情绪表演，不能套叙事旁白的中性语气或让他人听见；本项不使内心声自动触发仅叙事旁白适用的覆盖字段与长镜记录。现场对白继续执行原对白规则；混合镜头同时保留其真实开口、发声区间与原有同期例外。

**声音完整时长与画面自然所需时间分别确定，再放到同一时间线上匹配。** 旁白需要8秒，不表示一次抬手需要8秒；画面证据出现过也不证明整镜一直有有效内容。先核对目标语种原声的自然语速和必要气口，估时确有偏差才校正，不为少配画面快读、拖长旁白或默认加缓冲。再从动作距离、接触难度、物体重量、人物状态、阅读量和必要情绪过程判断画面时长；不用文字长度、动词数量或固定每镜秒数换算。

逐镜在同一设计记录内回答三个问题：**本镜必须看懂什么；正常速度下何时看懂且必要过程完成；此后到切出还有什么不可省的观察。** 复用已有动作节点、反应区间、`static_spans` 和视觉阶段；没有相应结构化记录时直接在原画面描述与计时复核中明确，不新建每镜必填表，也不为过检补虚构的阶段或空列表。

- **自然结束点具体落地。** 容易被摊满时间的动作写清发起、关键接触和完成时点，采用“第 X 秒完成／切出”的段内动作提示，不另造镜头区间。例如原文确有递花且自然过程约1.5秒，可写“右手从原位置递出花束，第1.5秒到达双方之间；随即切到原剧情需要的下一观察对象，花束仍由原手握持”。不是让所有递花固定1.5秒，也不是只加一句“正常速度”却仍将一次递花铺满8秒。时点需与该镜的真实起止、动作记录及下镜初态一致。
- **区分完成与必要余波。** 情绪消化、尝试控制、姿态改变与关系转折可以在动作完成后继续形成有效内容；必须有本次剧情、可见阶段和落点，不能统一削成一秒反应。文字须从真正显露、对焦且无遮挡后留出可读时间。相反，已完成结果的凝视、呼吸、随机眨眼、耳尾轻摆、毛发运动或无信息慢推，不能替剩余时间提供依据；按实际纯停留登记并检查静态上限。
- **正常速度完成后换有效任务。** 从原文及已有场景中补全未呈现的对象、施受关系、关键接触、证据、相关人物反应和结果；每个补充须回答它增加了什么必要理解。不是每类各加一镜，也不为多切镜头将同一动作拆成准备、靠近、接触各自慢做。切到另一个角度继续未完动作时承接进度；动作已完成就不重演。3D保持合理缓入缓出、重心与耳尾次级动作，不延长启动／收势来填旁白；真实复杂过程或有依据的慢动作按原规则保留，不强制全片匀速。
- **复核整条镜头组。** 多个短镜也可能重复同一信息；只换景别、改编号、拆成更多生成段或重复播放素材，都不增加有效内容。按原声语义与事件允许的时点调整切点，不能提前展示下一条消息、倒置动作、让人物听见内心声或提前反应。旁白仍单次连续执行，画面切换不新增停顿、重读、对白或口型。
- **信息不足如实处理。** 先检查遗漏了哪些原有信息，以及原剧情允许同期呈现的相邻内容能否重新分组；保持揭露顺序、发声类别及动作因果。抽象叙述可以承载原场景已有的具体关系／状态，但不是凭空演一场新回忆或新增事件。确无足够可视内容且原声必须完整时，不能保证同时保持高信息密度；在已有授权内处理，超出既定旁白删减边界的压缩或补充改编只单列建议，不自行实施，不以慢动作或空等掩盖缺口。仅切短生成素材或后期剪辑同样不能创造不存在的信息。

返修将具体段镜、自然落点及剩余时间的处理合并记入既有 `delivery_review.timing`／`visual_continuity`。可合并说明共享依据的镜头，但不能用“均为正常速度”代替实际核对。修改切点同步动作阶段、声源交集、信息到达、画面文字、静态时段、音效和后镜状态；原声确需重新估时则传播到整条相关时间线。没有改声音的依据时保留原声时长。

工具在渲染、计划及成稿命令完成结构检查后，用 `narrative_visual_pacing.py` 列出所有被旁白／内心声覆盖的实际镜头及本镜声音交集，整镜前后无声部分也在内容复核范围。它不测动作速度、不判断动作完成时点、不自动缩时或证明内容充足；少于6秒、映射完整及结构通过均不免复核。无工具按同一口径人工检查。

如可用样片已有正常速度动作却未执行切点，按实际偏差回修；必要时提出独立正常速度素材与完整旁白后期组接方案，遵守现有生成／后期边界，不自动提交生成或声称本技能已经执行剪辑。有足够合法画面时这可控制取用区间；素材不足时仍按上段处理。只有实际观看／试听后才验证成片节奏，不承诺提示词完全杜绝慢放。

## 内部覆盖记录

在原 `segment` 中使用 `narration_coverage`。本段累计叙事旁白超过6秒时必填；其他旁白也按同口径内容复核，必要时填写。清单只供核验，不新增正式提示词字段，不由程序自动编剧情。

```json
{
  "narration_coverage": [
    {
      "source_id": "N1",
      "text": "I walked up to the phone and pressed end.",
      "task": "action",
      "focus": "佐伊接近手机并完成结束直播的操作",
      "views": [
        {"shot_start": 0, "evidence": "佐伊走近一步，右手从身侧抬向手机，指尖尚未触屏"},
        {"shot_start": 2, "evidence": "佐伊食指承接已伸出的进度按下按钮，随即离开屏幕"}
      ]
    },
    {
      "source_id": "N2",
      "text": "The screen went black.",
      "task": "result",
      "focus": "结束直播后的屏幕状态",
      "views": [{"shot_start": 2, "evidence": "手机屏幕随按下操作变黑，仍由伊森左手握持"}]
    }
  ]
}
```

`text` 是本段实际发声文字的原文片段；同一 `source_id` 可按语义列多项，按顺序拼回本段该来源全部发声文字且不重不漏。多个镜头共同承载同一句时，在同一项的 `views` 列出，不重复登记句子；一镜内完成动作与结果时可以被不同项引用，但各自证据必须说明不同的必要信息。跨生成段只映射本段实际发声片段，不复制另一段全文。

`task` 为 `context / relationship / action / detail / reaction / result`，`focus` 写本项具体对象与观看目的；分类名不是画面内容。`shot_start` 指本段已有实际镜头的开始时刻。`evidence` 摘录该镜最终“画面内容”中能证明本项得到呈现的具体文字，可来自手写画面或已有动作／反应／长镜记录的自动输出；不在其他镜、运镜字段或段首补一句代替本镜画面。此记录不会自动把证据插入成稿，须先真实完成分镜。

程序检查本段旁白文字全覆盖、来源归属、镜头引用、重复证据及成稿绑定。它不能判断一句里有几个真正必要的视觉信息；不得把所有旁白塞进一项“人物情绪”或用泛泛的人脸证据声称全覆盖。逐项人工对照上表与原文，发现缺失就补实际内容或调整机位／切镜。

## 返回前检查

四模式共用的 [关键信息与特写](shot-selection.md#关键信息的可读性与特写) 同样用于这里：从旁白与当前剧情确认应展示的证据，而非只查已登记的细节任务；`action / result / relationship` 中的文字、标记、操作与状态也要核对实际可读落点。短旁白没有强制覆盖记录，或人物取景已到中近景，均不免检；声轨完整不证明证据已呈现。

- 从旁白回看镜头：每个必要事实有没有对应的可见信息，行动者、对象、过程和结果是否完整，画面是否提前揭露或新增剧情。
- 从镜头回看旁白：是否持续提供本段需要的信息；若只有同一主体重复表情／耳尾、无关空镜或已完成动作，改为有依据的另一观看任务，或缩短并重新分组。
- 逐镜确认叙事旁白实际镜长严格小于3秒，并按 [整段排列](shot-sequence.md) 排除空转、重复返回和机械快切；旁白连续、动物表演丰富或“保持张力”都不能豁免。
- 核对整句原声连续、画内嘴部状态、动作进度及前后段构图。画面改排不自行改变原声时长；按上节确有自然发声估值偏差才重新核定并同步时间线，不靠快读或新增停顿容纳镜头。
- 按 [景别成稿复核](shot-selection.md#推文景别成稿复核) 检查实际取景与信息是否相配、连续偏宽是否有逐镜任务。程序的 `REVIEW` 提示只定位候选问题，人工核对具体修订或保留依据；没有提示也不代表画面细节已经可读。

结果并入既有 `delivery_review.visual_continuity`。结构检查不等于已确认画面信息完整，也不证明视频模型执行了所有镜头；内容复核和实际视频检查分别据实报告。
