# 结构化校验方法

四模式共用本记录结构。顶层必填已明确选择的 `mode`，两种推文的声音类别、旁白清单、长旁白复核及50秒整集下限见 [模式记录](mode-records.md)；本页旧的无最低时长／VO／OS示例按剧模式解读。公共命令行不接受缺失或未知mode。

用于提示词生成的结构化记录校验。交付流程及最终文本检查见 [交付前校验流程](delivery-validation.md)；仅分析不建立生成用 JSON，无 Python 或文件工具时执行等价人工复核。脚本及同目录 `delivery_checks.py` 只使用 Python 标准库，只读取指定文件，不联网、不生成视频、不改写文件。

## 使用边界

1. 先从已读原文建立发声清单，再设计镜头。`sources` 只包含已选范围实际应发声的原句或已核对的固定译文，按原文顺序排列；原文位置、关键非语言事件及用户明确授权的文本调整依据另按 [原文对应与跨集记录](source-continuity.md) 维护。
2. 从原模板的分镜时间、“运镜”“画面内容”和原声音字段同步校验记录。`shots` 只列实际连续镜头／内部子镜头，不再列父分镜；跨子镜头发声只记一条，跨段拆句按实际发声部分分别记录同一 `source_id`，不能为切反应镜头拆出新的原文来源。脚本另按成片时间检查同一来源片段之间的停声间隔，真实停顿及最终画面承接按 [拆句停顿与声音承接校验](delivery-validation.md#拆句停顿与声音承接校验) 记录。JSON 仅供内部校验，不要求正式输出新增字段或子镜头标题。
   回忆抽离合并时，`segments` 记录实际生成分组，另用 `events` 记录原文剧情单元、`playback` 记录成片区间顺序；`sources` 仍是原文叙事出现顺序。脚本逐生成段检查词数与时长，按 `playback` 还原台词、VO、OS 的发声顺序及文本；未提供时默认各段整段按 `segments` 顺序播放。
3. 中间检查运行 `python scripts/validate_plan.py /absolute/path/plan.json`；交付检查必须再提供 `--final-prompt /absolute/path/final.txt`。Windows 路径有空格时加引号。退出码 0 表示本次所选检查通过，1 表示发现问题，2 表示输入或读取错误。基础模式明确提示交付尚未检查。修正实际分镜后同步记录再运行，不能只改 JSON 制造通过结果。
4. 最终模式读取实际提示词，检查段数与段号、标注时长与词数、字段结构、分镜时间、出镜名单、声音文本／类别／说话人／发声区间、内部镜头区间、剪辑区间及复核后的文本摘要；镜头记录完整时还检查声音互斥、在场人物合集、各镜真实可见范围与成片顺序的景别切点。最终模式同时检查 [动作链记录与具体动作句](action-continuity.md)，核对相邻已记录状态、必要结束状态与动作文字在对应镜头的绑定；不能自动理解正文是否漏动作或动作是否物理可行。每个实际镜头还须提供 [逐镜关系记录](delivery-validation.md#逐镜关系记录)，检查证据与该分镜画面文字的绑定。脚本不读取原剧本，无法证明原文清单无遗漏、翻译语义正确、动作可拍、关系构图真实或音频估时自然；不能因名单与证据文本一致就认定没有关系位丢失。上述内容仍按主技能人工复核。
5. 最终交付另按 [复核事项处理](review-closure.md) 验证当前候选逐项处理、全部段的原文反查及设计／成稿双摘要；未处理或旧版本结论不放行。旧制作记录仍可渲染，旧复核记录须实际重审后补齐，不能批量默认通过。

四种模式的长对白或短句关键接收另按 [听者接收与反应](dialogue-reception.md) 维护 `speech.dialogue_review` 与必要的 `sources.reaction_targets`；基础设计和最终文本均核对，纯计时预检不代表已验证反应覆盖。

源句可用 `reaction_channels: {"听者": "face"}` 或 `"body"` 明确必要反应部位并建立覆盖要求，防止仅改通道绕过脸部可见性。承载对白且总长超过6秒的实际镜头另按该页记录 `shot.dialogue_visual`，否则回到实际切镜设计；听者覆盖与长镜取舍分别检查，内部依据不进入正式提示词。

## 最小记录示例

以下是已明确选择的片段示例，`current` 为内部范围标识，不是原剧集号；不因示例自动确认用户的生成范围。各时间都是本段内秒数。

```json
{
  "mode": "真人剧",
  "episodes": [{"id": "current", "complete": false}],
  "sources": [
    {"id": "L1", "episode": "current", "speaker": "Mara", "kind": "dialogue", "language": "en", "text": "Put it down."}
  ],
  "segments": [
    {
      "id": "current-S1", "episode": "current", "duration": 4, "english_words": 3,
      "shots": [{"start": 0, "end": 2}, {"start": 2, "end": 4}],
      "speech": [
        {"source_id": "L1", "speaker": "Mara", "kind": "dialogue", "start": 0.2, "end": 1.7, "estimated_seconds": 1.5, "text": "Put it down."}
      ]
    }
  ]
}
```

- `content_language`：本次共用发声与画面文字目标，来源优先级见 [剧本语种](source-continuity.md#剧本语种与台词画面文字)。新稿填写单一目标语言代码，如 `zh`、`en`、`pt`、`es`、`zh-Hant`、`pt-BR`；不填 `mul`。每条 `sources.language` 与它一致；原文／用户明确要求的外语或混语在对应来源填非空 `language_exception_basis`，并保留具体位置与原因供实审，不能靠例外改写原句。混语仍填 `speech.language_parts`。地区代码双方都明确时须一致；未明确地区不自动补定口音。旧记录未填该字段且发声来源统一为中文／英语／葡语／西语之一时，程序可按已声明的发声语种补用共用限制，不从中文导演说明猜语种。无声或多语来源不能唯一确定目标时，制作命令要求显式填写；不能默认为英语。新稿仍先分析正文并填写目标。
- `episodes`：按已确认的处理顺序列内部唯一范围 ID；只有请求完整一集时 `complete` 为 `true`。不得为了绕过最低时长将完整集标成节选。正文集号与显示标题按原文保留；已知集号时填写 `title`，段编号自动采用“集号-段号”。同集续作可填正整数 `segment_start` 承接已确认起点；内部 ID 不充当原集号，也不出现在画面上。
- `sources`：每条 ID 唯一，`kind` 为 `dialogue`（人物现场台词及其画外延续）、人物 `VO` 或人物 `OS`，与原模板的声音类别相同；VO/OS 的实际语义另记在内部原文对应中，不仅凭缩写推定。`speaker` 填对应的原剧本角色名，有中文名就保留中文，并与 `speech.speaker`、可见人物名单及最终声音行首、参考括号内的两处姓名一致；以上是两种剧模式的声音来源；两种推文允许原文独立叙述者，使用narration／inner类别及mode-records.md的旁白清单和音色参考规则。`language` 是最终发声语言，英文为 `en`，混合语言可用 `mul`；混合发声必须在 `speech.language_parts` 按原顺序列出 `{language, text}`，片段拼接须还原本条全文，英文部分仍计入 96 词；英／西／葡语共用词速不改变这个仅限英文的计词上限。中文等非拉丁文字语言内出现拉丁字母时，脚本要求明确分语言记录；西语等语言中的英文混用仍须人工识别，不把拉丁字母一律当英文。
- 语种校验检查来源声明、两项限制及最终成稿绑定：覆盖自定义限制时仍须保留自动生成的语种声明，不得另写其他目标语种的默认指令，中文目标不得夹带禁止中文。实际引号内台词及可见文字与原稿、目标语种、例外依据的符合性由既有内容复核检查；程序不能凭拉丁字母辨别西语／葡语／英语，不能把字段正确当作翻译正确。
- 面部／眼部颜色与视效变化：按 [面部与眼部描述校验](appearance-validation.md) 检查最终实际字段。常见无依据惨白／红眼等会触发 `facial appearance REVIEW`；明确局部轻微脸红、眼眶微红可保留，原文明示面部视效可填 `segment.appearance_reviews` 绑定来源与实际范围。该记录不是题材开关，也不自动证明原文或图片真实性；实际发声原句不因颜色词删改。
- `segments`：按生成提示词交付顺序排列，ID 唯一，同集连续、不混集。`duration` 和 `english_words` 是每个实际生成段标题的标注值，脚本与该段镜头区间、发声文本重新计算比对。回忆抽离时此顺序可以与成片顺序不同，须同时填写 `events` 与 `playback`。
- `unrelated_prefix`：仅在因前后完全无关联而实际独立拆出的前段对象内设为 `true`；其他段省略或设为 `false`，必须为布尔值。脚本对标记为真的段检查至少 4 秒，并继续检查 30 秒、96 词等限制；两种剧的普通短段和碎片组合不因此套用4秒下限；两种推文的每段提示词均另按 [分组预算](narrative-budget.md) 满足4–30秒，段内片段／镜头不因此延长到4秒。是否满足拆分条件、碎片组合是否被误拆、是否漏标及后半内容是否正确向后合并，仍须对照原文与分组人工核对，不能用省略或改为 `false` 规避已拆前段的下限。
- 最终整段 `duration` 必须为整数且段首不带小数，分镜末时点与其一致；可选 `pre_round_duration` 表示整段统一调整后的原始估值，填写时须大于等于1秒且 `duration` 等于其直接去小数后的值。基础草稿可暂有小数总长，交付前按 [整数时长](timing.md#整段整数时长) 整理实际区间，不自动裁断声音／动作或向上取整。
- `shots`：按时间顺序从 0 覆盖到本段结束，既无空隙也无重叠；边界使用 0.1 秒或更粗单位。所有实际镜头默认至少 1 秒，短镜依时长规则记录局部例外，包含有声覆盖的反应镜头，实际声画可能需要更长；连续静态展示最多 2 秒，交付记录逐镜填写 `static_spans`，具体见 [实际镜头与静态展示](timing.md#实际镜头与静态展示)。单个实际镜头不得覆盖不同声音类别；交付记录用 `frame_id` 归入原模板分镜，再检查整个分镜的声音互斥及默认只含一位发声人物。按实际相交时间汇总人物，包括前镜延续声音，不只按该镜声音行或主拍人物判断。镜头与分镜的对应及扩展字段见交付流程。
- 四种景别组合仍按实际结束／开始状态判断换机位或换主拍；无有效局部例外时相邻同景别仍禁止同机位，跨段仍禁止同景别；[时间跳切](cut-techniques.md#时间跳切的内部记录) 在后镜填 `jump_cut_before`，基础／最终检查均核对同段同场和实际前镜，最终文字还须绑定本镜跳切说明。基础草稿模式兼容原机位／姓名记录；最终模式及渲染器必须读取切点两侧的 `view/end_view`，比较固定空间中的摄影位置／高度和主拍，绑定到本镜运镜区间。字段与构图变更流程见 [真实机位校验](camera-continuity.md)，不凭编号、说话人或前景肩背变化放行。
- `speech`：按发声开始顺序列出；`estimated_seconds` 是该部分实际需要的发声及自然气口时长，有音频时用实测，无音频的中文按 [中文每秒7字](chinese-timing.md) 独立估算，英语、西班牙语及葡萄牙语共用实际原语种词数÷3.4估时，数字读法先展开；不在该实际时长上再叠加中文 `N/7` 或英文 `W/3.4` 已经包含的时间，不因分镜或拆声片段而重复加时。值必须能放入声音区间，不得为了通过检查缩短估值。非英文也必填，纯无语言段使用空数组。
- 跨段拆句：按原文当前位置逐片段匹配，还原原文字符连接及词间空格；不得在英文及拉丁字母单词、缩写、词内连字符内部拆开，例如不能把 `Nobody` 拆成 `No` 与 `body`。中文片段不强加空格，英文原有词间空格保留。脚本检查字符与单词边界，自然语义停顿仍人工判断。
- 数字读法：`text` 原样保留；中文或英文含数字时用 `number_expansions` 指定原字符串的零起点字符区间（含 start、不含 end）及 `spoken`。例如 `Pay $20.` 对应 `[{"start":4,"end":7,"spoken":"twenty dollars"}]`。脚本只替换数字表达，保留其余文本，再计词；可选的 `spoken_form` 必须等于推导结果，没有数字时必须等于原文。中文按展开后的发声汉字计字，英文计词；混合语言把展开记录放在对应中文或英文 `language_parts` 项内。数值读法是否忠实仍人工核对，不能以改读法压缩词数。
- 异常估时：英文计词量除以 `estimated_seconds` 超过 8 词/秒时触发复核，不能直接交付。这是发现明显误填的阈值，不是目标语速，也不替代整段总词数的 `W/3.4` 初筛；逐条异常语速检查不要求逐条追加时长。应先修正估值；只有确有已查看并测量的对应音频时，才能提供 `timing_review: {"basis":"measured_audio","source":"实际音频与区间","measurement":"测量方式及结果","seconds":实测秒数}`，秒数须等于估值。脚本只检查复核记录结构，不测量音频；没有实测依据时不得编填字段绕过。低于阈值也不代表发声自然。
- 原文明示重叠讲话时，相关段可填写 `overlap_basis`，记录具体原文位置与依据；否则脚本将重叠视为错误。该字段不能授权改写台词顺序或让听者提前反应，也不自动豁免一分镜一位发声人物的默认规则。
- `frame_speaker_exceptions`：只在有具体依据的特殊多人分镜上填写，结构及条件见 [单人发声与特殊例外](delivery-validation.md#单人发声与特殊例外)。按本段 `frame_id` 绑定非空 `basis` 与完整 `source_ids`；无例外时省略，不把普通轮流接话或多个可见人物误当例外。基础记录具备交付镜头元数据时检查，最终模式必须检查；声音类别互斥及重叠依据要求仍独立生效。
- 共同默认每段英文96词上限、30秒上限；两种推文每段严格4–30秒且完整集默认至少50秒，两种剧不设整集下限；`unrelated_prefix: true` 的独立前段至少 4 秒。只有用户明确修改时才在顶层加入 `limits`（`english_words`、`segment_seconds`、`episode_seconds`、`unrelated_prefix_seconds`，可只提供被修改项；`episode_seconds` 默认0，仅表示用户明确要求的整集下限，0表示无下限），并填写 `limits_basis` 记录该用户要求；不可为了通过校验自行放宽，两种推文既有较大 `segment_seconds` 也不能豁免30秒上限。

时长新增可行性记录与局部短镜例外见 [计时规则](timing.md)，结构化音效见 [声效事件](sound-timing.md)。无音效不建事件；原数据含自由音效字段时先据剧情迁移，不自动猜时点。

## 原文剧情单元与成片顺序

`events` 是从原文叙事顺序建立的内部剧情单元清单，用于检查有声和无台词内容的顺序。回忆抽离合并时必须同时填写 `events` 与 `playback`；段内短回忆按 A→B→C 原顺序生成时，可在同一 `segment_id` 内分别记录三个 `events` 区间而省略 `playback`，按默认整段顺序校验。简单线性片段可省略这两项；下方抽离示例仅用于已选择回忆独立生成的场景。只要填写 `playback`，脚本就要求非空 `events`，不能只列台词代替剧情记录。

- 每项包含唯一 `id`、所属 `episode`、对应原文事件摘录 `text`、实际生成段 `segment_id` 及该段内 `start`、`end`。`text` 来自原文或已确认构思；不从已生成内容倒推清单、不为了过检重排原文。
- 一个单元对应同一时间线的一段连续剧情，可含多个镜头、同一时段的动作和发声；并行发生的内容放在同一单元。原文事件跨生成段或回忆插入点时，按原有阶段拆成不同单元，保留来源位置。不为建立记录新增动作或切镜。
- 区间包含本单元已有动作、声音及必要停顿；所有生成段须由这些单元完整覆盖一次，无漏段、空隙或重叠。这样既记录回忆，也记录其前后的触发与返回，不能只登记回忆 B 而遗漏现实 A、C。
- `playback` 按成片顺序列生成区间，必须完整使用各段一次。一个剧情单元须完整落在一条剪辑区间内；不能让现实 A+C 共用一个跨回忆插入点的单元。必要时按原有阶段拆记录。
- 脚本把单元映射到成片时间，核对原文顺序、片段归属与完整覆盖。漏填剪辑顺序时会按默认生成顺序检查，A+C、B 因与 A→B→C 不符而失败；无台词回忆移到片尾同样失败。

以下是完整、全无台词的分组校验示例；文字为示例剧情，秒数仅演示分组，不作为切镜节奏要求：

```json
{
  "mode": "真人剧",
  "episodes": [
    {
      "id": "current",
      "complete": false
    }
  ],
  "sources": [],
  "segments": [
    {
      "id": "S1",
      "episode": "current",
      "duration": 18,
      "english_words": 0,
      "shots": [
        {
          "start": 0,
          "end": 8
        },
        {
          "start": 8,
          "end": 18
```

## 更新技能时的行为检查

修改相关规则后，用以下小场景审查实际输出；仅检查规则字样存在不算行为验证。无视频时只记录提示词层面的结果，视觉质量须由实际生成片段另行评估。无需为此自动提交视频任务。

| 输入场景 | 应观察的行为 |
| --- | --- |
| 提供 `堡垒马车-封闭式车厢-白天.png` 与 `北境龙主堡垒-大门前院.jpg`，本段按此顺序使用后又返回车厢 | 填写 `场景：堡垒马车-封闭式车厢-白天、北境龙主堡垒-大门前院`；不带扩展名、不重复列车厢、不简写名称，分镜和光影仍各自对应 |
